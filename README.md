# dsh-async-tools

[English](<README.en.md>) · [完整用户参考](<docs/user-reference.md>)

[![CI](https://github.com/MC5Spear/dsh-async-tools/actions/workflows/ci.yml/badge.svg)](https://github.com/MC5Spear/dsh-async-tools/actions/workflows/ci.yml)

让 DSH 执行耗时命令或委托子代理时，Agent 不必一直等着。本插件把工作放到后台，让 Agent 继续处理独立任务；需要结果时再等待，结果直接送回会话。每次等待都有指定时长，到期不会停止后台工作。

经常处理长任务、需要并行委托时，值得安装；主要运行短命令、没有后台委托需求时，可以继续使用现有预设。本文的“宿主”指加载插件的 DSH。

这是第三方插件，与 DeepSeek 官方无隶属关系。项目由个人维护，接受 issue，不接受外部 PR，响应与修复没有固定时限。安全问题也通过 issue 提交，请先删除敏感信息。

## 安装前先确认

| 项目 | 当前适用版本 |
| --- | --- |
| 插件版本 | `0.2.8+dsh.0.2.1-rc` |
| 支持的宿主版本 | `0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5` |

**DSH 必须是上表四个版本之一。** 正式 `0.2.1`、`0.2.0`、`0.2.2` 及未列入的新 rc 均不放行。建议使用 Node.js 24；插件的 Node 声明不等于整套 DSH 的最低要求，其他运行时先看[运行时前提](<docs/user-reference.md#1-安装身份与前提>)。

### 验证到什么程度

本线已有验证限于本机 Windows、隔离实例，各类检查覆盖的内容不同：

- 四个支持宿主分别通过本包全量模块测试套件与静态检查。
- 真实浏览器检查了设置页、提问浮层的关键行为和无障碍树。
- 真实模型会话抽样检查了五工具的核心行为，包括后台交付、等待与插话、子代理续接、提问迟答；这不是全部功能逐项实测。
- 安装件经官方 CLI 装入隔离实例，检查了工具名册、预设补丁和依赖树。

部署前还需注意以下未验证范围：

- Linux 实机命令与单次提权未验证；macOS、远程环境无验证结论。
- 真实操作系统输入法、读屏和触屏未验证；浏览器无障碍树检查不能代替这些检查。
- 工具结果已构造、但提交前被宿主改写为取消错误的精确时序，尚未在真实宿主验证。
- rc.3／rc.4 的真机逐项重验未完成；全量套件与静态检查已覆盖它们，但不等于逐项实机覆盖。
- 远端 CI 已配置四版本矩阵，远端执行尚未发生。

涉及上述环境或行为的部署，先与维护者安排隔离验证。旧 rc.2／rc.5 安装的实测结论不自动覆盖后续机制变化；逐项范围在对应源码提交的 `docs/design.md` §9.3 中说明，获取方法见[文档与许可](<#文档与许可>)。

## 安装并确认已加载

本包不从 npm 分发。选择终端或 GUI 中的一种方式：

```powershell
dsh plugin --profile web add github:MC5Spear/dsh-async-tools#adapt/dsh-0.2.1
```

GUI：打开 DSH 插件管理页，在安装对话框的安装地址中填入 `github:MC5Spear/dsh-async-tools#adapt/dsh-0.2.1`。

这个地址跟踪会移动的维护分支，安装时取得的内容可能变化。需要固定来源时：

1. 检出准备安装、且能从该仓库取得的目标源码，在检出目录运行 `git rev-parse HEAD`，记录完整提交号。
2. 把安装地址中 `#` 后的分支名换为该完整提交号。仅有本地提交号不代表远端已可取得该提交。
3. 安装后，在宿主为目标 profile 安装本包的目录中，检查 `package.json` 的 `version`；应与所选源码中的版本一致。同时保留实际使用的安装地址和完整提交号作为来源记录。版本号不等于提交身份，变更记录也不能证明本机安装了哪个版本。

安装完成后按顺序确认：

1. 打开插件列表中的本包详情页，应能看到设置表单。
2. 新建会话，在预设选择中确认 `dsh-async` 和 `dsh-async-create` 可选。
3. 选择其中一个，确认 Agent 能使用下表中的五工具。预设是决定 Agent 使用哪些工具的一组配置，无需手工创建预设目录。

如果取不到源码，先核对仓库地址与固定提交号，再检查网络或代理；仍无法获取时，向提供来源的维护者询问可用安装件。若安装后入口缺席，先核对宿主版本，再按[安装排查](<docs/user-reference.md#1-安装身份与前提>)检查装载日志。

## 第一次后台任务

以下示例使用 PowerShell 和出厂等待设置，适用于上述 Windows 验证环境。

1. 新建会话，选择 `dsh-async`（通用编码）或 `dsh-async-create`（保留插件与预设创作工具）。
2. 把下面这段请求粘贴给 Agent：

   > 请做一次无害的后台执行演示，不修改文件、不访问网络、不创建子代理。先用 async_run 执行 `Write-Output SHORT_OK`，确认短命令结果。再用 async_run 执行 `Start-Sleep -Seconds 30; Write-Output LONG_DONE`，显式设置 yield_ms=20000。收到 job_id 后保留编号，不重复运行命令；需要等待时用 async_wait 指定该作业，显式设置 wait_ms=30000。最后报告两个标记和真实退出信息；如果未收到编号，先用 job_list 查找。

3. 短命令应直接显示 `SHORT_OK`。长命令运行 30 秒，超过首次最多等待的 20 秒后，应先返回作业编号 `job_id`；随后结果会附在等待返回或完成消息中，包含 `LONG_DONE`。检查真实退出信息，`completed` 本身不等于退出码为 0。

对应的 **Agent 工具调用示意（不是可在终端执行的函数）**：

```text
async_run(command="Start-Sleep -Seconds 30; Write-Output LONG_DONE",
          description="Wait then print completion marker", yield_ms=20000)
async_wait(targets=[{kind:"job", id:"<返回的job_id>"}], wait_ms=30000)
```

`yield_ms` 省略时出厂默认 20000 ms，出厂请求边界为 20000–600000 ms，超出时按边界生效。`wait_ms` 每次必填，没有默认值。等待到期、取消等待或停止当前回合，都不停止后台任务；不需要的作业用 `job_kill` 显式停止。

结果通常只交付尚未读过的内容，需要保留时及时保存。正文截短后的续取、取消窗口的恢复副本和宿主缓冲真丢失，是不同情况，分别见[结果读取与恢复](<docs/user-reference.md#4-等待状态与直接交付>)。不要为查进度重跑原任务。

## 工具与预设

两个预设都直接提供以下五工具，不改写原有预设。检查状态、发送消息和停止任务仍使用 DSH 管理工具。

| 工具 | 用途 |
| --- | --- |
| `async_run` | 执行命令；直接返回结果或后台作业编号 |
| `async_wait` | 等待消息、作业结果或指定目标；先交付就绪结果，没有可等待工作时立即返回 |
| `async_agent` | 后台创建可续谈的子代理，立即返回 `agent_id`；最终回答独立送达 |
| `async_workflow` | 用脚本协调大规模多代理任务，并作为后台作业管理 |
| `async_list_subagent_models` | 分页浏览或搜索模型，查询对指定创建工具是否适用 |

**自建预设也能使用全部异步功能。** 先手工挂入五工具；其中 `async_workflow` 还须与编排引擎放在隔离 `workflowEngine` 的组内，并能取得所需宿主服务。再按需把自建预设加入 `boundPresets`。绑定只决定操作要求和辅助功能的作用范围，**不会自动安装或移除工具**。完整示例见[自建预设组合](<docs/user-reference.md#7-高级组合>)。

通常让子代理使用默认或继承模型即可。需要显式选择时，按[模型查询到创建](<docs/user-reference.md#5-模型目录授权与继承>)的步骤操作：每次 `async_agent` 创建都读取当前 DSH 策略，保存设置影响后续创建，不切换运行中的子代理。原生创建工具与工作流 `agent()` 的规则各不相同。

## 设置、安全与停用

设置位于插件列表 → 本包详情页 → 描述与组件行之间。编辑后保存才生效；恢复默认也须保存，普通合法设置保存无需重启。

「适用预设」名单 `boundPresets` 默认包含本包两份预设，空数组表示全部解绑。名单内的会话会获得异步操作要求；静默失败提示还须开启 `silentFailureGuard`，待答面板还须开启 `askTakeover`，两开关默认均关闭。名单不代替开关，也不改变工具挂载。全部 20 项设置及提问规则见[设置参考](<docs/user-reference.md#2-首次使用与设置>)。

命令继承会话目录、沙箱、审批和权限。插件不自行收集遥测、发起网络请求或读写凭据；模型目录由 DSH 接口提供，查询不调用模型推理。但命令仍可能访问网络或敏感信息。输出和宿主临时保存文件可能含秘密，分享前脱敏，在有权限的位置保存所需内容。

**停用或卸载前，先更改默认预设。** 若默认仍为 `dsh-async` 或 `dsh-async-create`，移除后新会话会报 `agent-preset/not-found`。在宿主设置改为可用预设；已经移除时清空或重选默认，再建会话确认恢复。用 `job_list` 检查活动作业并显式停止不需要的任务。移除工具不会自动取消会话启动的作业，重启可能终止活动进程。详见[停用、恢复与报障](<docs/user-reference.md#8-停用恢复与报障>)。
