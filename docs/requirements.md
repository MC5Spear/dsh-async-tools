# dsh-async-tools 需求

> 本文定义当前产品要求，不代表工作树已实现或完成验收。[设计文档](<design.md>)说明目标机制、验证方法及当前实施差距，不能以代码现状降低本文要求。
> 需求与设计允许相互引用；除此之外，必要内容应自包含，不靠内部材料、其他文档或外部资料补齐。源码与测试用于核验，不代替缺失要求。
> 正文按功能维护，同一规则只在一个主题下完整定义；变更直接更新该主题，历史由 Git 保存。短期增补使用第 9 章，维护者定期归并。

## 1. 产品目标与职责范围

### 1.1 产品目标

插件让 Agent 在长任务尚未结束时继续处理其他工作，解决三类等待问题：

1. 命令或子代理长期不返回时，调用它的 Agent 仍须能处理任务和消息。普通提问无人作答时，可选提问接管也须让 Agent 在到期后继续。
2. 长命令或编排超过首次等待预算时，返回后台作业编号，任务继续运行。短任务在预算内完成时，同次调用直接返回结果。
3. 使用 goal（持续推进任务的目标机制）时，Agent 可以主动等待一段明确时长，减少结束回合后又被目标驱动唤醒的无效往返。

等待预算限制 Agent 本次等多久，不限制后台任务能运行多久。任务是否成功要从结果判断；需要停止后台任务时，使用明确的停止操作。

### 1.2 产品组成与影响范围

本文的“宿主”均指加载本插件的 dsh。dsh 原生工具指 dsh 自带的工具，不包括本插件工具。

交付一个插件包、六个直接可调用的工具、两个 Agent 预设、插件设置表单及可选的提问接管和静默失败防护。

| 工具 | 职责 |
| --- | --- |
| `async_run` | 启动命令，首次等待结束时返回结果或后台作业句柄 |
| `async_wait_job` | 有界等待作业并交付本次读取结果 |
| `async_agent` | 创建仅后台运行的可续子代理，返回 `agent_id` |
| `async_wait_agent` | 有界等待合法子代理停止运行，或因消息、取消、到期交回控制 |
| `async_workflow` | 将宿主编排引擎的一次运行作为后台作业管理 |
| `async_list_subagent_models` | 只读列出或搜索供应商／模型，分页返回并说明对目标创建工具的适用性 |

两个预设是 `dsh-async`（异步模式）与 `dsh-async-create`（异步创造模式）。工具随使用者挂载它的预设行生效，不被限定为只有这两个预设可用；本包不把工具注册进宿主全局工具层。

- 不修改宿主源码、不打宿主源码补丁；使用官方插件服务和 bundle patch 声明。
- 不替换宿主的作业、命令执行、子代理、审批或配置服务，不改变原有预设的工具清单和运行行为。
- 命令和子代理的创建、管理与权限仍由宿主承担。本包不把所有任意宿主工具自动变成异步工具。
- 工具使用新名称，不遮蔽原生工具；两个新增预设的定向组合规则见第 3 章。
- 提问接管和静默失败防护默认关闭，仅在本包两个预设范围内生效。
- 面向本地执行环境；Windows 与 Linux 的要求见 3.3，macOS 和远程执行环境不在验证范围。

## 2. 异步任务的执行、等待与结果

### 2.1 共用等待契约

#### 2.1.1 主体、目标与预算

“主体”是本次调用工具的 Agent，可以是根代理、子代理或更深层代理。“目标”是本次等待的作业或子代理。监听到组合内其他 Agent 的事件，不代表消息发给本主体，也不代表目标已结束。

- `async_wait_job` 和 `async_wait_agent` 必须显式提供 `wait_ms`；缺省报错，不静默采用配置默认值。请求值按第 5 章的生效上下限夹紧。
- `wait_ms` 覆盖插件等待执行阶段的总预算：入口查询、存在性检查、重试、轮询、等待及必要返回处理共同使用一份预算，不各自重新取得完整预算。
- 预算到期交回控制权，不继续等待额外查询或诊断。不承诺硬实时精度；宿主进入插件执行前的审批和调度不计入这一预算。
- 查询超时或失败表示状态未证实，不能当作目标不存在、目标终态或空输出。重试仍受同一预算约束。
- 执行工具的首次等待使用 `yield_ms`，默认值及边界见 5.2。它限制等待占用，不终止后台任务；批准权限与首次等待分开，不把审批时长冒充命令运行时间。

#### 2.1.2 消息唤醒与取消

目标未结束时，以下任一条件结束本次等待：

1. 发给本主体、可在下一模型步骤领取的用户插话、通知或代理转达消息到达。
2. 同类消息在等待开始前已经到达、尚未领取。
3. 调用被取消。
4. 预算到期。

消息的认定与读取边界：

- 不要求消息来自等待目标；其他作业完成或其他子代理的消息同样可以让主体处理新内容。
- 用户排队消息保持宿主下一轮领取语义，不唤醒当前等待，也不改投递落点。
- 内部进度事件、日志、目录或配置快照不是上述消息，不据此制造无效唤醒。
- 只检查本主体的收件箱，不向其他 Agent 广播，不替宿主领取或丢弃消息。消息正文仍在宿主领取点进入上下文。
- 收件箱或待领取列表读取失败时，按未命中可处理消息处理，不制造唤醒或目标终态；等待仍受总预算约束，宁可多等，不可错报消息到达。

交回控制的口径：

- 工具返回只交回控制。
- 正常消息唤醒、调用取消、预算到期和目标终态分别说明原因。消息唤醒不改变目标状态；不把非目标消息当作目标完成。
- 消息和取消的处理不能等满剩余预算；准备查询阶段同样及时交回控制，具体可测容差由设计规定。
- 已有可靠目标终态证据时优先返回目标结果，不因同时到达的消息诱导重复等待。查询失败不能构造这一优先条件。
- 等待结束不停止后台工作。显式作业终止及子代理管理继续使用宿主的非阻塞管理工具。

上述消息和控制规则适用于命令、编排的首次等待及两个等待工具。`async_agent` 不进行等待，没有消息唤醒阶段。

#### 2.1.3 状态、通知与结果

- 区分后台作业终态、子代理当前是否运行、调用是否结束等待、结果消息是否已进入上下文；不以一个状态冒充另一个。
- 结果和提示可直接用于下一步：句柄、状态、结束等待原因及可执行的后续读取或等待指引清楚可见。
- 工具描述、参数说明、错误和返回提示必须自解释，并使用真实生效的预算、语言及后端值。不能只返回一个 id，也不能把无法证实的状态写成确定事实。
- 作业完成通知是宿主备用唤醒机制，`async_wait_job` 是本包规定的后台结果读取途径；不能宣称它排除了宿主的其他读取工具。
- 预算内结果由活等待交付时，不重复补发作业完成通知。提前结束等待后及时撤销等待登记，不能错误抑制后续宿主通知。
- 最终子代理回答不作为 `async_wait_agent` 的返回正文；按宿主消息进入主体上下文。停止运行不等于成功，普通转达消息也不等于结算。

### 2.2 命令执行与作业取回

#### 2.2.1 启动与首次等待

`async_run` 接受必填 `command`、`description`，以及可选 `yield_ms`、`workdir`；单次提权参数见 6.1。

启动前，先按宿主规则取得会话当前有效目录，再解析本次 `workdir`：

| 本次调用 | 目录要求 |
| --- | --- |
| 省略 `workdir` | 使用会话当前有效目录。 |
| 相对 `workdir` | 以会话当前有效目录为基准解析。 |
| 绝对 `workdir` | 保持绝对路径语义。 |

会话切换目录后，后续命令按新目录解析，不使用会话创建时的旧目录。当前目录检查、失效恢复及同会话并发处理均遵守目标宿主规则。解析失败时说明原因，不在其他目录静默执行；此时零作业注册、零进程启动。已启动进程的目录不随后续会话切换而改变，沙箱权限也不因此扩大。

命令按以下启动和交付规则执行：

- 必须从 Agent 调用。没有主体或入口已取消时，可读拒绝，零作业注册、零进程启动。
- 参数和权限批准完成后，先接受作业注册及并发准入，再启动进程。触顶拒绝时没有进程在运行；说明生效上限、存活作业和等待或终止不再需要的作业的出路。
- 命令从执行开始就是归属于发起会话的作业，活动期间可在任务面板观察，而不等预算到期才注册。
- 首次等待内结束，直接交付输出和真实结局，短命令不需要额外取回调用。
- 首次等待因预算或消息结束，返回 `job_id` 及等待结束原因，命令继续后台执行。后续用 `async_wait_job` 取回结果。
- 调用停止只结束等待，不把该信号连接成命令取消。宿主可能把可见调用结果改为取消错误，不能据此宣称命令已停止；后台作业仍归宿主作业管理。
- 不设置后台命令的绝对寿命时限。显式 `job_kill` 或 owner 会话处置按宿主语义结束任务。
- 命令及编排的首次等待预算由本次调用参数确定，运行中的首次等待不提供调整操作；提问加时是第 4 章独立功能，不改变这份预算。

#### 2.2.2 作业等待与终态

`async_wait_job` 接受必填 `job_id`、`wait_ms`，遵守 2.1。

- 入口确认作业对主体可见。查无或不可见可读报错；查询失败给重查出路，不暗示应重新启动命令。
- 入口已终态，直接交付本次可读取结果；否则等待完成，或按 2.1 提前交回。
- 目标终态分别报告 `completed`、`killed`、`failed`，保留输出及结局细节。`stopping` 等尚未收尾状态不当作终态。
- 非终态返回有效句柄、等待原因和再次等待指引；在无法证实时，不宣称目标确定仍在运行。
- 插话、取消和到期不调用目标的终止操作，等待登记和监听资源在本次调用结束时释放。

#### 2.2.3 输出与一次性交付

读取沿用宿主消费式游标，只在需要交还模型时消费一次，不为轮询状态提前读空输出。

- 返回本次全部通道的增量文本。首次成功终态读取附带的最终 `result` 必须并入同一次工具结果，不丢弃、不靠之后再读补救。
- 增量在前、最终结果在后。仅在增量非空且不以换行结尾时，二者之间增加一个换行；只有最终结果时直接作为输出；两者都空则为空串。
- 后续读取不重复已消费增量或最终结果。状态可重复查询，不代表结果可以重复交付。
- 读取抛错时，给模型可见的读失败标记和重试出路，不把它伪装为空输出；未成功消费的最终结果可在之后成功读取时交付。
- 合并后的结果内容按 `maxResultChars` 裁剪，保留首尾、说明省略量并标注截断。该值限制保留的内容字符数，不是最终模型可见文本的总长上限；裁剪说明及必要的状态、诊断提示另计，保持紧凑，不因内容预算过小而丢失。原始结果中的文本仍计入内容预算。
- 输出丢失与裁剪分开说明。宿主报告 spill 路径时必须交付路径；没有路径不能声称磁盘仍有完整副本。
- 正常退出不加失败标记；非零退出和信号终止在模型可见文本中给出真实标记。首次返回和后台取回两条路径一致，不能将被终止的进程报成正常完成。

#### 2.2.4 呈现与可管理性

任务名称是命令原文，`description` 是活动期的进度说明；完成后按宿主行为清除进度。命令、状态、运行时长和实时输出从执行开始可见，界面可做视觉截断，但注册名称不预先截断。

保留宿主 `job_list`、`job_output`、`job_kill` 管理入口，不改它们的原有行为。

### 2.3 子代理派生、模型选择与等待

#### 2.3.1 后台派生与原生参数兼容

`async_agent` 的公共调用参数与目标版本 dsh 原生子代理创建工具保持名称、类型、必填条件、缺省及校验语义一致。参数兼容不代表两工具采用相同的策略生效时机；本包实时策略见 2.3.2，查询结果的目标适用性见 2.3.4。

| 参数 | 要求 |
| --- | --- |
| `description`、`prompt` | 必填字符串，分别为任务展示说明和任务内容。任务说明按当前后端是否继承上下文如实编写；独立新子代理的任务书自包含。 |
| `cwd` | 可选字符串，指定子代理初始目录；缺省继承父代理当前有效目录，相对路径以该目录解析。后续目录变化互不影响，权限与校验遵循 dsh。 |
| `provider`、`model` | 可选且必须成对，值为准确的 LLM 路由 ID。省略时按 dsh 的配置默认、后端路由默认及父路由继承顺序解析，不把显示名称当作 ID。 |
| `reasoning_effort` | 可选非空字符串，使用所选模型支持的推理强度 ID。允许单独指定并校验最终有效路由；省略时继承兼容值或使用所选模型默认值，换路由时不沿用不兼容的旧值。 |
| `agent_preset` | 仅在工具配置了可选预设且后端支持独立预设选择时提供；按允许集合校验，省略时使用配置默认或继承父预设。不得据此向原本无权选择的预设开放权限。 |

- 只有后台形态，不提供前台模式选择；派生成功后立即返回 `started`、`agent_id`、实际指定或继承路由及有界等待指引，不等待任务完成、不轮询。创建工具本身不增加等待时长参数；等待预算属于 `async_wait_agent`。
- 子代理后端由 `subagentProvider` 配置选择，与调用参数中的 LLM `provider` 分开。无主体、后端未注册、不支持可续派生或不支持请求参数时，可读拒绝且不派生；参数按后端支持条件展示和执行，不能接受后静默忽略。
- dsh 原生工具的内部配置不是 Agent 调用参数。保留按 dsh 配置子代理默认选项及可选预设的方式，不开放任意参数透传；未知参数显式报错并列出当前支持键。
- 指定路由或推理强度时，在创建前校验有效路由和模型支持信息。参数、权限、策略及解析失败均不返回成功句柄；可更换路由解决的拒绝，提示调用 `async_list_subagent_models` 列出或搜索，并给出保留目标工具的查询方式，不附整份模型表、不自动换模型重试。
- 最终回答及普通转达按 dsh 消息进入直接父主体上下文。子代理成功启动后，创建工具返回不停止后台执行；成功、失败及取消的结算由 dsh 管理，本包不重复投递最终回答，不遗留未承接的异步拒绝。

#### 2.3.2 模型选择配置实时生效

配置唯一来源为 dsh 现有的子代理模型选择开关和允许名单。本包不另设名单，不以会话开始时写入的策略记录限制后续 `async_agent` 调用，也不修改 dsh 原生工具的策略。

- 用户成功保存配置后，已有会话、新会话、恢复会话及各层子代理的后续本包派生调用读取当前生效配置，无需重开会话或重启实例。新增路由可用于后续选择；删除路由后后续显式选择被拒绝。
- 开关关闭时，显式指定路由或推理强度被拒绝。全部省略时，按 2.3.1 使用配置默认或继承路由，不因允许名单变化被拒绝；已运行子代理不自动换模型、不停止。
- 每次创建使用一致的生效配置，在实际启动前确认请求仍被允许。校验期间配置变化导致路由被撤回时，本次拒绝或要求重试，不使用过期许可继续创建。查询结果不是后续创建的授权凭据。

显式选择遇到以下情况时，在派生前拒绝，并说明当前原因：

| 条件 | 所需处理 |
| --- | --- |
| 所选路由不在允许名单内 | 拒绝该路由，不创建子代理。 |
| 开关启用，但名单为空或非法 | 说明名单问题，拒绝显式选择。 |
| 设置服务缺席或读取失败 | 说明策略尚无法读取，拒绝显式选择。 |

这些失败都不能用旧会话策略、全部放行或任意替代模型解决。其他异步工具及无显式模型选择的派生不受影响。

配置变化不向所有 Agent 推送完整列表，不因保存动作唤醒无关任务。dsh 原生创建工具仍遵循其实际会话策略；本包不能把实时配置描述成原生工具已经采用的策略。

#### 2.3.3 等待合法目标

`async_wait_agent` 接受必填 `agent_id`、`wait_ms`，遵守 2.1。

- 首先确认目标存在，且在本主体有权等待的子代理范围内。查无与查询失败分开；短暂尚不可见的重查受总预算约束。
- 入口检查目标当前运行状态，已停止运行就结束等待，避免对已经结束的目标继续空等。
- 等待中接收可靠目标结算／状态证据，并以简单运行状态轮询检查目标是否仍在运行，不能只检查持久目录中有没有记录。
- 轮询作为结束消息未到达时的备用判断，不另建宿主消息投递重试系统。查询失败按状态未证实处理。
- 目标停止运行时可以报告当前非运行状态，但不冒称任务成功、最后回答已到达或永久不能再次运行。
- 发给主体的可处理消息到达时交回控制，普通转达和非目标通知不被升格为目标结算。此规则对根、子及深层主体一致。
- 不读取子代理私有会话日志或内部运行记录来取得答案；使用宿主公开目录、状态查询和事件。

#### 2.3.4 路由列表、搜索与目标工具适用性

`async_list_subagent_models` 是独立只读工具。它列出或搜索当前会话可见的子代理 LLM 供应商／模型，不创建代理、不发送模型推理请求、不修改配置或当前 Agent 的路由。名称独立于 dsh 原生 `list_subagent_models`，两者可同时挂载。

**查询方式与内容**：

- 无供应商筛选且无搜索词时，分页浏览供应商，返回准确 ID、名称和对应模型数量；只有确认目标策略后，数量才能标为允许模型数，未确认时标为目录已知数。指定 `provider` 时，分页浏览该供应商的模型。提供 `query` 时，支持跨供应商搜索，也支持在指定供应商内搜索。
- 搜索去除首尾空白，忽略大小写，按供应商或模型的 ID、显示名称作包含匹配；空白搜索词等同未提供。不默认使用正则，不改写准确 ID；同名但不同供应商或不同模型 ID 的条目不合并。
- 指定 `provider` 和 `model` 可查看准确模型及其推理强度 ID、名称和默认项；只指定 `model` 时提示必须同时给出 `provider`。准确模型详情与非空搜索词不能同时请求，冲突参数可读拒绝。模型未提供某项元数据时如实说明，不编造推理强度或替 Agent 选择。
- 模型目录由 dsh 已注册的 LLM 供应商及公开目录接口提供，并结合适用策略。允许名单中未被目录列出的模型仍可按准确 ID 查询和列入结果；不能仅因目录未列出就判不支持。目录条目本身也不等于已获策略允许、已通过凭据验证或远端服务保证可用。
- 读取失败与无匹配分开；部分供应商查询失败时，明确结果不完整，失败部分不记为零模型。结果按 `agentLang` 提供完整中英文文案，供应商／模型 ID、名称及其原始元数据保持原样；不返回凭据、密钥、私有接口地址或其他会话内容。

**目标工具与调用兼容**：

- 支持可选 `target_tool`，按当前会话实际可见的创建工具名称确认目标，可为 `async_agent` 或 dsh 原生子代理创建工具，包括用户配置的工具名。目标只影响筛选、适用性和调用指引，不授予额外权限。
- 省略目标且仅有一个可识别创建工具时，可明确采用该工具；存在多个目标或不能可靠识别时，不默认为通用可用。仅挂查询工具也可查目录，但须说明未确认可用创建入口。

判断适用性时，先确认目标工具，再使用该目标对应的策略来源：

| 目标 | 判断依据 |
| --- | --- |
| `async_agent` | 2.3.2 的当前 dsh 配置。 |
| dsh 原生创建工具 | 该工具的实际参数、配置及当前会话策略。 |

全局名单与原生会话策略可能不同，两个方向都要保留：新增路由可能已可供本包选择，却尚不适用旧会话的原生工具；全局撤销的路由也可能仍在原生会话策略内，不能先按全局名单过滤而遗漏。

结果须标明目标和依据，并区分“允许选择”“不允许选择”“适用性未确认”。只有取得已确认的目标依据，才能将条目标为可选，或提供可直接用于目标工具的参数。若 dsh 公开接口不足以确认策略或参数条件，返回“未确认”及原因；不读取其他会话私有数据、不猜测，也不为取得结论而修改原生工具。

- 目标不存在、不可见、不接受显式路由或后端不支持时，明确报告该限制。可继续提供已获依据的目录信息，但不能生成宣称适用于该目标的创建调用。
- 模型条目使用准确的 `provider`、`model`；推理强度仅在目标支持 `reasoning_effort` 且已确认该模型支持时，作为可选值提供。调用示例仅含目标实际接受的字段；搜索词、分页参数、目标参数和本包专有返回字段不能混入创建参数。不把 dsh 原生工具参数示例宣传为适用于任意工作流的 `agent()` 钩子。
- 查询是当前信息，不保证配置或目录变化后的创建成功；创建仍执行目标自身的校验。不支持路由时，指引 Agent 保留目标工具条件重新列出或搜索，不自动改用另一个创建工具绕过限制。

**分页**：

- 供应商列表、模型列表及搜索结果均分页，先筛选再分页；`page_size` 为整数，默认 20，范围 1—100，非法值可读拒绝。
- 每页提供本页条目、匹配总数、是否还有下一页，以及可直接继续查询的参数。回显目标、筛选和搜索条件；部分结果不完整时，总数明确为已取得结果数，不能冒充全量总数。
- 同一查询和同一版本内顺序稳定，不重复或漏项。继续翻页绑定原查询条件及影响结果的策略／目录版本；配置、目标适用性或目录变化使版本失效时，提示重新查询，不把新旧版本拼接成完整列表。改变筛选条件后从新查询开始。
- 分页不能用正文截断替代；长说明可以缩短，但准确 ID、适用性、完整性标记和继续查询信息必须可见。具体页码或游标形式由设计定义。

### 2.4 后台编排

`async_workflow` 提供 `script`、`meta`、可选 `args`、`yield_ms`。只有后台作业形态，首次等待与结果取回遵守 2.1 和 2.2.3。

- 用于用户明确要求的 workflow 或大规模多代理编排；一两个委托使用 `async_agent`。描述必须同时说明使用条件和可用替代入口。
- 参数校验、作业准入在引擎启动前。无主体、入口已取消、引擎缺席或准入触顶时给可读错误，不假装运行已启动。
- 沿用宿主编排引擎，不重写它的隔离、并发、总量和结构化输出校验；后台化不取消这些限制。
- 首次等待内完成直接返回完整可裁剪结果；因消息或时长到期结束等待时返回作业句柄。停止等待不取消编排，显式 `job_kill` 才请求取消运行。
- 编排与命令共享宿主作业并发管理。名称为 `meta.name`，描述进入活动进度，启动即任务面板可见。

#### 2.4.1 脚本与钩子契约

| 项目 | 当前要求 |
| --- | --- |
| `script` | 纯 JavaScript 脚本体，允许顶层 `await`，以 `return` 返回可 JSON 序列化值。不是 TypeScript 或模块，不在脚本中声明参数 `meta`。解析失败不启动；运行错误或无法序列化使编排失败。 |
| `meta` | JSON 对象，非空 `name`、`description` 必填；可选 `whenToUse`、`phases`。阶段项为 `{title, detail?, provider?, model?}`，标题非空，其余为可选字符串；未知字段拒绝。阶段声明不自动改变顺序或路由。 |
| `args` | 可选 JSON 对象，脚本内原样提供；裸列表需包成对象。 |
| `agent(prompt, opts?)` | 等待一个子代理结束，无 schema 返回最终文本，有 schema 返回校验对象；普通子代理失败为 `null`。选项仅为 `schema`、`label`、`phase`、`provider`、`model`；两个路由覆盖可独立提供，不套用 `async_agent` 的成对规则。未知选项拒绝。 |
| `agent` 的 `schema` | 对象根 JSON Schema，仅支持 `type`、`properties`、`required`、`additionalProperties`、`items`、`enum`、`const`、`oneOf`；可有不增加校验约束的 `description`、`title`、`default`、`examples` 注解，值为无损 JSON，前两个为字符串。其他关键字拒绝。 |
| `pipeline(items, ...stages)` | 每条目独立流过阶段，无跨阶段屏障。阶段收到 `(prev, item, index)`；普通阶段错误把本条目降为 `null`，跳过其余阶段，不影响其他条目。 |
| `parallel(thunks)` | 并发执行零参函数，等待全部完成；普通函数错误只把对应结果降为 `null`。 |
| `phase(title)`、`log(message)` | 提供阶段进度及日志；已声明阶段按精确标题匹配。脚本只协调，不提供文件系统、网络、定时器或 Node.js API。 |
| 致命误用 | 坏钩子参数、未知选项、不支持的 schema、超过总量或组合条目上限，终止整个脚本，不能被 `pipeline` 或 `parallel` 吞成局部 `null`。并发槽满时排队，不当作超过总量。 |

#### 2.4.2 运行记录与交付边界

- 活动日志承接阶段、日志、子代理开始和结束信息；阶段更新进度，模型经作业读取取得增量和最终结果。
- 工具顶层调用提供持久的运行开始、子代理开始／结束、运行结束记录供 GUI 回放。子调度不写这些持久节点，但进度、日志、结算与结果恢复仍有效。
- 记录写入失败告警并停止该次运行的后续记录，不伪造回放成功；不能因记录缺失丢掉作业或最终结果。
- 不为编排内部的单个 one-shot 子代理提供额外模型侧等待入口，编排结果由整次运行交付。

## 3. 异步预设与作用范围

### 3.1 两个预设

- `dsh-async` 基于宿主 shipped standard，保留通用编码功能。
- `dsh-async-create` 基于宿主 shipped 创造模式（cordis 框架系的随宿主预设），保留插件和预设创作功能及对应 skill 工具。
- 六个工具在两预设中直接可调用，不要求模型把它们包装进一个占住调用步骤的同步呈现程序。
- 两预设都只有 `async_run` 命令执行入口，以及 `async_agent`、`async_workflow` 创建入口；保留宿主非阻塞的检查、消息和停止管理工具。
- 在两预设禁用原生同步 shell 和原生委托／编排入口（原生编排入口默认前台等待整场编排、另有 run_in_background 后台形态；入口收归本包以统一等待预算与消息纪律，委托入口一并收归以保持派生入口唯一）；保留必要引擎服务。具体组成按当前兼容宿主基线核对，不静默丢掉基线其他功能。
- 任务书按后端是否继承上下文编写，独立新子代理任务书自包含；工具指引要求后台启动后继续其他工作，需要结果时有界等待，不反复轮询或重新派生来检查进展。
- 创建工具的原生参数兼容按 2.3.1 执行；可选预设及模型参数仍受配置和后端支持约束，不把参数兼容当作任意选择预设或模型的许可。

### 3.2 可见性与隔离

工具行只在挂载它们的预设范围内注册；设置表单独立可见，不要求先切换到异步预设。宿主配置行不注册工具，缺省角色不能自动变成命令工具。

- 使用者可在自建预设按工具选择挂载，查询工具与异步创建工具可分别使用；本包不替使用者修改其预设，不保证自建组合会禁用已有同步工具。
- 本包只默认将路由查询工具加入两个异步预设。用户是否将工具用于普通预设或其他工作流，由用户决定；查询工具不自动替换 dsh 原生创建／查询入口，不接管其他工作流。实时策略仅约束 `async_agent`，不改变 `async_workflow` 内部 `agent()` 钩子或其他引擎的策略和参数契约。
- 本包两个预设的创建、等待规则不改写宿主 shipped 预设。
- 提问接管和静默失败防护仅在本包两个预设内生效；开关开启也不能向其他预设注入纪律或改变行为。
- 编排行必须能取得所在组合的引擎服务；不正确组合时可读拒绝，不能以不可用行冒充工具可用。

### 3.3 平台要求

Windows 与 Linux 的两个预设提供一致的异步入口清单，均不出现同步 shell。Linux 的命令执行与单次提权必须在对应环境验证；没有该环境时记录未验证，不能用 Windows 结果宣称两平台通过。

## 4. 提问接管与待答交互

### 4.1 接管范围与初始等待

总开关为 `askTakeover`，默认关闭。只接管本包两预设的根 Agent 普通提问；没有 Agent、不是本包预设、非根主体或计划评审时交还宿主原生流程。审批链不属于提问接管，不替换原生提问工具。

- 一次提问调用是一批，可含多题；同批共享期限，各题保留独立答案状态。
- 初始窗口采用请求进入时生效的 `askTimeoutMs`。窗口内作答返回真实答案，全部题作答或忽略后提前结束。
- 截止时保留已答内容；未答题返回超时事实，允许 Agent 按最佳判断继续，明确之后仍可补答。不能替用户选择推荐项或伪造用户答案。
- 调用取消保持取消语义，不被超时合成答案覆盖。

### 4.2 全局待答面板

本包接管的题从进入等待起出现在 Web 页面内待答面板，按会话分组；“全局”仅指页面聚合本包题目，不扩大接管范围，通知渠道限 Web 页面。

- `askUiSeat` 选择待答问题的显示方式。右下角浮窗直接显示问题；侧边栏底栏徽标显示未处理问题数，点击后展开问题。两种方式复用同一题目交互，切换不改提问、计时或答案交付规则。默认值见 5.2。
- 徽标计数为未处理问题数，全部处理后消隐。
- 支持单选、多选、自定义选项、单题忽略和跳转所属会话。超时题保留标记，可迟到作答。
- 展示真实期限和剩余时间，文案使用 `uiLang`；自动档随宿主当前语言更新，不要求重新打开页面。
- 提交失败给可见原因并保留待处理内容，不能假装作答已送达。

#### 4.2.1 作答项与选择关系

每题提供与预设选项并列的一项“自定义回答”。该项有独立的选中状态和文本输入，文本本身就是答案，不是已选预设项的附加说明。没有预设选项的题目也使用这一自定义作答规则。

| 题型 | 选择规则 |
| --- | --- |
| 单选 | 预设选项与自定义项互斥；选择任一项即取消其他项，只提交当前选中的一项。 |
| 多选 | 预设选项各自切换，自定义项也可独立选择；可以只选预设、只选自定义，或同时选择两者。选中或编辑自定义项不取消已选预设项。 |

题目初始不选中任何项；“推荐”等提示不代表已选中。程序不分析自定义文本与预设项是否语义冲突，也不据此替用户增删选择。

#### 4.2.2 自定义输入与草稿

- 通过选择控件选中自定义项，或点击其文本输入框、主动输入非空白文本时，选中自定义项，并按 4.2.1 处理其他项；不要求输入后再额外勾选。
- 用户可以通过选择控件取消自定义项的选择。切换选项或取消选择时可以保留自定义文本草稿，但未选中的草稿不参与提交；再次点击输入框或主动输入有效文本时重新选中。
- 清空已选中的自定义文本时，保持该项选中，不自动恢复旧预设选择；本次回答按 4.2.4 判为无效。
- 仅移动键盘焦点、恢复草稿或刷新题目展示，不自动改变选择。文本框有内容、获得焦点或出现光标，都不单独证明该项已选中。

#### 4.2.3 选择反馈与操作

- 预设项与自定义项采用一致的选中效果。以整项底纹变化为主要视觉提示，边框变化为辅助，并有明确的单选标记或勾选标记；不能只靠边框加粗或颜色差异表示选择。
- 普通、悬停、选中和键盘焦点状态容易区分。输入框的焦点轮廓与作答项的选中效果分别表达，未选中的自定义项不能只因悬停或获得焦点而看似已选中。
- 深色和浅色主题下均能直接辨认所有已选项，不能要求用户逐项比较细微边缘变化。长题干、选项说明和自定义文本不遮住选择标记。
- 鼠标、触屏和键盘均可选择、取消选择及编辑；单选项遵守 4.2.1 的替换规则。辅助技术可取得题目、选项名称、选中状态、单选或多选关系以及自定义输入的关联，不仅依赖视觉反馈。

#### 4.2.4 有效提交与答案一致性

- 没有选中项时不可提交。选中的自定义项必须含有效文本；去除首尾空白后为空的文本无效，即使多选题还选有预设项，也不可提交该回答。空白检查只用于有效性判断，不授权改写用户文本。
- 无效时禁用“提交”，并就近说明需要选择答案或填写自定义内容。按钮与快捷键遵守相同规则；服务端也拒绝违反选择关系或有效性规则的作答，不将其记为已答或投递答案。
- “不答／忽略”是独立操作，不受答案有效性限制，不转换成空答案、推荐项或虚构的自定义回答。
- 提交只包含当前选中的预设项，以及当前选中且有效的自定义答案。多选时将自定义答案作为与其他已选项并列的答案，不降为附加说明；未选中的预设项和文本草稿不混入答案。
- 界面提交记录、窗口内工具返回和 4.4 的迟到通知，必须表达同一组实际选择与自定义答案，区分题目提供的选项和用户选中的答案，不让 Agent 猜测哪部分有效。两种面板显示方式及窗口内、迟到作答均遵守本节规则。

### 4.3 延长等待

每个会话组提供“增加等待时间”动作，每次追加时长可配置，默认 60 秒；配置登记见 5.2。

- 一次点击作用于该组点击当时尚未到期的批次，在各批原截止时间上增加本次时长，倒计时继续运行。
- 同批未答题共用新期限，已答内容保留；一组的操作不影响其他会话。
- 新到批次使用自己的初始期限，不继承之前的延长。没有在窗批次时不产生未来批次的状态。
- 实际已经到期的批次不能重新进入原调用等待；之后作答仍按迟到路径处理。
- 操作成功后界面更新真实期限，失败可见。每批保留自己的身份和到期点。

### 4.4 迟到作答与消息交付

超时题仍允许后续作答或忽略。迟到内容以本包通知投递给原发问主体，不冒充用户发言。通知必须自包含，模型不必凭记忆还原旧工具调用。

通知正文包含：稳定题号、题干全文、全部选项及各项说明、多选属性、实际答案或明确忽略状态，以及时间信息。答案按 4.2.4 确定。全部选项属于题目信息，不表示用户全选；只有被选中且有效的自定义文本列入答案，未选中草稿不进入通知。

- 主体空闲且没有本包尚未开始的投递时，立即唤醒开始轮次；运行中或已有本包待启动投递时，在下一领取点并入。同一领取窗口的多条由宿主一起领取，不故意逐题串行开轮次。
- 运行中的异步等待按 2.1 的可处理消息规则及时交回控制；先到未领取答案同样有效。
- 轮次结束边缘的已接受通知必须有可处理的恢复路径，不重复正文，不把投递异常伪装成成功。
- 已到期未处理题在新批接管时清扫超龄记录，保留期为 24 小时。该期限控制到期后的题目记录，不改变正在等待批次的期限。
- 题目已清扫或主体不可接收时，提交必须显示未送达，不能声称答案已被接受。
- 暂存题、计时和接管监听由插件管理；卸载时未结请求交还可用原生路径或明确取消，不留下悬置承诺。已超时请求不能重复交还产生新的幻影问题卡。

## 5. 配置、语言与设置界面

### 5.1 来源、生效与失败处理

本章是配置默认值和合法范围的唯一权威。功能节规定使用语义，设计引用本章，不维护第二份默认表。

- 配置按从低到高的优先级合并：schema 默认值、宿主配置行、用户设置覆盖。用户层没有该字段时，继续使用组合层值；字段存在但值等于默认值，仍算用户覆盖。
- 可编辑字段位于宿主行的 `config.settings` 嵌套子树。保存后无需重启，后续调用使用新值；描述和参数说明中的数字、语言及后端也随生效值刷新。
- dsh 的子代理模型选择开关和允许名单由 dsh 管理，不复制到本包设置表单或配置快照；实时读取及失败处理按 2.3.2，查询工具对各目标的适用性按 2.3.4。
- 工具行的 `toolName` 只决定本行注册哪个工具，不属于设置字段，也不参与宿主设置覆盖；宿主行缺省为不注册工具的配置角色。
- 配置快照缺席时工具使用合法备用值，并给出设置未接线的诊断，不能出现界面保存成功、行为不变却没有线索。

配置失败按发生时机处理，不能把配置缺失与配置损坏静默混同：

| 发生时机 | 所需处理 |
| --- | --- |
| 提交非法新输入 | 拒绝保存并说明原因。 |
| 运行中收到非法配置 | 保留上一合法值并告警。 |
| 启动时遇到跨字段非法持久值 | 保持设置修复入口，以合法默认值运行，明确显示降级状态。 |

- 活动批次已采用的初始期限不因修改 `askTimeoutMs` 重置；延长动作采用点击时生效的追加值。
- 宿主配置行与用户层均未显式设置 `askUiSeat` 时，才使用其默认值。已有合法显式选择保持不变，不为应用默认值而清除覆盖或改写用户配置。显示方式不决定是否接管提问，接管开关按 4.1 生效。

### 5.2 默认值与范围

| 配置 | 默认值 | 合法范围／解释 |
| --- | --- | --- |
| `defaultYieldMs` | `20000` ms | 默认首次等待预算 |
| `minYieldMs` / `maxYieldMs` | `1000` / `600000` ms | 首次等待请求的可配置夹紧下限／上限 |
| `defaultWaitMs` | `30000` ms | 等待示例默认配置；等待工具参数仍必填 |
| `minWaitMs` / `maxWaitMs` | `250` / `600000` ms | 等待请求的可配置夹紧下限／上限 |
| `pollIntervalMs` | `500` ms | 子代理运行状态备用轮询间隔，实际调用不得因此越出总预算 |
| `maxResultChars` | `30000` | `[1,1000000]` 的正整数，按 `String.length` 计量保留的结果内容，不是字节；提示另计规则见 2.2.3 |
| `jobKind` | `async-command` | 非空字符串，命令作业种类 |
| `subagentProvider` | `spawn` | 子代理后端；修剪后空值使用默认，未知后端在调用时可读拒绝 |
| `uiLang` | `auto` | `auto` / `zh` / `en` |
| `agentLang` | `en` | `en` / `zh` |
| `silentFailureGuard` | `false` | 布尔，仅本包预设的可选防护 |
| `askTakeover` | `false` | 布尔，仅本包根 Agent 的普通提问 |
| `askTimeoutMs` | `60000` ms | 固定合法配置区间 `[10000,600000]`，初始提问窗口 |
| `askExtendMs` | `60000` ms | 每次延长等待时长，正有限毫秒值，计时值遵守本章合法数值范围 |
| `askUiSeat` | `sidebar` | `sidebar`（侧边栏底栏徽标）／`overlay`（右下角浮窗） |

维护配置校验时，分两步判断，不要把字段合法范围与请求夹紧范围混为一谈：

1. **检查设置字段本身**。`askTimeoutMs` 使用表内固定区间；其余预算毫秒字段和延长时长字段使用 `[1,2147483647]`，允许小数。`maxResultChars` 计字符，必须是表内范围的正整数。
2. **检查字段之间的关系**。必须同时满足 `minYieldMs ≤ defaultYieldMs ≤ maxYieldMs`、`minWaitMs ≤ defaultWaitMs ≤ maxWaitMs` 和 `pollIntervalMs ≤ maxWaitMs`。

单次调用再按生效的 min／max 设置夹紧请求值，即把超出区间的值取为相应边界。该请求区间可配置，不是设置字段本身的固定合法范围。调用已经开始后，只能扣减剩余预算，不能将剩余值重新抬到下限而扩大总预算。

### 5.3 两个独立语言开关

- `uiLang` 管理本包设置表单和待答界面；自动档只读跟随宿主语言，显式中文／英文由本包选择，不能修改宿主全局语言。
- `agentLang` 管理六工具的描述、参数说明、提示、错误和本包纪律文案，默认英文；中文档同样完整。
- 只改一边，另一边的可见文案不变。两档键集对应，遗漏翻译不能静默显示键名或另一语言。
- 工具名、模型路由、命令、题目和用户输入是数据，保持原样；翻译不能改变预算、字段或行为。
- 宿主拥有的插件元数据按宿主语言显示，不冒称受本包独立开关控制；操作者日志格式不随语言开关变化。

### 5.4 设置页面

设置入口是插件列表中本包详情页，表单在描述与组件行之间直接可见，不要求切预设、展开组件或进入行级子页。写入使用宿主本机回环设置入口；不可用或只读时明确说明，不伪造可写。

- 控件与宿主官方设置表单一致，采用可用的官方共享控件；宿主未提供的输入类型可复用字段外壳，不复制整套等价表单。
- 全部可编辑字段按身份在场，显示真实生效值。字段标签、说明、覆盖状态、输入与错误关联，键盘与辅助技术可操作，深浅主题均可读。
- 编辑只暂存；只有保存写入。恢复默认也只暂存清除该字段覆盖，保存才生效；离开页面丢弃未保存草稿。
- 覆盖依据是用户层是否存在字段，不按值是否等于默认推测。只提交改过的字段，不用整表写入清掉其他覆盖。
- 保存是一次原子提交，按真实应答判成败。无改动、非法草稿或保存中不可保存；失败保留草稿并可见提示，不假报成功。
- 毫秒字段同时显示生效值与当前草稿的秒数，草稿随每次输入立即变化。整数秒无小数、非整数最多两位；亚 10 ms 正值显示 `< 0.01 s`。
- 空、非数字、非有限或非正值显示 `—`；非法值另给字段原因，空草稿清覆盖语义不变。
- 读数在字段说明下换行，含“生效／输入”两个标识，数值只用秒文本，单位存储仍是毫秒。
- 安装、停用或卸载的已知风险需要用户动作时，在设置页醒目提示，不能只藏在维护说明。

### 5.5 设置名称与说明内容

中文档的全部设置字段、枚举选项、操作按钮、状态和校验提示使用自然、具体的中文。同一概念使用同一名称。标签写清设置对象和用途，说明写清适用范围及修改后的行为；不能用近义词重复标签来代替解释。配置键、枚举值和工具参数名保持原样，作为技术标识补充展示，不代替中文名称。文案改写不改变执行机制、合法范围或配置优先级。

下表规定中文字段名称和需要解释的功能语义，不是必须逐句展示的文案模板。毫秒字段名称附“（毫秒）”，读数按 5.4 显示；默认值和合法范围只在 5.2 登记。按 5.6 分配常驻说明与展开帮助，并按 5.7 判断内容是否有助于当前受众使用功能。功能行为、合法范围和失败处理仍按各功能章节实现。

| 配置 | 中文字段名称 | 功能说明要点 |
| --- | --- | --- |
| `defaultYieldMs` | 默认首次等待时长 | `async_run` 和 `async_workflow` 未指定 `yield_ms` 时采用的等待时长。等待内完成直接取得结果；到时仍未完成则取得作业编号（`job_id`），后台任务继续运行，Agent 可继续其他工作。 |
| `minYieldMs` / `maxYieldMs` | 首次等待时长下限／首次等待时长上限 | 限制本次 `yield_ms` 的有效值。请求超出区间时按相应边界取值；到时返回作业编号，后台任务继续运行。 |
| `defaultWaitMs` | 等待示例时长 | 用于后续等待调用示例中的 `wait_ms` 数值。实际调用两个等待工具时须显式填写 `wait_ms`。 |
| `minWaitMs` / `maxWaitMs` | 单次等待时长下限／单次等待时长上限 | 限制两个等待工具本次 `wait_ms` 的有效值。请求超出区间时按相应边界取值；预算覆盖本次全部阶段，到时交回控制，后台任务继续运行。 |
| `pollIntervalMs` | 子代理状态检查间隔 | `async_wait_agent` 定期检查子代理运行状态的间隔，用作结束事件未到达时的备用判断。 |
| `maxResultChars` | 结果内容字符上限 | 限制单次保留的结果内容字符数，超出时保留首尾并标明截断；状态和裁剪说明另计。计量规则按 2.2.3 和 5.2。 |
| `jobKind` | 命令作业类型标识 | 设置注册命令作业使用的类型名称，便于在作业列表和日志中识别。 |
| `subagentProvider` | 子代理创建后端 | 选择 `async_agent` 使用的子代理创建服务。需要指定模型时，使用调用中的 `provider`／`model` 参数。 |
| `uiLang` | 插件界面语言 | 选择设置表单、字段帮助和待答界面的语言，可跟随宿主语言或显式选择中文／英文。 |
| `agentLang` | Agent 文案语言 | 选择工具描述、参数说明、提示、错误和执行纪律文案使用的语言。 |
| `silentFailureGuard` | 命令静默失败提示 | 开启后，在命令可能未执行且缺少明显报错的特定条件下，给出诊断提醒和检查建议；适用范围及提醒条件按 6.3。 |
| `askTakeover` | 在待答面板处理提问 | 开启后，在待答面板处理本包两个预设根 Agent 的普通提问；关闭时使用宿主原生流程。等待到期后 Agent 继续处理任务，用户仍可稍后作答。 |
| `askTimeoutMs` | 首次提问等待时长 | 从接收一批提问起计时，同批多题共享期限。到期保留已答内容，Agent 继续处理任务，用户仍可稍后作答；新值用于后续批次。 |
| `askExtendMs` | 每次增加的等待时长 | 每次点击“增加等待时间”，给该会话当时仍在等待的批次各追加的时长。 |
| `askUiSeat` | 待答问题显示方式 | 选择“侧边栏底栏徽标”或“右下角浮窗”；说明各自如何展示、展开问题，按 4.2。默认标记与 5.2 一致。 |

首次等待的展开帮助提供时长示例，区分“直接取得结果”和“先取得作业编号、稍后读取结果”，说明到时后台任务继续运行。示例数值标为演示值，生效值由实际读数展示。设置说明、工具描述、参数说明和返回提示使用一致概念，按各自受众与当前动作提供必要信息；具体分工按 5.7。

### 5.6 常驻说明与展开帮助

每个设置字段提供常驻短说明，以及标签旁可点击的带圈问号帮助按钮。点击后在该字段下方展开详细解释，再次点击收起；不以仅悬停显示的提示代替点击帮助。帮助内容属于本包界面，按 `uiLang` 提供中文和英文，两语的范围、限制和示例含义一致，不依赖其他插件或外部文档补齐。

- 常驻说明优先说明用途、修改后的结果及操作前必须知道的条件。展开帮助补充确实有助于配置的关系、操作步骤和示例；两处均按 5.7 筛选内容，展开区不收纳无关的排除项或内部实现说明。与当前动作相关的必要风险、必填条件和结果状态就近可见。
- 帮助按钮常态可发现。问号大小、轮廓与对比度足以和普通说明文字区分，不能依赖悬停后变色才看见。必要时可附“说明”文字；具体尺寸和样式由设计确定，不使用错误或危险警报来制造醒目效果。
- 支持鼠标、触屏和键盘。按钮有包含字段名称的可访问名称，焦点和展开状态清楚可辨，并关联对应解释区域；深浅主题下均可发现、阅读和操作，不能只靠颜色表达状态。长解释和示例不被裁切或遮住。
- 帮助按钮不提交表单。展开或收起不改变字段值、覆盖状态、草稿、校验结果、秒数读数或保存状态，也不触发提问或任务操作。设置只读、输入非法或保存中时，帮助仍可阅读，字段错误及重要风险不因帮助开合而消失。

### 5.7 文案的信息价值与受众

本节适用于本包全部面向用户和 Agent 的文案：插件与预设简介，设置标签、选项、常驻说明与展开帮助，待答面板及其状态和通知，六工具描述、参数说明、返回提示、错误及两预设的执行纪律，以及公开使用说明。中文和英文遵守相同原则。行为规范约束实现；显示文案只提供当前受众使用功能所需的信息，两者分别审查。

#### 5.7.1 内容选择

- 优先说明功能用途、操作方法、实际结果和必要风险。能够直接说明实际行为时，使用具体表述，不靠连续否定或逐项排除解释功能。
- 禁止无关排除：不得在用途之外罗列与当前操作无关的功能边界。
- 禁止假想纠错：不得为了澄清没有实际使用依据的假想误解，增加无助于读者选择或操作的说明。
- 禁止内部约束外露：不得把实现防护、设计例外、验收反例或开发方的合规要求原样搬入使用说明。确实影响使用时，改写为读者需要知道的条件、结果或动作。
- 禁止重复自证：同一说明中、同一操作流程内，不得反复声明相同边界或保证而不增加新信息。不同入口需要独立使用时可以保留必要信息，但不要求设置、帮助、工具描述和每次返回都重复完整规则。
- 无使用价值的内容直接删除；改成肯定句、移入展开帮助或换一种同义说法，都不算解决问题。规则不是否定词禁用表，也不以字数最少作为目标。

#### 5.7.2 必要信息与表达位置

保留某项限制或警示，必须能说明：省去后，当前受众会在哪个实际任务中误设参数、误选动作、误读结果，或面临何种具体损失。满足这一条件的信息按相关动作就近展示；正文只写判断和操作所需的内容，技术细节可按需展开。

- 用户设置说明回答“有什么用、改了会怎样”。Agent 文案回答“何时调用、如何填写、返回什么、下一步做什么”。执行纪律保留正确调度、权限和结果判断所必需的规则，不套用面向设置使用者的精简尺度。
- 后台任务继续运行、显式取消、参数必填、权限审批、未保存内容丢失、截断与结果找回、超时后可继续作答、卸载前必要动作，以及真实失败或结果未确认等信息，按受众和实际触发条件说明；不能为精简而隐去风险、制造成功或删除必要调用约束。
- 错误和拒绝说明当前原因、受影响对象及可行的下一步；没有依据时不编造原因或恢复保证。正常路径不堆叠尚未发生且无须提前知道的异常说明。
- 删除显示说明不改变既有行为、校验、安全边界、默认值、合法范围、失败处理和协议字段。参数必填、预算、隔离、答案真实性等内部要求继续按相应功能章节执行。

#### 5.7.3 全范围核对与验收

按文案来源及其显示、返回位置清点全部中英文内容，覆盖 5.7 首段的所有类别；逐项判断信息对当前受众的用途。已发现的句子只是定位线索，修正范围不得局限于截图、几个字段或关键词搜索结果。保留项须能说明实际使用理由；删除项不得只转移位置。

## 6. 安全、诊断与信息暴露

### 6.1 沙箱与单次提权

`async_run` 遵守宿主当前沙箱与工作目录，不放宽会话策略、不绕过审批。

- 仅在存在约束执行器及可用目标时提供 `sandbox_permissions`、`justification`；两者成对，理由非空，未支持字段不能静默忽略。
- 单次升权先取得正常审批，再接受进程启动。拒绝、取消、审批服务缺席、无主体或不是严格加宽时，可读区分，零进程启动。
- 许可仅作用于本次调用，不写成后续命令的永久权限。
- 沙箱拒绝、退出失败及信号终止在首次或后台结果中可见。只有实际支持升权时，才给确切的同命令一次重试指引。
- 宿主可能无法识别未覆盖的本地化消息；此时本包不得另建一套权限判定冒充宿主批准。实际没有验证的标记不能算通过。

### 6.2 通用异常与信息暴露

- 插件内部异步拒绝、定时和取消回调错误不得成为进程级未处理异常；退出路径释放自己的监听、定时器和等待登记，不能停止无关任务。
- 模型可控值进入日志时单行化；注册失败的宿主原文在模型结果中单行化并最多 500 字符，完整诊断保留在操作者日志。
- 生命周期和异常诊断写 stderr，不污染宿主启动 stdout。日志失败不伪造业务成功。
- 子进程环境使用宿主提供的环境集合，本包不自造、不追加或剥离键；不收集遥测、不自行发起网络请求或读写凭据。路由目录与模型信息委托 dsh 公开接口读取，适配器自身的访问遵循 dsh；不为查询发起模型推理或凭据探测。
- 输出 spill 位置由宿主决定；本包只交付宿主报告的找回线索，不把临时路径当长期保存保证。

### 6.3 可选静默失败防护

`silentFailureGuard` 默认关闭，只在本包预设范围内生效，同时控制结果诊断、命令描述警示和执行纪律提示。关闭后这三处不产生本包防护内容，其他预设不受开关影响。

- 受限执行、未提权、存在约束执行器，且命令符合捕获形启发式并产生空白输出时，给条件式提示：若预期输出缺失，命令可能未执行，先裸调用验证；不直接断言失败。
- 捕获形的形态清单由设计 §6.2 维护；普通管道不纳入空输出启发式。良性 cmdlet 捕获形空输出可产生条件提示，不冒称确定拒绝。
- 输出命中受限部署的可见拒绝签名时，可附诊断和裸调用／正常升权重试出路；这是附加解释，不替换宿主沙箱判定。
- 命令描述只在声明提权字段的部署显示警示；执行纪律紧凑且随开关和模型语言更新。部署特有的杀毒软件规则不能宣传为所有机器的通用事实，也不加入可移植的结果判定。
- 本包防护导致的重复、误判或错误提示须修正；不承担所有宿主或环境异常的自动恢复。

#### 功能与权限要求

- 在插件设置中提供开关，Windows 环境启用后，以 Git Bash 作为异步命令执行的默认命令行。实际执行命令的 `async_run` 及子代理对它的调用使用相同规则；`async_workflow` 本身仍只编排代理。
- 采用支持受限执行的方案：Git Bash 必须能在只读、工作区内读写及 `dsh-approve-for-me` 的“自动审批”权限预设下直接运行当前策略允许的命令。普通命令不能仅因 Bash 初始化失败而被迫申请完全权限。
- 保持只读和工作区边界。不得通过关闭沙箱、永久放宽会话策略、默认使用完全权限或未隔离执行来满足直接可用要求。Bash 启动的脚本及子进程同样受当前权限约束。
- 与 `dsh-approve-for-me` 兼容。危险命令和需要更宽权限的工作区外操作，在取得本次有效许可前受到拦截，并能进入宿主正常审批流程，由自动审批插件按其配置审查。命令改用 Bash、脚本、重定向或子进程后，不得因此漏过本应触发的检查。
- 审批请求提供真实工具身份、Bash 命令或脚本、实际参数、工作目录、申请权限及理由，足以让审批方判断本次操作；不能只送审无实际内容的启动包装。接管范围、拒绝规则、审查故障和人工备用流程遵守审批插件的生效配置。
- 在同一会话策略和审批配置下，Git Bash 与 dsh 原生 PowerShell 的等价操作在可审批性上保持一致：应受限的操作仍受限，应审批的操作仍可送审，批准只作用于本次操作；拒绝、取消或未取得有效许可时，不执行所申请的越权操作。开关本身不授予权限。

#### 异步行为与使用反馈

- 保留本包的首次等待、消息打断、后台存活、输出读取、完成通知及显式取消规则。每次调用绑定一致的执行后端、命令和权限；切换开关不能把已解析命令交给另一种 shell，也不改变已启动作业的后端或权限。
- 设置、工具描述、参数说明及诊断与实际后端一致，按第 5 章的语言和界面要求提供。Bash 不可用或受限执行准备失败时，说明原因与恢复方法，不静默改用另一种 shell 或未隔离执行。

#### 后续验收结果

- 在独立 Windows 实例中，分别验证只读、工作区内读写和自动审批预设：策略允许的命令能运行，受限写入和越界副作用被阻止；不能仅凭非受限模式成功判为通过。
