## 1. 产品目标与职责范围

### 1.1 产品目标

#### 产品目的

本插件面向需要长期自主执行的 Agent 任务，为任务的安全、持续推进提供支持。任务推进不应依赖人工持续在场，也不应因局部操作或交互的无限等待而永久失去后续处置机会。系统应在有效授权与安全约束内，保留观察状态、判断结果、调整行动和接受干预的能力，使正常工作能够持续，异常情况能够得到处理，无法继续时能够明确说明原因。

#### 贯穿产品的要求

开发和取舍时须同时保持以下要求：

- **局部等待不阻断整体推进**：整体推进不以每项局部工作及时正常结束为前提。某项工作发生延迟、失败、挂起或不返回时，调用方仍应保留处理其他工作、判断问题和采取处置的机会。
- **长期工作可持续、可控**：正常长期工作不应仅因耗时而被终止；调用方须能在有界等待后重新取得控制，任务状态可观察，并支持明确干预和停止。等待预算不是后台任务寿命，结束等待不等于停止后台工作，等待返回也不等于任务成功。
- **自主推进遵守授权与安全边界**：无人回复不构成许可，提问到期只返回未答事实；缺少继续所必需的决定时，须明确说明阻碍。持续推进与可控性必须在有效授权和安全约束内同时满足；效率、体验和减少模型消耗属于优化目标。
- **以真实进展判断推进**：依据真实任务状态及后续行动判断进展，不把会话活跃、回合续接、工具调用次数或进程存活等同于有效推进。允许有目的地等待、结束当前回合或明确停止，不要求为接收将来消息一直等待。使用 goal（持续推进任务的目标机制）时，可围绕实际后台结果或明确任务依赖进行有界等待，减少结束回合后又被目标驱动唤醒的无效往返，而不以维持会话活跃为目的。

### 1.2 产品组成与影响范围

#### 职责范围与协作边界

本文的“宿主”均指加载本插件的 dsh。dsh 原生工具指 dsh 自带的工具，不包括本插件工具。

本包负责执行与等待分离、有界等待、覆盖范围内的提问接管、真实状态和结果交付，并保留任务管理入口，为上述目标提供支持。命令或编排在首次等待预算内完成时，同次调用直接返回结果；超过预算时返回后台作业编号，任务继续运行。

宿主负责命令执行、作业、子代理、消息及其生命周期，命令和子代理的创建、管理与权限仍由宿主承担；自动审批插件负责其接管范围内的风险与授权审查。本包不代替这些职责，也不将任意宿主工具自动变成异步工具。

- 使用官方插件服务和 bundle patch 声明，不修改宿主源码、不打宿主源码补丁。
- 不替换宿主的作业、命令执行、子代理、审批或配置服务。自建预设的工具清单由使用者维护；预设功能绑定只按 3.4 改变已选预设的纪律注入、静默失败提示和提问处理，不改变未选预设的这些行为。
- 面向本地执行环境；Windows 与 Linux 的要求见 3.3，macOS 和远程执行环境不在验证范围。

#### 产品组成

交付一个插件包、五个直接可调用的工具、两个 Agent 预设、插件设置表单及可选的提问接管和静默失败防护。

| 工具 | 职责 |
| --- | --- |
| `async_run` | 启动命令，首次等待结束时返回结果或后台作业句柄 |
| `async_wait` | 检查已就绪内容，确认存在可等待工作时才有界挂起，按 2.1、2.2.5 交回控制并交付作业内容 |
| `async_agent` | 创建仅后台运行的可续子代理，返回 `agent_id` |
| `async_workflow` | 将宿主编排引擎的一次运行作为后台作业管理 |
| `async_list_subagent_models` | 只读列出或搜索供应商／模型，分页返回并说明对目标创建工具的适用性 |

两个预设是 `dsh-async`（异步模式）与 `dsh-async-create`（异步创造模式）。工具随使用者挂载它的预设行生效，不被限定为只有这两个预设可用；本包不把工具注册进宿主全局工具层。工具使用新名称，不遮蔽原生工具；两个新增预设的定向组合规则见第 3 章。

提问接管和静默失败防护默认关闭；开启后仅在预设功能绑定名单内生效。异步执行纪律也使用同一名单，不受这两个开关控制。名单的设置与生效规则见 3.4，默认范围见 5.2。提问接管只覆盖根 Agent 的普通提问，不接管审批或计划评审；具体范围见第 4 章。

## 2. 异步任务的执行、等待与结果

### 2.1 共用等待契约

#### 2.1.1 主体、目标与预算

“主体”是本次调用工具的 Agent，可以是根代理、子代理或更深层代理。“目标”是本次等待的作业或子代理。消息归属、等待结束和任务完成分别判断；同一组合中其他 Agent 的事件不能当作本主体收到消息或目标完成。

- `async_wait` 是本包公开等待入口，必须显式提供 `wait_ms`，可选 `targets`，不另设等待模式或意图参数。检查范围和挂起条件见 2.1.4。
- 正值 `wait_ms` 覆盖插件等待执行阶段的总预算：入口查询、存在性检查、重试、轮询、等待及必要返回处理共同使用一份预算，不各自重新取得完整预算。`wait_ms=0` 表示只检查当前内容，不是零毫秒硬实时要求；必要检查的短时总上限与返回规则由 2.1.4 定义。
- 正等待预算到期后立即进入返回流程，不再等待额外查询或诊断。JavaScript 调度可能带来延迟，不能按硬实时系统解释此预算。宿主进入插件执行前的审批和调度不计入预算。
- 查询超时或失败表示状态未证实，不能当作目标不存在、目标终态或空输出。重试仍受同一预算约束。
- 命令和编排的首次等待使用 `yield_ms`（默认值及边界见 5.2），以本次创建的作业为目标，适用 2.1.4 的唤醒与总预算规则，不依赖其他工作取得等待资格。子代理派生按 2.3.1 在后台启动后立即返回。审批与首次等待分开，不将审批时长算作命令运行时间。

#### 2.1.2 消息唤醒与取消

唤醒条件由 2.1.4 统一规定。入口已到达、尚未处理的消息与等待中新到消息采用同一判定；内部进度、日志、目录和配置快照不构成可处理消息。

- 只观察本主体有权接收的消息，不向其他 Agent 广播，不替宿主领取或丢弃消息。已有消息正文在宿主领取点进入上下文。
- 用户排队消息保持宿主下一轮领取语义，不唤醒当前等待，也不改投递落点。
- 收件箱或待领取列表读取失败时，按未命中可处理消息处理，不制造唤醒或目标终态；等待仍受总预算约束。
- 返回区分目标事件、用户插话、其他消息、调用取消、预算到期，以及未进入等待的无工作或条件未确认情形；挂起后已无可等待工作也须说明。非目标消息不能改变目标状态，具体出口遵守 2.1.4。
- 符合条件的消息和调用取消须及时结束等待，准备查询阶段同样适用；具体可测容差由设计规定。
- 等待结束不停止后台工作。显式作业终止及子代理管理继续使用宿主的非阻塞管理工具。

#### 2.1.3 状态、通知与结果

- 区分后台作业终态、子代理变化、调用结束等待和内容交付，不以一个状态冒充另一个。
- 返回说明是否进入挂起等待、未进入或结束等待的原因、涉及对象及已交付内容。没有可等待工作、条件无法确认、目标终态、实际取消和预算到期分别表达；检查耗尽预算时如实说明，不能伪称已挂起等待或确认无工作。状态字段及展示形态由设计确定，提示使用真实生效的预算、语言及后端值。
- 无可等待工作时，指引 Agent 继续可执行工作；当前阶段已完成或只缺后续安排时，报告结果或所需输入并结束回合。确需延时或检查外部条件时，使用相应调度或启动实际的延时／条件检查任务，再按需等待结果，不无条件要求另建睡眠作业。条件未确认时说明检查问题及可行重查方式，不默认要求重跑原任务。等待到期后的行动按 3.1 重新判断，不无条件提示续等。
- 作业结果按 2.2.5 直接交付，不以当前存在等待调用为前提。
- 子代理变化与消息交付见 2.3.3。

#### 2.1.4 等待条件、目标检查与唤醒（WAIT-01）

`async_wait` 用于有界等待已经执行中的工作，不作为保持会话在线、等待未来派工或单纯延时的工具。正时长调用只有在确认存在本次可等待的工作时，才进入挂起等待。任务尚未完成、存在持续目标，或预期未来可能收到消息，均不能单独构成挂起条件。

**可等待工作与检查范围**：

- 可等待工作是宿主公开状态证实的非终态作业或正在运行的子代理，且本主体有权等待。作业的 `stopping` 等尚未收尾状态仍按非终态处理；目录中存在记录、过去执行过任务、已终态作业，以及没有新变化的空闲或无驻留子代理，不构成可等待工作。未来可能恢复运行或收到消息，不改变本次判断。
- 省略 `targets` 或传入 `[]`，由工具在本主体原有权限和可见范围内检查可等待工作；未指定目标不等于没有可等待工作，也不表示允许无工作时等待未来消息。不因自动检查扩大访问权限或父子关系范围。
- `targets` 为非空列表时，只以指定对象判断挂起条件，列表外的运行中工作不能代替指定目标取得等待资格。支持混合列出作业和子代理，每项语义形状为 `{kind: "job" | "agent", id: "..."}`，使用准确类型与不透明标识。
- 参数及所有请求目标的必要类型、可见性和关系校验不能因某一目标已满足返回条件而跳过。空标识、未知类型、错误类型、查无或无权访问的目标可读拒绝，不静默改成未指定目标调用。查询失败不等于查无；返回只说明已证实的状态，不泄漏不可见对象。
- 运行时检查判断对象、权限和公开执行状态，不判断任务意图。存在可等待工作不证明本次等待合理；调用必要性及到期后的行动遵守 3.1。

**入口处理与挂起条件**：

| 入口情况 | 所需行为 |
| --- | --- |
| 已有符合本次唤醒条件的消息、目标终态或尚未报告的变化；未指定目标时已有可交付作业内容 | 完成必要校验后立即交回，按 2.2.5、2.3.3 处理内容及变化，不再挂起。目标终态不要求仍有未交付正文。 |
| 没有已满足的返回条件，且已确认存在可等待工作 | 允许在剩余总预算内挂起；其他对象状态未知时仍如实标明，不将其伪造成运行中。 |
| 确认本次检查范围内没有可等待工作 | 立即返回“本次未进入等待：没有可等待工作”，不消耗剩余预算作纯消息等待，不将此结果称为任务失败或预算到期。 |
| 无法确认是否存在可等待工作，且没有其他已确认对象支持挂起 | 返回“本次未进入等待：无法确认等待条件”及原因、可行的重查方式，不伪装成没有对象或目标终态。检查期间确实发生取消、唤醒或预算到期时，同时保留实际结束原因。 |
| `wait_ms=0` | 只检查当前可用状态与内容，不等待任务进展或未来消息，不重试、不轮询。必要权限、可见性及关系查询各只发起一次，全部检查与返回处理共用短时总上限，不按目标或查询数量另给时间；查询不能及时完成时返回未确认，不猜测对象不存在或已完成。无需存在可等待工作；合法可见的运行中作业也可交付当前未交付增量。 |

零等待的检查总上限由设计根据受支持宿主的接口与实测确定，给出明确数值及固定调度容差；不采用正等待下限，也不直接沿用现有两秒窗口作为已批准值。检查期间仍处理已到的有效消息并及时响应取消；慢查询不省略权限校验，也不在工具返回后追补未经确认的结果。

入口先检查已有返回条件，不为取得挂起资格而等待未来工作启动；校验与查询受 2.1.1、2.1.2 的时间和中断约束。检查期间到达的消息、结果和状态变化不能因检查与订阅的交接而遗漏；具体实现由设计规定。

**挂起后的唤醒与退出**：

| 调用条件 | 结束等待的条件 |
| --- | --- |
| 省略 `targets` 或传入 `[]`，且已满足挂起条件 | 任一发给本主体、可在下一模型步骤处理的消息到达，或作业结果可交付时交回。 |
| `targets` 为非空列表，且已满足挂起条件 | 任一指定作业进入终态、指定子代理产生 2.3.3 定义的变化通知，或用户插话到达时交回。 |
| 确认本次检查范围内已无可等待工作 | 及时交回，不继续等待未来消息；能确认的终态和变化按相应规则报告，不能将未知状态当作已结束。 |
| 调用取消或预算到期 | 结束本次等待，返回实际原因，后台任务继续运行。 |

- 多目标采用任一满足即返回。返回说明触发对象及其他目标的已知状态，不逐个调用等待，也不要求全部目标结束。目标类型、消息来源及所属主体可靠关联，不从通知正文猜测编号。
- 未指定目标时，符合条件的通知和代理转达均可唤醒；指定目标时，非目标消息按 2.1.2 正常投递，不结束本次等待。
- 非目标消息和列表外作业内容不改变指定目标的唤醒条件；在其他原因使本次调用返回时，仍按 2.2.5 顺带交付已就绪内容。挂起条件与内容交付分别判断，不为交付或重试读取已经结束的工作继续挂起。
- 没有活等待、本次未进入等待或当前回合已结束时，作业结果按 2.2.5 交付，消息按宿主原有语义投递。
- `wait_ms` 为有限非负数。零等待不按正等待下限夹紧，按本节的检查总上限返回；正数按 5.2 处理。缺省、负数、非数值及非有限值可读拒绝。正等待的检查与挂起共用预算，不在确认存在工作后重新计时；预算到期不再等待额外检查。

### 2.2 命令执行与作业取回

#### 2.2.1 启动与首次等待

`async_run` 接受必填 `command`、`description`，以及可选 `yield_ms`、`workdir`；单次提权参数见 6.1。

启动前，先按宿主规则取得会话当前有效目录，再解析本次 `workdir`：

| 本次调用 | 目录要求 |
| --- | --- |
| 省略 `workdir` | 使用会话当前有效目录。 |
| 相对 `workdir` | 以会话当前有效目录为基准解析。 |
| 绝对 `workdir` | 保持绝对路径语义。 |

会话切换目录后，后续命令按新目录解析，不使用会话创建时的旧目录。当前目录检查、失效恢复及同会话并发处理均遵守目标宿主规则。解析失败时说明原因，不在其他目录静默执行；此时零作业注册、零进程启动。已启动进程的目录不随后续会话切换而改变，沙箱权限也不因此扩大。

命令按以下启动和交付规则执行：

- 必须从 Agent 调用。没有主体或入口已取消时，可读拒绝，零作业注册、零进程启动。
- 参数和权限批准完成后，先接受作业注册及并发准入，再启动进程。触顶拒绝时没有进程在运行；说明生效上限、存活作业和等待或终止不再需要的作业的出路。
- 命令从执行开始就是归属于发起会话的作业，活动期间可在任务面板观察，而不等预算到期才注册。
- 首次等待内结束的输出和真实结局按 2.2.5 直接交付。
- 首次等待因预算、用户插话或调用取消结束时，命令继续后台执行。正常返回包含 `job_id` 及等待结束原因；后续作业内容按 2.2.5 自动交付，需要等待时使用 `async_wait`。
- 调用停止只结束等待，不把该信号连接成命令取消。宿主可能把可见调用结果改为取消错误，不能据此宣称命令已停止；后台作业仍归宿主作业管理。
- 不设置后台命令的绝对寿命时限。显式 `job_kill` 或 owner 会话处置按宿主语义结束任务。
- 命令及编排的首次等待预算由本次调用参数确定，运行中的首次等待不提供调整操作；提问加时是第 4 章独立功能，不改变这份预算。

#### 2.2.2 作业等待与终态

作业作为 `async_wait` 的一种目标，参数和唤醒条件遵守 2.1.4。

- 入口确认作业对主体可见。查无或不可见可读报错；查询失败给重查出路，不暗示应重新启动命令。
- 已终态作业立即按 2.2.5 处理未交付内容或报告交付状态；尚未结束的作业等待终态，或按 2.1 提前交回。
- 目标终态分别报告 `completed`、`killed`、`failed`，保留输出及结局细节。`stopping` 等尚未收尾状态不当作终态。
- 非终态返回有效句柄、已知状态及本次未进入或结束等待的原因，指引按 3.1 重新判断后续行动；在无法证实时，不宣称目标确定仍在运行，不默认要求再次等待。
- 插话、取消和到期不调用目标的终止操作，等待登记和监听资源在本次调用结束时释放。

#### 2.2.3 输出与一次性交付

作业内容按 2.2.5 首次交付，不为轮询状态提前消费输出。读取、保存及实际交付之间须保持一致，内容尚未成功交付时保留重试路径。

- 返回经过 5.2.1 展示配置筛选的增量文本。首次成功终态读取附带的最终 `result` 必须并入同一次交付，不丢弃、不靠之后再读补救。
- 增量在前、最终结果在后。仅在增量非空且不以换行结尾时，二者之间增加一个换行；只有最终结果时直接作为输出；两者都空则为空串。
- 正常后续读取不重复已交付增量或最终结果。状态可重复查询，不代表结果可以重复交付；送达未确认时按 2.2.5 的有限恢复规则处理，不能把内部消费等同已交付。
- 读取抛错时，给模型可见的读失败标记和重试出路，不把它伪装为空输出；未成功消费的最终结果可在之后成功读取时交付。
- 合并后的结果内容按 `maxResultChars` 裁剪，保留首尾、说明省略量并标注截断。该值限制保留的内容字符数，不是最终模型可见文本的总长上限；裁剪说明及必要的状态、诊断提示另计，保持紧凑，不因内容预算过小而丢失。原始结果中的文本仍计入内容预算。
- 输出丢失与裁剪分开说明。宿主报告 spill 路径时必须交付路径；没有路径不能声称磁盘仍有完整副本。
- 正常退出不加失败标记；非零退出和信号终止在模型可见文本中给出真实标记。首次返回和后台取回两条路径一致，不能将被终止的进程报成正常完成。

#### 2.2.4 呈现与可管理性

命令、状态、运行时长和实时输出从执行开始可见，界面原始命令及调用记录按原有权限保持可查，允许视觉截断。`description` 是活动期的进度说明，完成后按宿主行为清除进度。注册名称与模型可见名称的取值由设计区分；关闭回显时，Agent 的任务列表和返回使用作业编号、名称或简短描述，不附命令原文。开启时，原文只能按 5.2.1 选定位置、同批去重和预算规则提供，不能因原文来自注册名称就绕过裁剪或在多个载体重复。不得通过裁掉界面原始记录来满足模型输入预算。

保留宿主 `job_list`、`job_kill` 等非阻塞管理入口。模型可见的作业标识按 5.2.1 保持紧凑；结果读取入口的可见性按 3.2 处理。

#### 2.2.5 作业结果直接交付与恢复（WAIT-01）

本节适用于本包创建的命令和编排作业，以及在本包预设中主体有权访问、经宿主公开作业服务提供输出的其他作业。自建预设明确采用本包等待与交付组合时按 3.2 处理。子代理消息另见 2.3.3。

- 作业在首次等待内完成，直接随创建调用交付结果。转入后台后，内容随等待返回或含结果的完成消息交付；没有活等待时也适用，不要求 Agent 专门再调用一次工具领取已完成结果。
- 同一交付批次指同一主体在一个领取窗口中，将共同进入下一次模型输入的本包完成消息、等待返回及首次等待返回。批次内共享 5.2 的总内容预算，首次等待内完成的命令和编排也从本批剩余额度分配后再构造返回内容。额度不足时裁剪，额度耗尽时保留条目并提供延后交付方式；并行创建调用不能各自取得完整预算。具体批次识别由设计确定。
- 等待返回时，在同批预算内汇集本主体已就绪、尚未交付的作业内容，不限于目标列表。已有消息会在同一模型输入中交付的正文，不再复制到等待返回；只有状态而没有结果正文的通知，由本次交付补齐可用结果。宿主或其他工具已经生成的消息正文保持原样，不为凑本包预算而裁剪或改写；这部分内容不计入本包可控制的总量，但须用于避免本包重复交付。
- 已完成作业在等待入口立即处理。结果尚未交付时提供结果；有依据确认已交付时仅报告终态及已交付事实，不重复正文、不继续空等。送达未确认与恢复请求按下文处理；没有已知可用路径时，不能把暂不可读取写成结果为空或已经交付。
- 作业成功、失败和终止均可结束目标等待。返回保留真实结局与可用输出；读取失败不改变作业结局，须说明读取失败并给出 `async_wait` 重试方式，不要求重跑原任务。
- 运行中作业的增量只在交回给模型时消费。通过零等待主动读取时，返回当前可用内容和状态；没有新内容时明确说明，不将无增量解释为任务失败。
- 首次等待直接返回、等待返回与完成消息共享交付事实。同一输出片段或最终结果在正常交付中只出现一次；同一事件唤醒多个等待时，本包不因此复制正文或多发只要求再次读取的通知。
- 内部读取成功、活等待已释放或结果已准备好，都不能单独视为模型已经收到内容。并发交付、等待取消和读取后尚未提交时须防止内容丢失；结果构造后被宿主替换为取消错误，也不得直接视为已送达并清除唯一副本。正常重复等待只返回必要状态或新增内容，送达未确认时按下列恢复规则处理。

**送达确认与有限恢复。** 正常路径继续自动交付，不因保留副本反复通知或要求额外领取。无法确认内容已进入模型上下文时，保留有明确期限的恢复副本，沿用 `async_wait` 交付入口取得内容，不重新执行原任务。恢复时如不能排除原内容已被收到，须在正文前明确提示“可能重复”，并标明所属作业；这一带标记的恢复不视为正常路径重复投递。已确认送达的内容不因此成为可任意回看的历史结果。

恢复副本的保留时长、存储上限、到期及生命周期清理规则由设计明确，不能无限保存。恢复期限内，取消等待或等待预算到期不提前删除未确认内容；清理后须能说明副本已过期或不可用，不能伪称早已送达。副本恢复仍受原权限、同批内容及条目预算限制；没有副本且宿主未报告其他位置时，不编造找回保证。

- 多作业、多条完成消息和多个工具返回共享 `maxResultChars`，不按数量倍增预算。展示配置筛选后再分配和裁剪；每份内容标明归属，必要结局和裁剪标记保持可辨。批次还须限制条目数及预算外状态、标识和诊断说明的总量，不能通过大量附加提示绕开内容预算。数值、分配次序及合并方式由设计给出有限且可测的规则；无法在本批交付的项目给出紧凑的延后标记和继续方式，不得静默丢失。
- 超预算内容说明省略范围，并提供现有完整输出位置或继续取得尚未交付内容的可执行方式。没有可用副本时如实说明缺失范围；已消费但尚未交付的内容不能因裁剪永久丢失。恢复未完成交付不等于提供历史回顾服务。
- 目标参数决定挂起检查范围及唤醒条件，不限制同批内容的交付范围。作业完成消息在主体忙碌、空闲、未进入等待或没有等待调用时，都采用直接交付规则；本包交付提示不得引导对刚收到的结果再次读取。

### 2.3 子代理派生、模型选择与等待

#### 2.3.1 后台派生与原生参数兼容

`async_agent` 的公共调用参数与目标版本 dsh 原生子代理创建工具保持名称、类型、必填条件、缺省及校验语义一致。参数兼容不代表两工具采用相同的策略生效时机；本包实时策略见 2.3.2，查询结果的目标适用性见 2.3.4。

| 参数 | 要求 |
| --- | --- |
| `description`、`prompt` | 必填字符串，分别为任务展示说明和任务内容。任务说明按当前后端是否继承上下文如实编写；独立新子代理的任务书自包含。 |
| `cwd` | 可选字符串，指定子代理初始目录；缺省继承父代理当前有效目录，相对路径以该目录解析。后续目录变化互不影响，权限与校验遵循 dsh。 |
| `provider`、`model` | 可选且必须成对，值为准确的 LLM 路由 ID。省略时按 dsh 的配置默认、后端路由默认及父路由继承顺序解析，不把显示名称当作 ID。 |
| `reasoning_effort` | 可选非空字符串，使用所选模型支持的推理强度 ID。允许单独指定并校验最终有效路由；省略时继承兼容值或使用所选模型默认值，换路由时不沿用不兼容的旧值。 |
| `agent_preset` | 仅在工具配置了可选预设且后端支持独立预设选择时提供；按允许集合校验，省略时使用配置默认或继承父预设。不得据此向原本无权选择的预设开放权限。 |

- 只有后台形态，不提供前台模式选择；派生成功后立即返回 `started`、`agent_id`、实际指定或继承路由及有界等待指引，不等待任务完成、不轮询。创建工具本身不增加等待时长参数；等待预算属于 `async_wait`。
- 子代理后端由 `subagentProvider` 配置选择，与调用参数中的 LLM `provider` 分开。无主体、后端未注册、不支持可续派生或不支持请求参数时，可读拒绝且不派生；参数按后端支持条件展示和执行，不能接受后静默忽略。
- dsh 原生工具的内部配置不是 Agent 调用参数。保留按 dsh 配置子代理默认选项及可选预设的方式，不开放任意参数透传；未知参数显式报错并列出当前支持键。
- 指定路由或推理强度时，在创建前校验有效路由和模型支持信息。参数、权限、策略及解析失败均不返回成功句柄；可更换路由解决的拒绝，提示调用 `async_list_subagent_models` 列出或搜索，并给出保留目标工具的查询方式，不附整份模型表、不自动换模型重试。
- 最终回答及普通转达按 dsh 消息进入直接父主体上下文。子代理成功启动后，创建工具返回不停止后台执行；成功、失败及取消的结算由 dsh 管理，本包不重复投递最终回答，不遗留未承接的异步拒绝。

#### 2.3.2 模型选择配置实时生效

配置唯一来源为 dsh 现有的子代理模型选择开关和允许名单。本包不另设名单，不以会话开始时写入的策略记录限制后续 `async_agent` 调用，也不修改 dsh 原生工具的策略。

- 用户成功保存配置后，已有会话、新会话、恢复会话及各层子代理的后续本包派生调用读取当前生效配置，无需重开会话或重启实例。新增路由可用于后续选择；删除路由后后续显式选择被拒绝。
- 开关关闭时，显式指定路由或推理强度被拒绝。全部省略时，按 2.3.1 使用配置默认或继承路由，不因允许名单变化被拒绝；已运行子代理不自动换模型、不停止。
- 每次创建使用一致的生效配置，在实际启动前确认请求仍被允许。校验期间配置变化导致路由被撤回时，本次拒绝或要求重试，不使用过期许可继续创建。查询结果不是后续创建的授权凭据。

显式选择遇到以下情况时，在派生前拒绝，并说明当前原因：

| 条件 | 所需处理 |
| --- | --- |
| 所选路由不在允许名单内 | 拒绝该路由，不创建子代理。 |
| 开关启用，但名单为空或非法 | 说明名单问题，拒绝显式选择。 |
| 设置服务缺席或读取失败 | 说明策略尚无法读取，拒绝显式选择。 |

这些失败都不能用旧会话策略、全部放行或任意替代模型解决。其他异步工具及无显式模型选择的派生不受影响。

配置变化不向所有 Agent 推送完整列表，不因保存动作唤醒无关任务。dsh 原生创建工具仍遵循其实际会话策略；本包不能把实时配置描述成原生工具已经采用的策略。

#### 2.3.3 子代理目标与变化通知

子代理作为 `async_wait` 的一种目标，遵守 2.1。

- 首先确认目标存在，且在本主体有权等待的子代理范围内。查无与查询失败分开；短暂尚不可见的重查受总预算约束。
- 用公开目录、状态查询和事件证明合法关系及变化事实，不以内部运行记录作为读取答案的入口。

等待子代理表示等待目标产生需要父主体处理的变化，不表示领取子代理结果。

- 指定子代理发给本主体的可处理消息，包括普通转达、提问和结算通知，均可满足本次目标等待。公开状态事件或查询能证明本次等待观察到状态变化时，也可交回控制；目录中存在记录本身不算变化。
- 等待入口已有尚未处理的目标消息或变化通知时立即返回。没有未处理通知时，比较本主体对目标已确认的公开状态与入口状态；能证明两次等待之间发生了尚未报告的新变化时，立即报告一次。只有缺少可比较的观察时才以入口状态建立基准，不能把新变化直接吸收为基准而漏报。
- 已向本主体报告的同一变化及未变化的空闲、无驻留状态，不重复报告为新变化，也不单独提供挂起资格；没有其他可等待工作时按 2.1.4 立即返回。未知状态不当作变化或已结束；后续调用已有新消息、新任务或新变化时正常处理，不为等待其将来出现而对静止对象挂起。观察关联与必要的变化记录由设计确定，不保存子代理结果正文，也不据此建立历史查询功能。
- 等待返回只说明变化来源、目标标识和已证实的状态，提示本主体处理消息；不复制消息正文，不把普通转达、状态变化或停止运行称为成功或最终回答已到达。
- 消息正文、最终回答和结算由宿主及 `send_message` 等相关工具自行交付。保持它们的公开投递语义，兼容能够提供目标归属与变化通知的相关工具。
- 本包不读取子代理私有会话日志取得结果，不接管宿主的回传提示，也不对宿主或子代理自行发出的多条消息做正文合并、改写或相似度去重。验收只要求本包自身不额外复制内容。

#### 2.3.4 路由列表、搜索与目标工具适用性

`async_list_subagent_models` 是独立只读工具。它列出或搜索当前会话可见的子代理 LLM 供应商／模型，不创建代理、不发送模型推理请求、不修改配置或当前 Agent 的路由。名称独立于 dsh 原生 `list_subagent_models`，两者可同时挂载。

**查询方式与内容**：

- 无供应商筛选且无搜索词时，分页浏览供应商，返回准确 ID、名称和对应模型数量；只有确认目标策略后，数量才能标为允许模型数，未确认时标为目录已知数。指定 `provider` 时，分页浏览该供应商的模型。提供 `query` 时，支持跨供应商搜索，也支持在指定供应商内搜索。
- 搜索去除首尾空白，忽略大小写，按供应商或模型的 ID、显示名称作包含匹配；空白搜索词等同未提供。不默认使用正则，不改写准确 ID；同名但不同供应商或不同模型 ID 的条目不合并。
- 指定 `provider` 和 `model` 可查看准确模型及其推理强度 ID、名称和默认项；只指定 `model` 时提示必须同时给出 `provider`。准确模型详情与非空搜索词不能同时请求，冲突参数可读拒绝。模型未提供某项元数据时如实说明，不编造推理强度或替 Agent 选择。
- 模型目录由 dsh 已注册的 LLM 供应商及公开目录接口提供，并结合适用策略。允许名单中未被目录列出的模型仍可按准确 ID 查询和列入结果；不能仅因目录未列出就判不支持。目录条目本身也不等于已获策略允许、已通过凭据验证或远端服务保证可用。
- 读取失败与无匹配分开；部分供应商查询失败时，明确结果不完整，失败部分不记为零模型。结果按 `agentLang` 提供完整中英文文案，供应商／模型 ID、名称及其原始元数据保持原样；不返回凭据、密钥、私有接口地址或其他会话内容。

**目标工具与调用兼容**：

- 支持可选 `target_tool`，按当前会话实际可见的创建工具名称确认目标，可为 `async_agent` 或 dsh 原生子代理创建工具，包括用户配置的工具名。目标只影响筛选、适用性和调用指引，不授予额外权限。
- 省略目标且仅有一个可识别创建工具时，可明确采用该工具；存在多个目标或不能可靠识别时，不默认为通用可用。仅挂查询工具也可查目录，但须说明未确认可用创建入口。

判断适用性时，先确认目标工具，再使用该目标对应的策略来源：

| 目标 | 判断依据 |
| --- | --- |
| `async_agent` | 2.3.2 的当前 dsh 配置。 |
| dsh 原生创建工具 | 该工具的实际参数、配置及当前会话策略。 |

全局名单与原生会话策略可能不同，两个方向都要保留：新增路由可能已可供本包选择，却尚不适用旧会话的原生工具；全局撤销的路由也可能仍在原生会话策略内，不能先按全局名单过滤而遗漏。

结果须标明目标和依据，并区分“允许选择”“不允许选择”“适用性未确认”。只有取得已确认的目标依据，才能将条目标为可选，或提供可直接用于目标工具的参数。若 dsh 公开接口不足以确认策略或参数条件，返回“未确认”及原因；不读取其他会话私有数据、不猜测，也不为取得结论而修改原生工具。

- 目标不存在、不可见、不接受显式路由或后端不支持时，明确报告该限制。可继续提供已获依据的目录信息，但不能生成宣称适用于该目标的创建调用。
- 模型条目使用准确的 `provider`、`model`；推理强度仅在目标支持 `reasoning_effort` 且已确认该模型支持时，作为可选值提供。调用示例仅含目标实际接受的字段；搜索词、分页参数、目标参数和本包专有返回字段不能混入创建参数。不把 dsh 原生工具参数示例宣传为适用于任意工作流的 `agent()` 钩子。
- 查询是当前信息，不保证配置或目录变化后的创建成功；创建仍执行目标自身的校验。不支持路由时，指引 Agent 保留目标工具条件重新列出或搜索，不自动改用另一个创建工具绕过限制。

**分页**：

- 供应商列表、模型列表及搜索结果均分页，先筛选再分页；`page_size` 为整数，默认 20，范围 1—100，非法值可读拒绝。
- 每页提供本页条目、匹配总数、是否还有下一页，以及可直接继续查询的参数。回显目标、筛选和搜索条件；部分结果不完整时，总数明确为已取得结果数，不能冒充全量总数。
- 同一查询和同一版本内顺序稳定，不重复或漏项。继续翻页绑定原查询条件及影响结果的策略／目录版本；配置、目标适用性或目录变化使版本失效时，提示重新查询，不把新旧版本拼接成完整列表。改变筛选条件后从新查询开始。
- 分页不能用正文截断替代；长说明可以缩短，但准确 ID、适用性、完整性标记和继续查询信息必须可见。具体页码或游标形式由设计定义。

### 2.4 后台编排

`async_workflow` 提供 `script`、`meta`、可选 `args`、`yield_ms`。只有后台作业形态，首次等待遵守 2.1，结果交付与恢复见 2.2.5，内容裁剪见 2.2.3。

- 用于用户明确要求的 workflow 或大规模多代理编排；一两个委托使用 `async_agent`。描述必须同时说明使用条件和可用替代入口。
- 参数校验、作业准入在引擎启动前。无主体、入口已取消、引擎缺席或准入触顶时给可读错误，不假装运行已启动。
- 沿用宿主编排引擎，不重写它的隔离、并发、总量和结构化输出校验；后台化不取消这些限制。
- 首次等待内完成直接返回完整可裁剪结果；因消息或时长到期结束等待时返回作业句柄。停止等待不取消编排，显式 `job_kill` 才请求取消运行。
- 编排与命令共享宿主作业并发管理。名称为 `meta.name`，描述进入活动进度，启动即任务面板可见。

#### 2.4.1 脚本与钩子契约

| 项目 | 当前要求 |
| --- | --- |
| `script` | 纯 JavaScript 脚本体，允许顶层 `await`，以 `return` 返回可 JSON 序列化值。不是 TypeScript 或模块，不在脚本中声明参数 `meta`。解析失败不启动；运行错误或无法序列化使编排失败。 |
| `meta` | JSON 对象，非空 `name`、`description` 必填；可选 `whenToUse`、`phases`。阶段项为 `{title, detail?, provider?, model?}`，标题非空，其余为可选字符串；未知字段拒绝。阶段声明不自动改变顺序或路由。 |
| `args` | 可选 JSON 对象，脚本内原样提供；裸列表需包成对象。 |
| `agent(prompt, opts?)` | 等待一个子代理结束，无 schema 返回最终文本，有 schema 返回校验对象；普通子代理失败为 `null`。选项仅为 `schema`、`label`、`phase`、`provider`、`model`；两个路由覆盖可独立提供，不套用 `async_agent` 的成对规则。未知选项拒绝。 |
| `agent` 的 `schema` | 对象根 JSON Schema，仅支持 `type`、`properties`、`required`、`additionalProperties`、`items`、`enum`、`const`、`oneOf`；可有不增加校验约束的 `description`、`title`、`default`、`examples` 注解，值为无损 JSON，前两个为字符串。其他关键字拒绝。 |
| `pipeline(items, ...stages)` | 每条目独立流过阶段，无跨阶段屏障。阶段收到 `(prev, item, index)`；普通阶段错误把本条目降为 `null`，跳过其余阶段，不影响其他条目。 |
| `parallel(thunks)` | 并发执行零参函数，等待全部完成；普通函数错误只把对应结果降为 `null`。 |
| `phase(title)`、`log(message)` | 提供阶段进度及日志；已声明阶段按精确标题匹配。脚本只协调，不提供文件系统、网络、定时器或 Node.js API。 |
| 致命误用 | 坏钩子参数、未知选项、不支持的 schema、超过总量或组合条目上限，终止整个脚本，不能被 `pipeline` 或 `parallel` 吞成局部 `null`。并发槽满时排队，不当作超过总量。 |

#### 2.4.2 运行记录与交付边界

- 活动日志承接阶段、日志、子代理开始和结束信息，阶段更新界面进度。Agent 内容按 5.2.1 筛选；日志展示配置不影响最终结果交付。
- 工具顶层调用提供持久的运行开始、子代理开始／结束、运行结束记录供 GUI 回放。子调度不写这些持久节点，但进度、日志、结算与结果恢复仍有效。
- 记录写入失败告警并停止该次运行的后续记录，不伪造回放成功；不能因记录缺失丢掉作业或最终结果。
- 不为编排内部的单个 one-shot 子代理提供额外模型侧等待入口，编排结果由整次运行交付。

## 3. 异步预设与作用范围

### 3.1 两个预设

- `dsh-async` 基于宿主 shipped standard，保留通用编码功能。
- `dsh-async-create` 基于宿主 shipped 创造模式（cordis 框架系的随宿主预设），保留插件和预设创作功能及对应 skill 工具。
- 五个工具在两预设中直接可调用，不要求模型把它们包装进一个占住调用步骤的同步呈现程序。
- 两预设都只有 `async_run` 命令执行入口，以及 `async_agent`、`async_workflow` 创建入口；保留宿主非阻塞的检查、消息和停止管理工具。
- 在两预设禁用原生同步 shell 和原生委托／编排入口，统一由本包执行创建和等待。原生编排入口默认前台等待整场编排，也有 `run_in_background` 后台形态；本包统一入口，才能一致执行预算与消息规则，并保持子代理创建入口唯一。
- 禁用创建工具时，仍保留必要引擎服务。按当前兼容宿主的预设基线核对完整组成，不丢掉基线的其他功能。
- 任务书按后端是否继承上下文编写，独立新子代理任务书自包含。工具指引要求后台启动后继续独立工作，确实需要运行中工作的进展或结果时才有界等待，不反复轮询或重新派生来检查进展。
- 每次等待前明确所等工作及其进展或结果将如何影响下一步；到期后重新判断状态、等待必要性及后续行动。可以继续等待正常进行的工作、检查异常、调整安排或结束回合，不自动续等，不仅为维持活跃而增加预算。没有输出或连续等待次数多不单独证明任务死循环，不据此自动终止正常长任务。
- 当前阶段已完成、只等父代理后续派工或转交材料时，报告结果及所需输入并结束回合；用户稍后回复或其他未来消息按宿主正常投递继续驱动，不调用等待工具保持在线。可续子代理结束当前回合不等于关闭后续协作，父代理可按宿主消息机制继续安排；不把一般外部事件视作已接入的唤醒源。
- 任务确需延时、定期监控或等待外部条件时，使用相应调度或执行实际的延时／条件检查任务，按需有界等待该任务。不得仅为取得等待资格而创建无实际任务目的的睡眠作业。
- 创建工具的原生参数兼容按 2.3.1 执行；可选预设及模型参数仍受配置和后端支持约束，不把参数兼容当作任意选择预设或模型的许可。

### 3.2 可见性与隔离

工具行只在挂载它们的预设范围内注册；设置表单独立可见，不要求先切换到异步预设。宿主配置行不注册工具，缺省角色不能自动变成命令工具。

- 使用者可在自建预设按工具选择挂载，查询工具与异步创建工具可分别使用；本包不替使用者修改其预设，不保证自建组合会禁用已有同步工具。
- 本包只默认将路由查询工具加入两个异步预设。用户是否将工具用于普通预设或其他工作流，由用户决定；查询工具不自动替换 dsh 原生创建／查询入口，不接管其他工作流。实时策略仅约束 `async_agent`，不改变 `async_workflow` 内部 `agent()` 钩子或其他引擎的策略和参数契约。
- 本包两个预设的创建、等待规则不改写宿主 shipped 预设。
- 异步执行纪律、提问接管和静默失败防护使用 3.4 的共同绑定名单；未选预设不产生这三类绑定行为。工具挂载及下述可见性规则分别生效，不由绑定名单增删工具或改写预设组合。
- 编排行必须能取得所在组合的引擎服务；不正确组合时可读拒绝，不能以不可用行冒充工具可用。

**等待与结果工具的可见性。**

- 两个预设中的本包工具见 1.2；创建与非阻塞管理入口见 3.1。两预设隐藏模型侧的原生 `job_output`，不改动宿主源码、原生预设或其他插件的全局工具行为。
- 不新增历史结果查询工具，也不把隐藏的读取入口替换成历史回顾入口。首次交付失败、未交付内容恢复和截断找回仍按 2.2.5 处理。
- 自建预设只有在明确采用本包等待和交付组合时才应用对应可见性规则，单独挂载本包查询工具不改变既有工具或消息交付。
- 工具描述、参数说明、执行纪律、完成通知、返回提示及后续公开说明使用同一等待与交付规则，明确正等待的工作前提、未指定目标时的自动检查及无工作时的后续行动。到期提示要求重新判断，不以“再次调用”作为默认下一步；零等待和必要的未交付内容恢复继续可用。中英文语义一致，Agent 文案按语义验收；界面原文按 5.7。保留必要调用信息，删除重复指令，不要求调用隐藏工具、再次领取已交付结果或为绕过检查另建无意义任务。

### 3.3 平台要求

Windows 与 Linux 的两个预设提供一致的异步入口清单，均不出现同步 shell。Linux 的命令执行与单次提权必须在对应环境验证；没有该环境时记录未验证，不能用 Windows 结果宣称两平台通过。

### 3.4 预设功能的适用范围（PRESET-BIND-01）

名单按会话当前实际预设 ID 匹配，不按显示名称、默认预设选择或工具行复制来源推断。下列功能使用同一名单，不分别维护三份范围配置：

| 功能 | 选中预设后的行为 |
| --- | --- |
| 异步执行纪律 | 注入后台委托、有界等待、作业结果直接交付、阶段完成后结束回合及 4.1 的提问角色规则；不受下述两个开关控制。 |
| 命令静默失败提示 | `silentFailureGuard` 开启时，按 6.3 产生结果诊断、`async_run` 描述警示和沙箱执行纪律提示。 |
| 在待答面板处理提问 | `askTakeover` 开启时，按 4.1 接管符合条件的根 Agent 普通提问。 |

- 名单决定功能作用于哪些预设，原有开关决定可选功能是否开启。勾选预设不自动打开开关，取消勾选也不改写开关值。未选预设不产生表中三类绑定行为；无实际预设或无法读取预设时，不推断为已选。
- 勾选并保存后，已挂载相关异步工具的自建预设应能获得对应行为，不再要求手工补写或修改工具行的 `owningPreset`，也不能被旧固定名单或原预设 ID 挡住。工具描述与结果诊断均须保持预设隔离；同一工具实现被多个预设复用时，选中预设取得的运行时信息不能使未选预设出现绑定内容。
- 绑定只选择上述功能的适用范围，不安装异步工具、不禁用原生同步或委托工具、不增删 `job_output` 等工具，也不改写用户预设组合。异步工具本身及 3.2 的工具可见性按挂载组合分别生效；没有相关工具时，不能把勾选视为工具已可用。
- 执行纪律应适合复用。涉及“某工具已禁用”等事实时须符合目标会话的实际组合，不能因为选中预设就作出不真实的声明。需要使用异步入口的行为规则与工具实际可见性分别说明，不通过修改用户组合使文案变真。
- 提问的根 Agent 限制、计划评审排除、审批边界及静默失败提示的触发条件保持不变。绑定本身不授予执行、模型选择或提权许可。

- 保存后无需重启，对已有会话的后续组稿、工具调用和新提问使用当前名单。取消绑定后，后续组稿及工具描述不再添加绑定内容，后续命令结算不再添加该防护诊断，新提问交还宿主原生流程；已进入会话历史的文字不回写删除。
- 已启动作业继续执行并按原有规则交付和管理，不因绑定变化被终止。已接管的待答批次继续保留原期限、作答与迟到答案送达规则，不因取消绑定被丢弃或重建。

## 4. 提问接管与待答交互

### 4.1 接管范围与初始等待

总开关为 `askTakeover`，默认关闭。只接管 3.4 绑定名单内预设的根 Agent 普通提问；没有 Agent、会话实际预设未选中、非根主体或计划评审时交还宿主原生流程。审批链不属于提问接管，不替换原生提问工具。

- 一次提问调用是一批，可含多题；同批共享期限，各题保留独立答案状态。
- 初始窗口采用请求进入时生效的 `askTimeoutMs`。窗口内作答返回真实答案，全部题作答或忽略后提前结束。
- 截止时保留已答内容；未答题返回超时事实，允许 Agent 按最佳判断继续，明确之后仍可补答。不能替用户选择推荐项或伪造用户答案。未作答、用户明确不答与真实答案分别记录和显示，不能把模型操作指令呈现为用户自定义答案。
- 调用取消保持取消语义，不被超时合成答案覆盖。

**异步执行纪律中的角色表达（ASK-01）。** 适用预设中的 Agent 应遵守：Agent 提问及选项不使用人称代词，涉及执行者、授权者或归属对象时使用明确、可区分的角色名称；涉及角色的选项写清角色与动作；收到选择后按相同角色理解。

### 4.2 全局待答面板

本包接管的题从进入等待起出现在 Web 页面内待答面板，按会话分组；“全局”仅指页面聚合本包题目，不扩大接管范围，通知渠道限 Web 页面。同一题内不得有标签与说明都相同（或都无说明）的选项，重复即整批拒绝并返回可读错误；忽略或作答提交命中批次或题记录缺席，同判未送达。

- `askUiSeat` 选择待答问题的显示方式。右下角浮窗直接显示问题；侧边栏底栏徽标显示未处理问题数，点击后展开问题。两种方式复用同一题目交互，切换不改提问、计时或答案交付规则。默认值见 5.2。
- 徽标显示未处理问题数，包括仍可回答的已超时题。最新一次读取确认没有待答题且没有需处理的故障时，正常徽标消隐；读取失败仍提供状态入口，不将缓存数量或猜测的 0 当作当前读数。窄侧栏中徽标与底栏按钮同排，图标与一至三位计数各自完整、不相遮挡；面板展开后不压住徽标或侧栏。在更大计数下仍可打开面板并读到准确数量。
- 支持单选、多选、自定义选项、对单题选择不答和跳转所属会话。超时题保留标记，可迟到作答。
- 新题进入待答列表时，向辅助技术提供温和的新增数量提醒，不移动当前键盘焦点、不打断正在进行的朗读，也不自动朗读题干全文。同批新增可合并提醒；倒计时、重复状态刷新和同一题的重新渲染不重复播报。两种显示方式均适用，侧栏面板收起时仍可提醒，文案随 `uiLang`；提醒不改变提问接管、期限或答案状态。
- 展示真实期限和剩余时间，文案使用 `uiLang`；自动档随宿主当前语言更新，不要求重新打开页面。
- 按 5.7.7 分开显示读取失败、明确拒绝、回执无法确认和确认未送达。保留待处理内容，给有依据的下一步。刷新状态与操作结果分别显示，不互相覆盖。

#### 4.2.1 作答项与选择关系

每题提供与预设选项并列的一项“自定义回答”。该项有独立的选中状态和文本输入，文本本身就是答案，不是已选预设项的附加说明。没有预设选项的题目也使用这一自定义作答规则。

| 题型 | 选择规则 |
| --- | --- |
| 单选 | 预设选项与自定义项互斥；选择任一项即取消其他项，只提交当前选中的一项。 |
| 多选 | 预设选项各自切换，自定义项也可独立选择；可以只选预设、只选自定义，或同时选择两者。选中或编辑自定义项不取消已选预设项。 |

题目初始不选中任何项；“推荐”等提示不代表已选中。程序不分析自定义文本与预设项是否语义冲突，也不据此替用户增删选择。

#### 4.2.2 自定义输入与草稿

- 自定义项采用上下布局：第一行显示选择控件和“自定义回答”标题，标题下方单独放置输入框，与预设选项“标题在上、内容在下”的组织方式一致。输入框使用该项可用内容宽度，不与标题横向争用空间；两种面板显示方式和窄屏下均保持这一关系。
- 输入框支持多行编辑，初始可见高度至少容纳三行正文。长文本在框内自动换行，超出可见高度时可通过纵向滚动或扩大编辑区查看，不要求用户横向移动才能检查普通中文回答。字号、行距及内边距应便于阅读和修改，不能只移动位置却仍保留狭小的单行输入框。触屏和无法确认指针类型的环境，输入字号至少 16 CSS 像素；仅细指针且可悬停时可采用与题干相同的较小字号，不通过禁用缩放掩盖聚焦放大。
- 编辑时按 Enter 插入换行，不直接提交；中文输入法确认候选文字也不触发提交。组合输入期间的提交限制见 4.2.4；用户输入的换行和正文原样保留。
- 通过选择控件选中自定义项，或点击其文本输入框、主动输入非空白文本时，选中自定义项，并按 4.2.1 处理其他项；不要求输入后再额外勾选。
- 用户可以通过选择控件取消自定义项的选择。切换选项或取消选择时可以保留自定义文本草稿，但未选中的草稿不参与提交；再次点击输入框或主动输入有效文本时重新选中。
- 清空已选中的自定义文本时，保持该项选中，不自动恢复旧预设选择；本次回答按 4.2.4 判为无效。
- 仅移动键盘焦点、恢复草稿或刷新题目展示，不自动改变选择。文本框有内容、获得焦点或出现光标，都不单独证明该项已选中。

#### 4.2.3 选择反馈与操作

“提交”与“不答”同排同高，可点击区域高度不低于 44 CSS 像素，主次通过外观而非缩小点击区域区分；两种面板和窄屏均不能裁压。

- 预设项与自定义项采用一致的选中效果。以整项底纹变化为主要视觉提示，边框变化为辅助，并有明确的单选标记或勾选标记；不能只靠边框加粗或颜色差异表示选择。
- 普通、悬停、选中和键盘焦点状态容易区分。输入框的焦点轮廓与作答项的选中效果分别表达，未选中的自定义项不能只因悬停或获得焦点而看似已选中。
- 深色和浅色主题下均能直接辨认所有已选项，不能要求用户逐项比较细微边缘变化。长题干、选项说明和自定义文本不遮住选择标记。
- 鼠标、触屏和键盘均可选择、取消选择及编辑；单选项遵守 4.2.1 的替换规则。辅助技术可取得题目、选项名称、选中状态、单选或多选关系以及自定义输入的关联，不仅依赖视觉反馈。

#### 4.2.4 有效提交与答案一致性

- 没有选中项时不可提交。选中的自定义项必须含有效文本；去除首尾空白后为空的文本无效，即使多选题还选有预设项，也不可提交该回答。空白检查只用于有效性判断，不授权改写用户文本。
- 无效时禁用“提交”，并就近说明需要选择答案或填写自定义内容。按钮与快捷键遵守相同规则；服务端也拒绝违反选择关系或有效性规则的作答，不将其记为已答或投递答案。
- 该题自定义回答仍处于输入法组合期、候选文字尚未确认时，客户端暂时禁用提交并说明需要先完成输入；鼠标、触屏及键盘提交入口均不接受该次动作。组合结束后重新检查答案有效性，只在有效时允许再次明确提交。组合期间发起的动作即使随后因失焦结束组合，也不排队补发或自动提交；保留草稿及已选项。“不答／忽略”仍是独立操作，服务端既有选择关系和答案有效性校验保持不变。
- “不答／忽略”是独立操作，不受答案有效性限制，不转换成空答案、推荐项或虚构的自定义回答。
- 提交载荷只包含当前选中的预设项，以及已选中且有效的自定义答案。
- 多选时，自定义答案与其他已选项并列，不作为附加说明。未选中的预设项和文本草稿不进入答案。
- 界面提交记录、窗口内工具返回和 4.4 的迟到通知，必须表达同一组实际选择与自定义答案，区分题目提供的选项和用户选中的答案，不让 Agent 猜测哪部分有效。两种面板显示方式及窗口内、迟到作答均遵守本节规则。

### 4.3 延长等待

每个会话组提供“增加等待时间”动作，每次追加时长可配置，默认 60 秒；配置登记见 5.2。

- 一次点击作用于该组点击当时尚未到期的批次，在各批原截止时间上增加本次时长，倒计时继续运行。
- 同批未答题共用新期限，已答内容保留；一组的操作不影响其他会话。
- 新到批次使用自己的初始期限，不继承之前的延长。没有在窗批次时不产生未来批次的状态。
- 实际已经到期的批次不能重新进入原调用等待；之后作答仍按迟到路径处理。
- 从确认的结果更新真实期限；没有适用批次和已延长分别显示。明确失败与回执无法确认也须区分；结果不明时先刷新，不自动重复发起加时。每批保留自己的身份和到期点。

### 4.4 迟到作答与消息交付

超时题仍允许后续作答或忽略。迟到内容以本包通知投递给原发问主体，不冒充用户发言。通知必须自包含，模型不必凭记忆还原旧工具调用。

通知正文包含：稳定题号、题干全文、全部选项及各项说明、多选属性、实际答案或明确忽略状态，以及时间信息。答案按 4.2.4 确定。全部选项属于题目信息，不表示用户全选；只有被选中且有效的自定义文本列入答案，未选中草稿不进入通知。

- 主体空闲且没有本包尚未开始的投递时，立即唤醒开始轮次；运行中或已有本包待启动投递时，在下一领取点并入。同一领取窗口的多条由宿主一起领取，不故意逐题串行开轮次。
- 运行中的异步等待按 2.1.4 判断迟到答案是否唤醒；先到未领取答案采用同一规则。
- 轮次结束边缘的已接受通知必须有可处理的恢复路径，不重复正文，不把投递异常伪装成成功。
- 接管新批时清扫已到期超过 24 小时、仍未处理的题目。没有新批时，记录可以保留更久；24 小时不是迟到作答本身的拒收截止，也不改变正在等待批次的期限。
- 题目已清扫或主体不可接收时，提交必须显示未送达，不能声称答案已被接受。
- 暂存题、计时和接管监听由插件管理。过期题记录保存在内存，不跨重启或卸载；需要保留的答复应写入原会话。卸载时，未结请求交还可用原生路径或明确取消，不留下悬置请求。已超时的请求不能重复交还，以免产生新的问题卡。

## 5. 配置、语言与设置界面

### 5.1 来源、生效与失败处理

本章是配置默认值和合法范围的唯一权威。功能节规定使用语义，设计引用本章，不维护第二份默认表。

- 配置按从低到高的优先级合并：schema 默认值、宿主配置行、用户设置覆盖。用户层没有该字段时，继续使用组合层值；字段存在但值等于默认值，仍算用户覆盖。
- 可编辑字段位于宿主行的 `config.settings` 嵌套子树。保存后无需重启，后续调用使用新值；描述和参数说明中的数字、语言及后端也随生效值刷新。
- dsh 的子代理模型选择开关和允许名单由 dsh 管理，不复制到本包设置表单或配置快照；实时读取及失败处理按 2.3.2，查询工具对各目标的适用性按 2.3.4。
- 工具行的 `toolName` 只决定本行注册哪个工具，不属于设置字段，也不参与宿主设置覆盖；宿主行缺省为不注册工具的配置角色。
- 配置快照缺席时工具使用合法备用值，并给出设置未接线的诊断，不能出现界面保存成功、行为不变却没有线索。

配置失败按发生时机处理，不能把配置缺失与配置损坏静默混同：

| 发生时机 | 所需处理 |
| --- | --- |
| 提交非法新输入 | 拒绝保存并说明原因。 |
| 运行中收到非法配置 | 保留上一合法值并告警。 |
| 启动时遇到跨字段非法持久值 | 保持设置修复入口，以合法默认值运行，明确显示降级状态。 |

- 活动批次已采用的初始期限不因修改 `askTimeoutMs` 重置；延长动作采用点击时生效的追加值。
- `maxResultChars` 的默认值只用于宿主配置行与用户层均未显式设置该字段的情况。升级后保留已有合法显式值，包括与旧默认值相同的覆盖；恢复默认并保存后清除用户覆盖，再按本节优先级取值。
- 宿主配置行与用户层均未显式设置 `askUiSeat` 时，才使用其默认值。已有合法显式选择保持不变，不为应用默认值而清除覆盖或改写用户配置。显示方式不决定是否接管提问，接管开关按 4.1 生效。
- 首次等待与单次等待配置沿用本节优先级。`minYieldMs`、`minWaitMs` 分别在宿主配置行与用户层均未显式设置对应字段时采用默认值；升级保留已有合法显式值，包括低于默认值的下限，不为应用新默认而改写配置。恢复默认并保存只清除用户覆盖，随后重新按优先级取值；非法配置仍按本节失败规则处理。

**适用预设的保存。**

- 绑定名单存入宿主行 `config.settings`，沿用 5.1 的配置优先级及 5.4 的草稿、原子保存、失败保留和离页丢弃规则。新增字段不能覆盖其他设置。
- 缺省字段按 5.2 取默认范围；升级保留已有合法显式值。数组中的 ID 必须为非空字符串且不得重复，非法新值拒绝保存并给出原因；目录中未发现或加载异常的 ID 本身不视为配置格式非法。
- 允许全部取消。保存空数组表示不向任何预设应用三类绑定行为，不等于恢复默认，也不停止异步工具或后台任务。恢复默认只清除本字段的用户覆盖，保存后按 5.1 重新取值；无宿主配置覆盖时回到 5.2 的两个默认预设。

### 5.2 默认值与范围

| 配置 | 默认值 | 合法范围／解释 |
| --- | --- | --- |
| `defaultYieldMs` | `20000` ms | 默认首次等待预算 |
| `minYieldMs` / `maxYieldMs` | `20000` / `600000` ms | `async_run` 与 `async_workflow` 首次等待请求的可配置夹紧下限／上限 |
| `defaultWaitMs` | `30000` ms | 等待示例默认配置；等待工具参数仍必填 |
| `minWaitMs` / `maxWaitMs` | `20000` / `600000` ms | `async_wait` 单次正等待请求的可配置夹紧下限／上限；`wait_ms=0` 不受下限限制 |
| `pollIntervalMs` | `500` ms | 子代理公开状态变化的备用检查间隔，实际调用不得因此越出总预算 |
| `maxResultChars` | `12000` | `[1,1000000]` 的正整数，按 `String.length` 计量 2.2.5 定义的同一交付批次中本包提供的全部结果内容；提示另计规则见 2.2.3 |
| `workflowProgressLog` | `false` | 布尔，控制是否向 Agent 提供工作流进度日志，语义见 5.2.1 |
| `fullCommandEcho` | `false` | 布尔，同时控制普通命令与工作流脚本原文向 Agent 的回显，语义见 5.2.1 |
| `jobKind` | `async-command` | 非空字符串，命令作业种类 |
| `subagentProvider` | `spawn` | 子代理后端；修剪后空值使用默认，未知后端在调用时可读拒绝 |
| `uiLang` | `auto` | `auto` / `zh` / `en` |
| `agentLang` | `en` | `en` / `zh` |
| `boundPresets` | `["dsh-async", "dsh-async-create"]` | 无重复的非空预设 ID 字符串数组；允许空数组，表示不绑定任何预设；行为见 3.4 |
| `silentFailureGuard` | `false` | 布尔，绑定名单内预设的可选防护 |
| `askTakeover` | `false` | 布尔，绑定名单内预设根 Agent 的普通提问 |
| `askTimeoutMs` | `60000` ms | 固定合法配置区间 `[10000,600000]`，初始提问窗口 |
| `askExtendMs` | `60000` ms | 每次延长等待时长，正有限毫秒值，计时值遵守本章合法数值范围 |
| `askUiSeat` | `sidebar` | `sidebar`（侧边栏底栏徽标）／`overlay`（右下角浮窗） |

维护配置校验时，分两步判断，不要把字段合法范围与请求夹紧范围混为一谈：

1. **检查设置字段本身**。`askTimeoutMs` 使用表内固定区间；其余预算毫秒字段和延长时长字段使用 `[1,2147483647]`，允许小数。`maxResultChars` 计字符，必须是表内范围的正整数。
2. **检查字段之间的关系**。必须同时满足 `minYieldMs ≤ defaultYieldMs ≤ maxYieldMs`、`minWaitMs ≤ defaultWaitMs ≤ maxWaitMs` 和 `pollIntervalMs ≤ maxWaitMs`。

正等待请求及首次等待请求按生效的 min／max 设置夹紧，即把超出区间的值取为相应边界。`async_wait` 的零等待按 2.1.4 执行，不抬高到正等待下限。请求区间不是设置字段本身的固定合法范围。调用已经开始后，只能扣减剩余预算，不能将剩余值重新抬到下限而扩大总预算。

首次等待默认下限用于减少秒级命令因过短预算而转后台、继而增加等待调用和消息交接的情况，不是最短执行时长。作业提前完成即按 2.2.5 交付，插话或取消仍及时结束等待；预算到期后后台工作继续。`defaultYieldMs`、`minYieldMs` 和 `maxYieldMs` 由命令与编排共用，与 `async_wait` 的单次等待配置分别生效，不代替结果交付、重复抑制和内容恢复要求。

单次等待默认下限用于减少有效依赖尚未完成时，因过短正等待预算而反复交回控制的情况，不是最短挂起时长。`async_wait` 仍须先按 2.1.4 判断是否有可等待工作；无工作、已有可交付内容、目标完成、插话或取消等条件要求交回时及时返回，不等满下限。零等待保持立即检查；`defaultWaitMs` 仍仅用于等待示例，实际调用必须显式提供 `wait_ms`。

#### 5.2.1 附加到结果的 Agent 内容

两个展示开关的默认值和类型仅在 5.2 登记，分别控制工作流进度日志和完整命令回显。设置界面、保存与实时生效按第 5 章执行。

- 工作流进度日志关闭时，阶段变化、子代理开始／结束等观察日志仅供界面与既有记录使用，不进入本包交付给 Agent 的结果正文。开启后可向 Agent 提供这些日志，并计入单次总内容预算。命令标准输出、标准错误及工作流最终结果不属于可关闭的进度日志。
- 完整命令回显关闭时，本包预设中的完成通知、等待返回和任务列表使用作业编号、名称或简短描述及状态，不重复整条命令或工作流脚本。开启后，普通命令与 `async_workflow` 的脚本均须支持向 Agent 提供原文；具体呈现位置由设计确定，同一领取窗口中同一作业的原文不在多个载体反复附上。附加原文计入同批内容预算，超限按实际原文长度裁剪并说明，不丢必要结局或改变实际执行内容。
- 两个开关只控制向 Agent 提供的附加内容。原始命令、实时进度和日志在用户界面按原有权限保持可查；不靠裁掉任务原始记录减少模型输入，也不改写命令实际产生的输出。
- 退出码、失败原因、终止事实、读取失败、输出丢失、截断标记和宿主报告的完整输出位置始终可见。可选日志先筛选，再裁剪结果，避免日志挤占关闭后本应留给有效结果的预算。

### 5.3 两个独立语言开关

- `uiLang` 管理本包控制的设置、待答和其他用户界面文案。自动档只读跟随宿主语言，无法确定为中文或英文时使用英文；显式选档不修改宿主全局语言。
- `agentLang` 管理五工具的描述、参数说明、提示、错误和本包纪律文案，默认英文；中文档同样完整。宿主原封不动的提示原文可保留宿主语言；本包新增或改写的指令，包括结果收集句，随 `agentLang` 切换。混合来源逐段区分，不能因处于宿主同名提示段就把自有改写一并排除。
- 两个语言设置各自生效。插件提供两语的入口不得因漏译显示键名或另一语言；同一份宿主消息无法分别渲染时，仍须按 5.7 定义共用模板及该位置的语言选择。
- 工具名、模型路由、命令、题目和用户输入是数据，保持原样；翻译不能改变预算、字段或行为。
- 宿主所控制的文案、包元数据及预设声明按宿主实际提供的显示规则处理，单语入口见 5.7.3；操作者日志格式不随语言开关变化。

### 5.4 设置页面

在插件列表打开本包详情，设置直接位于简介与组件列表之间；不要求切换预设、进入组件子页或先展开全部设置。使用宿主本机回环的设置入口保存；只读或服务不可用时，保留能够核实的值与说明，不伪造可写或已保存。

- 使用可用的宿主共享控件；宿主没有相应输入类型时复用统一的字段外壳，不另做整套表单。所有设置在同一表单中按用途分组，每个字段只有一个编辑位置。字段标签、说明、已保存的自定义值、未保存的修改及错误应能辨认，并与控件关联。
- 编辑只暂存；只有保存才写入。原“恢复默认”操作在页面标为“清除自定义值”，只暂存移除该字段的用户层值；保存后按 5.1 重新取值，可能仍使用宿主配置行的值。离开页面丢弃未保存的修改。开合分组或说明不算离开页面。
- 覆盖依据是用户层是否保存了该字段，不按值是否恰好等于默认判断。只提交改过的字段；一次原子保存，按真实结果报告。无改动、存在非法输入或正在保存时不可保存；保存失败或结果未确认时保留草稿，并分别说明。
- 平时显示一个生效值。仅当输入中的值与生效值不同、无法解析，或暂存了恢复默认时，分别标明当前生效值和待保存的输入或恢复动作。数值相同而来源不同，也须标明暂存的来源变化。时长保持毫秒输入和毫秒存储，秒数随编辑即时换算；整数秒不带小数，其他最多两位，低于 0.01 秒的正值单独标出。非法值给字段原因，空输入仍沿用清除覆盖的语义。取不到生效值时显示未知；遇到 5.1 的启动降级，应显示实际采用的值，将原配置作为需修复的值而非生效值。
- 保存、失败说明、全局状态和须在操作前知道的风险，不放入可折叠组。安装、停用或卸载确有已知风险且需要用户动作时，在相关决定前醒目提示；宿主提供的许可提示仍归宿主。组收起时仍在组标题标出未保存修改及校验错误；保存区列出阻止保存的字段及原因，操作者可直接展开并定位首个有问题的字段。涉及两个字段时，写清两个字段的名称及应满足的关系，不只显示配置键。收起、切换语言、重读预设目录和从诊断定位设置，均不默默写入或撤销草稿、恢复默认请求与错误；实际离开页面仍适用上条离页规则。
- 深浅主题与窄屏下均可使用。鼠标、触屏、键盘与辅助技术可操作分组、字段、帮助和错误定位；焦点与展开状态可辨认。进入页面不随意抢焦点，用户主动定位时应可继续在目标字段操作。

#### 5.4.1 适用预设目录

在插件详情页的“适用预设”组选择适用范围，与其他设置一同保存。说明勾选的实际效果及两个独立开关，行为见 3.4，界面原文见 5.7。

- 从宿主公开预设目录自动读取当前已注册的预设，提供每项带复选框的可多选列表。新增预设自动加入候选项，但不自动选中；已有用户选择不因发现新预设而改变。
- 列表展示宿主提供的显示名称，并附预设 ID 以区分同名项；没有名称时以 ID 显示。保存值为 ID 数组。内置名称沿用宿主显示规则，自定义名称不由本包擅自翻译；切换界面语言不改变绑定对象。
- 打开设置块时读取目录；预设新增、删除、改名或插件装载发生变化后，应通过宿主可用的变更通知更新列表。重新连接后重新读取，并提供手动刷新入口。刷新不提交设置，也不丢弃尚未保存的勾选草稿。
- 加载中、目录为空和读取失败分别显示。读取失败说明原因并提供重试，不把失败当作空目录，不清空保存值或草稿；读取中或失败时仍须保留已保存的选择和未保存的勾选，使用户可查看或取消，是否可保存由设置服务的可写状态决定。
- 加载异常的预设仍在列表展示异常原因，不允许新增勾选。已经保存的绑定保留选中状态并允许取消，不因异常自动删除配置。
- 成功读取的完整目录确实不含已绑定 ID 时，保留该项并按 5.7.6 标明缺席，允许取消绑定。尚未取得完整目录时不据此标记。目录只用于发现和展示，不因暂时缺席停用该 ID 在已有会话中的绑定。显示名称修改而 ID 不变时保持绑定；ID 改变视为新的候选项，不按相似名称迁移。
- 列表遵守本章的只读、帮助和可访问性要求。每项的选中状态清楚可辨，不依赖颜色或按住修饰键操作。

### 5.6 常驻说明与展开帮助

字段旁只说明当前选择的用途、改动后果和必须事先知道的条件；可共用组说明，不在同组每个字段重复。只有对配置有用的详细关系、示例和技术标识才放入展开帮助。同一字段或一组相关字段有详细说明时，保留常态可发现的带圈问号帮助入口，可点击展开／收起，不用仅悬停的提示代替。按钮的可访问名称包含对应字段或组名；展开状态与说明区域关联。无额外信息时不强行配一段帮助。

帮助开合不提交表单，不改值、错误、读数或保存状态，不触发提问或任务操作。只读、输入非法或正在保存时仍可读；内容不得裁切或遮挡操作。命令与工作流的首次等待用一个有用的示例区分直接拿到结果和先拿到后台作业编号；示例清楚标注，不冒充生效值。设置、工具说明及返回提示采用同一概念，分别按用户和 Agent 的实际任务提供信息。

### 5.7 面向用户的产品文案

#### 5.7.1 原文职责与范围

以下文案表是本包自有产品文案的中英文原文。**需求与验收 Agent 亲自撰写和修订原文；开发 Agent 只按原文与适用状态实现，不自行补句、翻译或改写。** 若真实行为、宿主能力或取值方式与原文不符，指出具体差异，由需求与验收 Agent 核实并修订；不得另写一份对用户显示的说法，也不得为了让句子成立而改写实际结果。实现中的词典和模板是原文的运行副本，不是另一处撰稿来源。新增插件自有界面文字在交验前须有完整两语及出现条件；缺少核准原文不能成为隐藏必要提示的理由。

按[公开文档原则中适用于用户资料的写作原则](<documentation-principles.md#写作原则>)写作：按用户任务选择信息，先说用途、实际结果和下一步，风险在相关操作前提醒。不展示无关的排除、内部工作规则、假想误解或反复自证；没有用的说明直接删除，不移入帮助。普通说明不以字数或否定句数量判断。README、用户参考、更新日志和当前问题清单仍在各自正文维护，不复制到界面文案表。

范围含插件与内置预设简介、设置、可访问名称、待答面板、状态与恢复提示，以及本包经宿主作业、会话消息和回放直接呈现给用户的自有文字。宿主原文、用户输入、题目、脚本和命令实际产物、模型／目录名称、配置键、协议字段和准确 ID 属于原始数据；不在运行时擅自翻译或改写。可为用户提供已核实的本地化解释，但原始诊断与技术标识保留可查，遵守第 6 章的可见范围。仅供 Agent 的工具说明、参数、纪律及结构化返回仍按 5.3 与行为章节审查，保留正确调度、权限、确认与恢复规则，不按界面原文逐字核对。若同一事件同时面向用户与 Agent，两者表达相同事实，不把模型的调用指令当成人用帮助。工具产出的详细诊断可供用户按需查看原文；其中本包选择作为普通会话文字直接显示的段落必须有本节核准的事实模板。

#### 5.7.2 怎样呈现原文

条目列出位置、何时显示或替换，以及两语原文。花括号是实际值，不显示占位符；字段名按适用语言填入，ID、路径、状态代码及原始内容不改写。同一格列出多条原文时，分号用于分隔条目；只有注明英文单复数变体时，` / ` 才分隔变体，空格和分隔符本身不显示。未注明为变体的斜杠保留其原义。中文与英文按各自的标点和数字格式呈现。模拟值只用于明确标注的示例。缺值按该状态专用文字呈现；没有必要且没有已批准的替代文字时省略相应可选片段，不将缺值变成 0、成功、失败或另一个事实。按 5.3 选择语言。本包直接控制的人用界面随 `uiLang`；宿主管理页支持本地化的插件元数据随宿主语言；只接受单一字符串的安装前简介及预设选择器按 5.7.3 的单语规则。宿主同一份会话消息或原始记录同时给用户和 Agent、且不能分别渲染时，仍按 `agentLang` 固定已写入的共用内容；不因切换 `uiLang` 伪造历史，不为两种语言另投递一条正文。能独立呈现的 UI 标签仍随 `uiLang`。

独立核对原文与实际时机：对照源码的各个显示入口与真实可操作页面，覆盖两语、动态值、缺值、首屏／展开／定位、正常／失败／未确认、未保存／降级与必要风险。词典键集合或逐字比对可以检出遗漏和擅改，但不能证明内容适用、翻译自然或用户看到了该看到的提示。改文案不改变权限、默认值、合法范围、等待、取消、内容交付或答案真实性。

## 6. 安全、诊断与信息暴露

### 6.1 沙箱与单次提权

`async_run` 遵守宿主当前沙箱与工作目录，不放宽会话策略、不绕过审批。

- 仅在存在约束执行器及可用目标时提供 `sandbox_permissions`、`justification`；两者成对，理由非空，未支持字段不能静默忽略。
- 单次升权先取得正常审批，再接受进程启动。拒绝、取消、审批服务缺席、无主体或不是严格加宽时，可读区分，零进程启动。
- 许可仅作用于本次调用，不写成后续命令的永久权限。
- 沙箱拒绝、退出失败及信号终止在首次或后台结果中可见。只有实际支持升权时，才给确切的同命令一次重试指引。
- 宿主可能无法识别未覆盖的本地化消息；此时本包不得另建一套权限判定冒充宿主批准。实际没有验证的标记不能算通过。

### 6.2 通用异常与信息暴露

- 插件内部异步拒绝、定时和取消回调错误不得成为进程级未处理异常；退出路径释放自己的监听、定时器和等待登记，不能停止无关任务。
- 模型可控值进入日志时单行化；注册失败的宿主原文在模型结果中单行化并最多 500 字符，完整诊断保留在操作者日志。
- 生命周期和异常诊断写 stderr，不污染宿主启动 stdout。日志失败不伪造业务成功。
- 子进程环境使用宿主提供的环境集合，本包不自造、不追加或剥离键；不收集遥测、不自行发起网络请求或读写凭据。路由目录与模型信息委托 dsh 公开接口读取，适配器自身的访问遵循 dsh；不为查询发起模型推理或凭据探测。
- 输出 spill 位置由宿主决定；本包只交付宿主报告的找回线索，不把临时路径当长期保存保证。

### 6.3 可选静默失败防护

`silentFailureGuard` 默认关闭，只在 3.4 绑定名单内生效，同时控制结果诊断、命令描述警示和沙箱执行纪律提示。关闭后这三处不产生本包防护内容；独立的异步执行纪律不受此开关控制。未选预设不产生这些提示。

- 受限执行、未提权、存在约束执行器，且命令符合捕获形启发式并产生空白输出时，给条件式提示：若预期输出缺失，命令可能未执行，先裸调用验证；不直接断言失败。
- 捕获形的形态清单由设计 §6.2 维护；普通管道不纳入空输出启发式。良性 cmdlet 捕获形空输出可产生条件提示，不冒称确定拒绝。
- 输出命中受限部署的可见拒绝签名时，可附诊断和裸调用／正常升权重试出路；这是附加解释，不替换宿主沙箱判定。
- 命令描述只在声明提权字段的部署显示警示；执行纪律紧凑且随开关和模型语言更新。部署特有的杀毒软件规则不能宣传为所有机器的通用事实，也不加入可移植的结果判定。
- 本包防护导致的重复、误判或错误提示须修正；不承担所有宿主或环境异常的自动恢复。

#### 7.1.1 宿主依赖复用与不必要的安装授权

本包安装和升级应复用当前 DSH 已提供的宿主依赖，不因重复安装整套宿主或其间接依赖，要求用户批准与本包运行准备无关的安装脚本。此要求覆盖目标 profile 开启 `autoInstallPeers` 的情况；不能只在关闭自动补齐的干净 profile 中验证成功，也不能要求用户先关闭该选项，来代替插件侧修复。

- 保留真实的依赖与兼容性约束，运行时仍须符合 7.3 的宿主版本及来源要求。不通过删除必要声明、版本豁免或替换宿主代码消除提示。
- 不自动允许安装脚本，不关闭安装脚本安全检查，不擅自修改 profile 或全局包管理策略。确有运行准备必要的脚本，须说明必要性并取得宿主正常授权；其他插件独立引入的脚本与本包引入的脚本分别核对。
- 既有 profile 的冗余依赖和授权记录清理属于实例维护，不随本包安装自动执行，不删除其他插件所需的包或许可。插件侧修复必须考虑旧安装及锁文件状态，不能以无关环境清理作为完成前提。
- 验证同时覆盖新安装、已公开旧提交升级到候选，以及支持集合中的各宿主；旧版用准确提交及安装来源标识，不只比较可能相同的包版本。保留包管理结果、脚本待授权项、依赖与锁文件前后变化，确认无需为本包的冗余依赖补授权，且设置、两预设及五工具正常。缓存或既有授权使提示消失，不单独作为修复证据。

### 7.2 停用、卸载与运行中任务

- 停用或移除声明后，不向新会话继续提供被撤的预设／功能；已开始会话保留宿主允许的预设版本引用，不能把退役声明误称为立即拆除所有活动组合。
- 本包监听、计时、设置快照、工具注册和客户端贡献按各自生命周期释放。作业归发起会话，由宿主 owner／服务管理，不承诺卸载生产者行就取消已启动任务。
- 已知可预见的残留或异常优先预防和解决；受支持机制无法自动处理时，可提供有限、独立的检查／补救工具或操作指南，只处理可识别的本包问题，不擅自改写无关用户配置。
- 用户将默认预设选成本包预设后，移除该预设可能使默认创建新会话报错。设置页按 5.7.4 在相关条件成立或未知时醒目提示切换默认预设；用户参考保留停用、卸载前及卸载后的实际操作步骤。不能宣称宿主必自动回退。
- 卸载后补救不依赖已卸载插件继续运行。未知问题不设计通用清理器，也不以有限测试承诺所有 OS 级进程或用户配置零残留。
- 重启从目标服务进程树外执行，先确认不影响正在工作的其他会话；测试和部署不得随手重启在用实例。

### 7.3 当前兼容基准与统一维护

本节是本分支目标兼容范围的唯一权威。同一个插件包须支持 dsh `0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5`，统一在 `adapt/dsh-0.2.1` 维护。目标插件版本为 `0.2.9+dsh.0.2.1-rc`（核心版本 `0.2.9`）。实现、测试、安装件与说明必须使用同一完整版本，并列明这四个宿主版本。

支持集合规定本包须满足的兼容目标，不代表每个行为已经通过验收。现行机制和验证差距见[设计的当前实施与验证状态](<design.md#9-当前实施与验证状态>)；证据复用与受影响内容的重新验证按 7.3.2 执行，局部兼容证据不表示发布条件已满足。

全部九个 `@deepseek-ai/dsh*` peer 使用同一准入集合：`0.2.1-rc.2 || 0.2.1-rc.3 || 0.2.1-rc.4 || 0.2.1-rc.5`。配套依赖为 `@deepseek-ai/cordis ~4.0.5`、`@deepseek-ai/cordis-plugin-timer ~1.1.7`、`@deepseek-ai/schemastery ~3.18.5`、`zod ~4.6.7`。安装时，九项 DSH peer 必须与当前宿主的 rc 版本相同，并解析到该宿主的模块树。配套 peer 使用宿主提供的同名包。`schemastery`、`zod` 等直接依赖可使用官方安装通道生成的 profile 本地副本，但实际版本须与宿主同名包一致，并满足各自声明范围；记录实际解析来源，不要求与宿主版本号相同。不能混用不同 rc 的 DSH 包。

本包不扩大到其他 `0.2.x`、`0.2.1` 正式版或尚未列入集合的 rc。新增 rc 在同一维护分支完成兼容验证后纳入正式支持，不默认新建分支。经用户明确授权可先扩充准入集合用于验证，但须标明待验收状态，不能以临时准入代替正式支持。不得用版本豁免、`engines.dsh` 覆盖 peer 或替换宿主源码绕过检查。已有分支历史合入保留分支后可删除冗余分支名；既有标签及发布标识保持不变。

#### 7.3.1 版本显示与发布标识

版本显示须同时标识插件自身版本和宿主兼容线。包清单列出准入集合，安装说明同时标明正式支持范围和待验收版本：

| 位置 | 要求 | 本分支目标值 |
| --- | --- | --- |
| `package.json.version` | 稳定为 `<插件核心版本>+dsh.<宿主兼容线>`；alpha 为 `X.Y.Z-alpha.N+dsh.<宿主兼容线>` | `0.2.9+dsh.0.2.1-rc` |
| Git 标签 | `v<完整package.json.version>` | `v0.2.9+dsh.0.2.1-rc` |
| Release 标题 | 列出验收通过后的宿主支持集合及插件核心版本 | `dsh 0.2.1-rc.2 / rc.3 / rc.4 / rc.5 ｜ dsh-async-tools 0.2.9` |

- 插件核心版本按自身发布递增。兼容集合变化需要重新交付时，递增核心 patch，不只修改构建元数据。
- `+dsh.0.2.1-rc` 是显示兼容线的构建元数据，不是宿主版本范围，也不使插件核心成为预发布版本。机器准入由九项 peer 准入集合确定，不代表集合内各版本均已验收。
- 管理页保留完整包版本；两语安装说明列出相同的准入集合及验收状态，不能将兼容线简称写成支持所有 `0.2.1` 版本。

alpha 渠道为 `adapt/dsh-0.2.1-alpha`，稳定渠道为 `adapt/dsh-0.2.1`，宿主兼容线与插件质量等级分别表达。`-alpha.N` 才是插件预发布标识，`+dsh.<兼容线>` 为构建元数据；每个可安装 alpha 候选使用可区分版本，并固定完整提交、支持集合及安装件。上列既有候选版本是当前基线，不因本条自动变成已发布 alpha。

完成验收、用户文档与问题登记后，验收负责人按明确授权普通、非强制推送对应 alpha 分支。验收完成不要求结论通过：普通缺陷和必要验证缺口准确登记在[公开问题清单](<issues.md>)后，不自动阻断 alpha；已确认严重安全问题及待推送内容或历史中的不宜公开材料阻断 alpha。稳定晋级须满足原验收要求并按另行发布权限处理，不晋级移动中的最新分支头。alpha 权限不含稳定分支、正式标签、Release、删除分支或改写历史；远端变化或推送失败须报告，不强推覆盖。稳定版本调整或重新打包须核对最终安装件与受影响验证，实现变化不能沿用原结论。

#### 7.3.2 多版本验证与证据复用

- 每个交付件冻结支持集合；CI 对 rc.2、rc.3、rc.4、rc.5 分别显式安装精确宿主，运行同一份插件测试和检查。仅让包管理器从 OR 集合自行选中一个版本，不能证明四个版本均已覆盖。临时准入期间也须建立 rc.5 验证档，保留旧版本验证，不以新增档替代原矩阵。
- 准入集合扩充后，同步核对兼容检查器、测试、CI、依赖锁定信息和说明；集合外拒载样本不得与已列入的版本重合。验证既要证明集合内放行，也要证明集合外仍被拒载。
- 对每个宿主验证官方准入放行、九项 DSH peer 及配套 peer 来自对应宿主树；直接依赖按本节允许的安装形态核对来源与版本。同时验证实际 tgz 安装和装载、完整版本及设置与预设可见。不支持的宿主按声明拒载，包含正式版、其他版本线和未列入的新 rc。
- 运行代码、宿主消费契约及配置条件未变时，可复用既有行为、模型及页面证据，并保留原报告的覆盖边界；不因合并分支而从零重跑未受影响的昂贵测试。统一包的准入、依赖解析、安装和受影响的版本检查须重新验证。
- 宿主升级时复核工具、作业／命令、子代理状态和投递、模型策略、编排引擎、配置与客户端挂点；变化影响到的行为再验证。其他插件仍需各自核对，不把本包兼容推广为整个 profile 通过。
- 两预设核对每个受支持宿主随包的 standard 与 cordis 基线，保留适用的时间上下文、计划任务、插件管理和原有启用状态。原生入口按 3.1，公共创建参数按 2.3.1 核对。
- 真实作业编号按不透明字符串处理，不将某种编号格式作为业务规则；固定编号假件须与真实宿主返回值覆盖并存。

## 8. 验收要求

### 8.1 结果与证据原则

验收针对当前要求，不保存完成日期和勾选流水。记录实际宿主版本、插件版本／提交、方法和配置；文档改写、代码存在、旧测试数量或历史截图不代表已交付。

- 单元、宿主接线、真实模型运行和 GUI 各证明自己的范围，替身不替代真实投递、页面或进程证据。
- 未执行、跳过、环境不满足或没有核验的项目，明确为未验证，不算通过；查询／读取失败也不算对象不存在。
- 关键保护应有撤去后能发现退化的验证，断言实际触发相应路径；超时、取消、并存信号、先到消息、读取失败和边缘到期分别覆盖。
- 优先默认权限执行。确需额外权限或特定环境时，经正常审批执行无害或隔离测试；不得绕过子代理授权，也不得以测试名义破坏用户数据。
- 测试与审查由独立子代理执行；主开发会话可写和修正，但不以自己的执行结果替代独立结论。文档修改同样审查和复审。
- 验收使用隔离验证环境，不以在用开发会话的破坏性操作取证；实例升级、重启和共享设置更改需明确权限及安全检查。

### 8.3 统一等待与直接交付的验收用例（WAIT-01）

1. 零等待含多个目标及慢／挂起查询时，全程符合设计明确的统一检查上限，不随目标数倍增；取消及时返回，关系未确认不泄漏内容、不伪称不存在；不等待任务进展、未来消息、不重试或轮询。未指定目标、空目标列表、单目标及混合多目标按 2.1.4 区分检查范围和挂起条件。覆盖没有工作、仅有已终态作业、仅有静止空闲／无驻留子代理及确有运行中工作；无工作立即返回，不将预算用于等待未来消息。显式目标不能借列表外工作挂起；非法参数和目标可读拒绝，全部请求目标均校验。零等待无运行中对象仍能即时检查，不按正等待下限挂起。
2. 同时运行 A、B，等待 B 时 A 完成：指定目标等待保持到 B 的事件、用户插话、取消、预算到期或已确认不再具备挂起条件；未指定目标的等待因 A 可用内容交回。同一领取窗口中已就绪的其他作业内容按同批预算交付，不附纯读取指令。未指定目标且仅有已就绪内容时直接交付，不要求另有运行中工作。
3. 非目标消息不打断命令或工作流的首次等待。用户插话及时交回，排队消息、内部日志、目录和配置快照保持原有语义；等待结束及取消不停止后台任务。
4. 结果构造后被改写取消、完成消息未确认领取时，在恢复期限内可通过既有入口取得内容；恢复可能重复时明确标记，正常状态检查和完成消息不因副本在场反复发送。覆盖恢复到期、存储上限与生命周期清理，确认没有把缺失状态当已送达。首次等待内完成、后台完成时正在等待、正在执行其他工作及主体空闲四种情况，都直接交付结果。正常路径同一输出不因完成消息、等待返回或多个等待而重复进入模型上下文；仅送达未确认的显式恢复允许带可能重复标记提供副本。
5. 已完成作业立即返回未交付内容或已交付状态；运行中作业可零等待取得增量。覆盖成功、失败、终止、无输出、读取失败及重试，不丢最终结果，不诱导重跑任务。
6. 指定子代理的普通消息、提问、结算及可确认状态变化可唤醒，返回不复制正文。入口未处理通知有效；前次等待到期仍为运行中、间隙转为空闲且无待领取通知时，后次入口对可证实的新变化报告一次。已报告变化不重复呈现为新变化；静止对象单独被再次等待时不挂起，实际恢复运行或出现新消息／变化时正常处理。宿主消息交付保持原样，宿主自行产生的多条消息不计为本包重复投递。
7. 多作业并发、同拍完成、等待取消与交付重叠时，完成消息与工具返回按同一领取窗口共享总内容预算；条目和附加说明受设计给出的有限规则约束，每份结果的归属、结局、裁剪和恢复方式清楚，延后及未交付内容可恢复。宿主或其他工具已生成的正文保持原样，本包不再复制。同一主体多等待不放大本包正文或纯读取通知。
8. 完整命令回显开启时分别验证普通命令及工作流脚本原文在选定位置到达、同批不重复附上，长文本裁剪量准确，普通命令注册名称经任务列表进入模型的路径也不得绕过预算或同批去重；关闭时二者均不附回显，界面原始记录仍可查。两个展示开关分别核对默认、显式开启、关闭及后续调用生效。Agent 默认不接收进度日志和整条命令回放，界面信息保持可查；命令输出、最终结果和必要诊断不受误伤，中英文含义一致。
9. 本包预设中隐藏的读取工具不可调用，提示无失效指路；五个工具和必要管理入口可用，不新增历史工具。自建组合的明确接入、单独查询工具挂载及其他预设均按 3.2 隔离。
10. 以真实模型运行对照“通知后专门领取结果”和“直接交付结果”，核对不再发生纯领取用途的模型请求。记录模型请求数及可取得的输入、缓存命中、输出用量；缓存命中的输入也计入额外消费，不用缓存命中代替消除无效请求的证明。
11. 强制入口查询失败、挂起或返回部分未知状态，区分没有可等待工作、无法确认条件和实际预算到期；有其他已确认工作时可在剩余预算内等待并保留未知标记。入口检查及等待期间的有效消息、取消和预算均及时生效；检查与订阅交接时到达的结果或变化不丢失。参数和目标不合法仍拒绝，不因已有可交付内容而跳过校验。
12. 等待期间，未指定目标调用中的可等待工作全部结束，或指定目标进入终态／停止运行时，及时交回；即使完成通知未到或结果暂时读取失败，也不继续挂起等待已结束工作。真实命令、编排和子代理持续不返回时，每次等待仍有界，后台工作不因预算、取消等待、连续等待次数或长期无输出被自动终止。
13. 用真实模型复现“子代理完成当前阶段、文件冻结、等待父代理转交并行验证材料”的协作：子代理报告已完成内容及所需输入后结束回合，不调用或反复续调等待来保持在线；父代理随后通过宿主消息机制交付材料，子代理能够继续下一阶段。另以确有运行中依赖、实际延时及监控检查任务作正向对照，验证必要等待仍可进行，不通过无意义睡眠作业绕过检查；不能只用提示词关键词断言替代行为证据。

### 9.2 GB-01：Windows Git Bash 开关（暂缓）

**状态：现行宿主沙箱下受阻，暂不实施，不纳入本轮交付与验收。** Git for Windows 的 MSYS2 运行时在受限沙箱中初始化时，创建必需的信号管道遭到拒绝，Bash 无法启动。在不修改宿主、不放宽沙箱且使用用户已安装运行时的约束下，当前无法满足本节的受限执行要求。

下列已确认目标及验收条件保留；恢复实施前须重新验证受限执行的可行性。

#### 已确认决定

- 开关为布尔设置 `gitBashShell`，默认关闭；恢复实施时由需求与验收负责人按 5.7 确定界面原文。
- 保存后对后续新调用立即生效；已启动作业的后端与权限不变（见 2.2.1 和 6.1）。
- 仅影响本包 `async_run`（含子代理对它的调用）；不改变宿主其他工具的命令执行。
- `async_run` 提供可选单次参数指定本次命令行：开关处于 PowerShell 时可单次选用 Git Bash，开关处于 Git Bash 时可单次选用 PowerShell。参数名称、取值与校验由设计确定，两语描述一致；不提供该参数时按开关当前值执行。
- Git Bash 运行时使用用户已安装的 Git for Windows：插件按常见安装位置、PATH 及环境变量探测 `bash.exe`；设置提供由用户自指定安装路径的覆盖字段，探测与覆盖的字段形态由设计确定。找不到可用运行时时报错并给出安装指引，不随包分发运行时。

#### 功能与权限要求

- 在插件设置中提供开关，Windows 环境启用后，以 Git Bash 作为异步命令执行的默认命令行。实际执行命令的 `async_run` 及子代理对它的调用使用相同规则；`async_workflow` 本身仍只编排代理。
- 采用支持受限执行的方案：Git Bash 必须能在只读、工作区内读写及 `dsh-approve-for-me` 的“自动审批”权限预设下直接运行当前策略允许的命令。普通命令不能仅因 Bash 初始化失败而被迫申请完全权限。
- 保持只读和工作区边界。不得通过关闭沙箱、永久放宽会话策略、默认使用完全权限或未隔离执行来满足直接可用要求。Bash 启动的脚本及子进程同样受当前权限约束。
- 与 `dsh-approve-for-me` 兼容。危险命令和需要更宽权限的工作区外操作，在取得本次有效许可前受到拦截，并能进入宿主正常审批流程，由自动审批插件按其配置审查。命令改用 Bash、脚本、重定向或子进程后，不得因此漏过本应触发的检查。
- 审批请求提供真实工具身份、Bash 命令或脚本、实际参数、工作目录、申请权限及理由，足以让审批方判断本次操作；不能只送审无实际内容的启动包装。接管范围、拒绝规则、审查故障和人工备用流程遵守审批插件的生效配置。
- 在同一会话策略和审批配置下，Git Bash 与 dsh 原生 PowerShell 的等价操作在可审批性上保持一致：应受限的操作仍受限，应审批的操作仍可送审，批准只作用于本次操作；拒绝、取消或未取得有效许可时，不执行所申请的越权操作。开关本身不授予权限。

#### 异步行为与使用反馈

- 保留本包的首次等待、消息打断、后台存活、输出读取、完成通知及显式取消规则。每次调用绑定一致的执行后端、命令和权限；切换开关不能把已解析命令交给另一种 shell，也不改变已启动作业的后端或权限。
- 设置、工具描述、参数说明及诊断与实际后端一致，按第 5 章的语言和界面要求提供。Bash 不可用或受限执行准备失败时，说明原因与恢复方法，不静默改用另一种 shell 或未隔离执行。

#### 后续验收结果

- 在独立 Windows 实例中，分别验证只读、工作区内读写和自动审批预设：策略允许的命令能运行，受限写入和越界副作用被阻止；不能仅凭非受限模式成功判为通过。
