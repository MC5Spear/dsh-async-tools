# 需求（dsh-async-tools）

> 事实依据一律落进正文（内部事实登记簿不随公开仓走）。本文只写"现在要做什么"，不写历史与设计推导。
> 需求编号 R1–R45 与交付物编号 D1–D18 是外部引用锚——`docs/design.md` 与代码注释都在引——只增不改；其中 R16、R19、R41–R43 为空置编号，不得回收给别的需求（回收会让既有交叉引用指错对象）。
> 本文与 `docs/design.md` 的分工：本文定"要什么"（每条需求是什么、判据是什么），design 定"怎么做"（模块、接线与源码锚点）。

## 1. 目标

给 DeepSeek Harness（dsh）做一个插件包与配套 Agent 预设，**消除"长工具调用占满整个工具批次"造成的 Agent 空转**。

dsh 的现状是：一次工具调用从开始到返回结果之间，Agent **完全停止工作**——同一批次里的其他工具不能并行（`tools/execute` 是串行 waterfall），用户消息也只能等到批次结束才被领用（回合内的消息要等步骤边界）。对于需要数分钟到数小时的任务（编译、构建、测试、装依赖），这等于把 Agent 冻住。

**codex 是行为蓝本**（`exec_command` 的 `yield_time_ms` 语义：默认 10 s、有效区间 250–30000 ms）：命令超过让出预算**不被杀死**，而是转后台并返回一个会话句柄；模型之后用另一次调用取回输出。dsh 只是宿主：本插件的让出语义、句柄形状、等待与打断语义都对齐 codex，再按 dsh 的 seam 实现。

**产出的三样东西**：
1. 一个插件包 `dsh-async-tools`，提供五个工具：`async_run`、`async_wait_job`、`async_wait_agent`、`async_agent`、`async_workflow`（R34）；
2. **两个 Agent 预设**：**异步模式**（基于「标准模式」standard）与**异步创造模式**（基于创造模式 cordis，R26），都用这套异步工具承担命令执行与子代理的创建/编排/等待；宿主的同步 shell 在预设内禁用（R6/R26 既有手术），可前台锁死批次的原生委托入口亦禁用（R35）；
3. 本流程固化为一个 dsh 插件开发技能（由子代理产出，见 §8）。

插件的一切影响随插件自身的生命周期存在与消失（R17）：仓库/开发树与实例安装目录彻底分离（R37），宿主随 0.1.7 → 0.2.0 线适配（R15/R31/R38/R44），**卸载插件 = 一切影响一并消失**。

### 1.1 呈现模式决定（用户裁定，不得再改）

**定为「标准模式」的 native 呈现，明确不走 PTC。** 依据三条，缺一不可：

- **功能性硬论据（决定性）**：`run_code` **本身是一次同步工具调用**。异步流程的本质是"跨步骤协作"——`async_run` 交出句柄、模型去做别的事、之后再 `async_wait_job` 取回。若把这些异步工具放进 `run_code` 生成的 SDK 里，模型必须写一个 TypeScript 程序把它们串起来，而**那次 `run_code` 调用在程序结束前不返回**，模型**又无法继续做别的事**，恰好抵消异步的全部意义。因此这些工具**必须能被模型直接调用**。
- **事实依据**：`mode: ptc` 时模型只能直接调用 `run_code`，其余工具都是它生成的 SDK 成员（宿主 `run_code` 指令原文："run_code is the only tool you can call directly"）；标准模式不挂 `tool-presentation` 行，走 schema 默认（native），工具直接可调用。
- **用户裁定**：走 PTC 太麻烦，明确选择标准模式。

**推论（约束需求其余部分）**：
- 异步工具的 `output.schema` 描述的是**原生返回形状**，不是 SDK 成员类型；`note` 文案写给直接调用者。
- R7 的预设验证项断言"标准模式下异步工具直接可调用"（模型工具列表里能直接看到它们），**不得**去断言 `tools:sdk` 段落。
- 预设以 shipped `standard` 预设（补丁形态）为基线做手术，而不是 `ptc` 的。

## 2. 强制需求

（编号单调排列；R16、R19、R41–R43 为空置编号，不得回收。）

### R1 `async_run`：带让出预算的命令执行（不可裁剪）
- 接受 `command`、可选 `yield_ms`、可选 `workdir`、`description`。
- **让出预算内结束** → 直接返回完整输出（普通命令路径，必须保持"和同步工具一样好用"）。
- **超出让出预算** → **不得杀死进程**；立即返回 `{ status: "running", job_id }` 形状的句柄，命令在后台继续运行。
- 返回句柄时，工具结果里**必须**附带一句显式、可执行的指令，告知模型：命令仍在运行、job_id 是什么、继续做别的事、需要输出时调用 `async_wait_job`。**不得只返回一个 id 就让模型自己猜。**
- 让出预算的语义是"等待预算"，**不是"进程寿命上限"**——这是与 dsh 内置 `pwsh` 前台模式（默认 120 s、上限 600 s，到期杀整棵进程树）的根本区别。
- 同上：`async_run` 启动的作业**不套任何绝对超时**，只在显式 `job_kill` 或会话结束（owner 处置）时终止。
- 让出窗口的执行形态（执行即注册、可打断的首次等待）与后台作业呈现（label=命令）由 **R32/R33** 细化。

### R2 `async_wait_job`：有界的作业等待（不可裁剪）
- 接受 `job_id` 与**必填**的 `wait_ms`。
- 作业在预算内结束 → 返回其输出与终态。
- 预算到期 → 返回"仍在运行"的句柄；**可重复调用**，作业不受影响。
- 用户**插话**（steer，R12 的定义）时必须立即返回"被用户打断"，且**不得影响作业继续运行**（等待中断不取消作业）；
  **排队（queue）消息不得打断等待**（R12）。
- `wait_ms` 必须被夹紧到 `[MIN_WAIT_MS, MAX_WAIT_MS]`：**调用者不能省略，也不能超过上限**（对齐 dsh 既有数字体系——宿主 `waitTimeoutMs` 默认 30000、`maxWaitTimeoutMs` 默认 600000，MAX 取 600000）。

### R3 `async_wait_agent`：有界的子代理等待（不可裁剪）
- 接受 `agent_id` 与**必填**的 `wait_ms`。
- 子代理已结束（或已非运行态）→ 立即返回"已结束"。
- 预算到期 → 返回"仍在运行"；可重复调用。
- 用户**插话**（steer，R12 的定义）时必须立即返回"被用户打断"，且不得影响子代理继续运行；
  **排队（queue）消息不得打断等待**（R12）。
- **权威结束信号**是结算通知（`source.kind === "subagent-settled"`）；状态查询（`listChildren()` 的目录条目——**没有 `activity` 字段**）只作屏障与安全网。
- **打断判定必须用 `source.kind === 'user'`，不得用 `role === 'user'`**——因为结算通知与子代理转达消息的 `role` 也是 `user`（插件注入消息的 role 被宿主强制为 `user`）。这是必须写进测试的强制约束，否则等待会被自己的通知反复打断。
- 子代理转达消息（`source.kind === "agent-message"`）**不得**当作结束信号，但可以当作"有进展"的唤醒信号提前重查状态。
- 信号分类的第四类——迟到作答（本包插件事件）的**唤醒交还**——见 R30-d：提前返回"仍在运行"句柄，不报 interrupted、不误报 settled。

### R4 全局不变量（本需求的核心）
- **所有等待必须有界。** 本插件各工具中没有任何一个允许无限期等待；`async_wait_job`/`async_wait_agent` 的 `wait_ms` 是必填参数。
- **打断等待 ≠ 打断工作。** 用户插话只能让"等待"提前返回，后台作业与子代理**必须继续运行**。
- **不得引入杀死长任务的行为。** 本插件不设"命令寿命上限"。
- **不得改变其他 Agent 预设的行为。** 插件行只挂在新建预设里；标准 / PTC / 极简 / 创造四个既有预设的工具面貌**必须零变化**。
- 所有副作用必须可逆：监听器、定时器、作业注册都必须属于当前 fiber，`stop`/`update`/卸载后无残留（`ctx.effect()` / `ctx.on()` / `ctx.timer.*` 均随 fiber 处置）。

### R5 提示词与可发现性
- 各工具的 `description` 必须自解释：等待与执行类工具（`async_run` / `async_wait_job` /
  `async_wait_agent`）覆盖让出语义、句柄形状、等待有界、用户插话会打断等待但工作继续，
  以及**用 `async_wait_job` 取回后台输出**；`async_agent` 不等待，其描述与 note 的要求
  （后台派生形状、模型选择取值、实际生效路由）由 R13 承载。
- **必须补上现有提示词缺口**：dsh 内置 `pwsh` 的描述从不告诉模型 120000/600000 这两个数字（描述只写"执行器应用其配置的默认值与上限"），导致模型无从判断该不该转后台。新工具必须把生效的预算数字写进描述（或至少写清"超过 N 秒会转后台"）。
- 预设的人设/工具指引必须说明新的工作方式：**长任务先启动、继续做别的事、需要时用 `async_wait_job` 取回**。

#### R5 的措辞约束
**`async_wait_job` 是取回后台输出的既定途径**；完成通知是宿主的备用唤醒（谁完全没在等，就靠它把模型叫回来）。
两者不得互相矛盾；通知文案由宿主 `dsh-tool-jobs` 提供，本插件不改它。

这条表述的判据是实测（真机端到端实录）：`async_wait_job` 覆盖结算时通知数为 0（`jobs.wait` 使
有等待者，结算事件的 `awaited` 为真），没有覆盖时通知发出且模型仍按人设走 `async_wait_job`。
工具描述里**不得**出现"唯一途径"这类排除性措辞。

### R6 部署与回滚
- 交付形态：**一个包，两副角色**（决策记录见设计 §17.3 与一次宿主行误删事故的内部处置留档）。
  | 角色 | 平面 | 职责 | 触发方式 |
  | --- | --- | --- | --- |
  | 工具角色 | 预设 | 各工具（按 `config.toolName` 每行注册一个，是 `tool-subagent` 系工具行的同款成例）；只读设置命名空间 | 预设组合里 `name: dsh-async-tools` 的行（带 `toolName`；0.1.7 为预设补丁 insert 行） |
  | 宿主角色 | 宿主 | 注册 `async-tools` 设置命名空间、维护预设目录、提供浏览器半边；**不注册工具** | 本包自带 `cordis.patch.yml` 插的宿主行（无 `toolName`），包名进 `dsh.profile.bundles` |
  开发源仓目录 → `profiles/web/node_modules/dsh-async-tools`（唯一部署联接）。
- **可见性有两条，分属两个平面，必须分开满足**（这是本插件部署形态的核心）：
  | 可见性 | 要求 | 归属平面 |
  | --- | --- | --- |
  | **工具可见性** | 我们提供的 `dsh-async` 预设**自己**挂了工具行 ⇒ 切到它就有 `async_run`/`async_wait_job`/`async_wait_agent`/`async_agent`/`async_workflow`（第五行在 delegation 组内，R35） | **预设平面** |
  | **设置可见性** | 不必切到本预设，插件设置页里**始终**能看到并可修改本插件的设置 | **宿主平面** |
- **工具不限于本预设**：工具随**挂载它的那一行**生效，任何预设加同样的行就能得到它们
  （R34 起为五个工具），
  `dsh-async` 预设只是替使用者把这些行写好的默认模板。本插件不提供、也不打算提供
  "只在某个预设里可见"的机制；一条工具是否在某个会话里可选，取决于该会话的预设组成里有没有那一行。
- **工具行绝不进宿主平面**：宿主平面注册的工具进入全局工具层，本插件全部工具会出现在**每一个**预设里
  （实测：`standard` 会话里同时出现 `pwsh` 与这些异步工具），违反 R4。
  "别人可以自愿加"与"我们不可以强行装到所有预设"是两件事，前者是许可，后者是本条禁令。
  单包化后的对应判据：宿主行**不得带 `toolName`**（T5④），宿主角色 apply **零工具注册**（T12）。
- **设置行必须在宿主平面**：设置页的插件配置只列宿主平面的行（预设子树不在 `dsh-client-modules` 的遍历范围内）。
- **宿主行的行名必须是平名（不含 `/`）**：名字带子路径时该行被**静默跳过**——命名空间照常注册、
  服务端可读可写，但浏览器半边永远进不了注入表，**设置卡片不渲染且没有任何报错**（客户端模块只认平名包；行名带子路径时该行被静默跳过）。
  宿主行复用平名包名 `dsh-async-tools`，卡片因此能进注入表（单包两角色：宿主行无 `toolName` 即宿主半边）。
- **进 bundles 的包必须声明 `dsh.bundle`**：本包自带 `cordis.patch.yml`（只插宿主行，不插工具行）。
  进了 bundles 而无 bundle 声明会让 `dsh-app-boot` **直接启动失败**。
- **安装形态**：包名 `dsh-async-tools` 进 `dsh.profile.bundles`（或等效地由 profile 的
  `cordis.patch.yml` 插同一行），宿主行才会成为一行 Loader entry，进而（a）被
  `dsh-client-modules` 扫到、把浏览器半边发给前端，（b）使设置卡片出现。卸载步骤在 README 里写清。
- **预设里工具行的安装由 R9 承担**，不再是手工步骤。
- **`dsh-async` 预设**以「标准模式」为基座（§1.1 决定；第二个预设的基座见 R26）：对 shipped `standard` 预设（补丁形态）做手术——① 删掉 `tool-pwsh` 行（模型不再能直接调用同步 pwsh）、`tool-bash` 行无条件禁用（R20）；② 新增四行挂载 `async_run` / `async_wait_job` / `async_wait_agent` / `async_agent`，第五行 `async_workflow` 插 delegation 组内 `tool-workflow` 行后（行位以 design §35.1-1 为权威），并禁用 `tool-workflow` 与 `tool-subagent`/`-fork`（R35）；③ `tool-ralph` 行随上游禁用（`disabled: true`、config 保留，重新启用 = 删那一行）。**不挂 `tool-presentation`**（标准模式本来就没有），保持 native 呈现。
- 预设随包 patch 交付（`presets/dsh-async.patch.yml`——bundle patch 数组按序应用、可插新行），**不落用户目录、不修改 shipped 预设**。
- 预设的**出现与清理由 bundle 行的生命周期负责**（每个声明急切创建 registry 拥有的 scope 与 Loader 树；声明更新或移除让上一 revision 退役）：不需要使用者手工放置或删除目录。

### R7 验证
- **所有测试与所有审查一律由独立子代理执行**（用户裁定）。主会话可以写代码、可以读产物，但**不得充当测试者或审查者**——测试结论与审查结论都必须出自独立子代理的报告。
- **单元测试**：等待夹紧、四路竞速的优先级、打断判定只用 `source.kind` **且只认 next-step 落点（R12）**、让出分支的形状、清理无残留、设置分层取值；R13 的参数纪律（`provider`+`model` 成对、未声明键报错）与路由白名单。
- **端到端**：必须在**验证实例**上验证（验证实例由服务管理器托管、可重启可反复取证；开发实例跑着在用的交互会话），不得用开发实例的结论替代。
- 端到端至少覆盖：
  1. 短命令（< 让出预算）返回完整输出；
  2. 长命令返回句柄，`async_wait_job` 能取回最终输出；
  3. 长命令运行期间用户**插话（steer）** → 等待立即返回，作业仍 `running`；
  4. 子代理运行期间 `async_wait_agent` 能等到结算；
  5. `async_wait_agent` 等待期间用户**插话（steer）** → 立即返回，子代理不受影响；
  6. **呈现模式（§1.1 决定的验证项）**：在该预设下，模型工具列表里**直接出现** `async_run` / `async_wait_job` / `async_wait_agent` / `async_agent` / `async_workflow`（第五行组内供电，R35），且**不出现** `run_code`——这证明异步工具是原生可调用的，异步的跨步骤协作成立；
  7. 预设隔离：其他预设（标准 / PTC / 极简 / 创造）的工具列表**无变化**；
  8. **两条可见性分开验**（这是 R6 新增的核心要求，缺一不可）：
     - **工具可见性**：`dsh-async` 预设下有这些异步工具；`standard` 预设下**没有**，且 `pwsh` 仍在；
     - **设置可见性**：**不切到本预设**，在插件列表里点开本包页面即可看到并修改本插件的设置
       （表单长在插件页的描述与组件行之间；判据按 R24：页面 DOM，不用后端返回）；
  9. **R9**：一次性 DSH_HOME 上跑"装上→预设出现→卸载→预设消失"，并对 R9 列的每条异常路径各验一次（尤其"同名用户预设不被删"与"内容被改过不被删"）；
  10. **R10**：在设置 UI 里改一个参数 → 后续工具调用**实际行为**随之改变（改 `maxWaitMs` 看夹紧、改 `maxResultChars` 看截断、看描述里的数字跟着变）。
  11. **R12**：长等待期间发 **queue** 消息 → 等待**不**被打断（等满预算返回 `running`），
      本轮结束后该消息被宿主领取进新轮次（模型可见并回应）；随后另一次等待期间发
      **steer** 消息 → 立即返回 `interrupted` 且后台工作不受影响。
  12. **R13**：`async_agent` 调用立返 agent_id 且 note 报告实际生效路由；传入
      `provider` + `model` 后子代理会话 descriptor 的路由与之一致，未传时与父路由一致
      （判据细目见 R13 可验证段）。

### R8 安全边界
- `async_wait_agent` **不得**读取子代理的会话日志、内部状态或越过包边界（`ctx.subagents` 的公共查询方法与 `agent/*` 公共事件是允许的全部通道）。
- `async_wait_job` **不得**为了"看到输出"而消费掉本应留给后续读取的内容；读取语义必须与 dsh 既有 job 读取游标一致（`jobs.read()` 返回下一个流式增量、读取推进游标、终态读取幂等）。
- 后台作业数量受 dsh 既有上限约束（每 owner 并发上限默认 10）；达到上限时报错必须可读、可行动。

### R9 预设跟随插件（安装即出现、卸载即清理）

- 预设随包 patch 声明（R17 逐项要求 1）：安装即出现、
  卸载即消失，生命周期由 loader/fiber 拥有（预设由插件行声明，revision 退役、末引用释放即处置）——"影响随插件"由机制本身成立。
- 本包**不自管用户目录、不设人工补救命令**（R17 的禁止清单）；"卸载即清理"的判据是
  R18 的"卸载后无残留"端到端。
- 预设行的注册失败是可选行警告、不得拖垮启动（也不得加 `disabled` 护栏等注册表服务就绪——护栏会让行永不导入）；宿主行异常只走 stderr 审计出口
  （`docs/design.md` §10/§20.3），不升级成启动失败。
- **可观测**：装载与告警结果走结构化 stderr 日志（`[async-tools]` 前缀）。


### R10 插件设置（参数可配置，且设置真的生效）

> 设置面机制与可用性判据见 R24（`plugins.bundle.config`
> 卡片挂在本包插件页上 + volatile 字段；表单由卡片自取控制器）。本条的五项语义继续有效：
> 字段可配置、"生效"以行为差异证明、两条可见性互相独立、取值发生在调用时、优先级层叠。

- 至少这些参数可从**插件设置**里配置，不再只靠预设行里的 `config`：让出预算默认值与上下限、等待预算上下限、`async_wait_agent` 的轮询间隔、返回给模型的输出上限、后台作业 kind。
- **设置 UI 里能看到并修改**这些项；保存后**无需重启**即对后续工具调用生效。
- **设置可见性与工具可见性互相独立**（R6）：不必切到 `dsh-async` 预设，插件设置页里就该能看到本插件的设置。
- **"生效"的判据要可观察**：改设置后，工具的**实际行为**（夹紧后的等待时长、截断阈值、返回文案里的数字）随之改变——只改到"设置页显示新值"不算生效。
- 各工具 `description` 里的预算数字随设置变化。**实现约束（已核实，两条）**：
  - 工具定义在**构造时**把描述求值成字符串——传取值器没有用，它当场被调用一次；
    参数说明同样被转成 JSON Schema 并固化（`ToolDefinition` 契约）。
  - 但工具表**按引用**保存工具对象，投影给模型时**现读字段**（值是借用的）。
  - 因此刷新描述的正确做法是**就地改写**已注册工具对象的描述与参数说明。
    **不得**走"先注销再注册"：那条路有个致命窗口——注册若抛错，工具就处在
    "已注销但没重新注册"的状态，会**凭空消失**。
- **取值必须发生在调用时**：工具不得在构造时把配置抄进闭包，而应持有活取值视图（宿主的 `ToolDefinition` 契约决定了描述/参数说明只在定义时求值一次）。
  设置读取走可选路径，**不进静态 `inject`**
  （写进 `inject` 会让没有该服务的 profile 启动失败——inject 是硬依赖声明）。
- 设置取值必须过校验，且**只有一套判据**：逐字段约束放进 `Config` 本身（`.min(1)`、
  `jobKind` 非空）——这份 schema 同时就是设置页逐字段校验用的那份，于是非法值在**保存那一刻**
  就被拒并能回给使用者看。跨字段约束（下限不大于上限、默认值落在区间内）schema 表达不了，
  必须由**显式的跨字段检查**承担：下限大于上限、默认值落在区间外，都必须被拒并给出可读原因
  （实现见 `docs/design.md`；判据是 `test/two-planes.test.mjs` 的 **T7b**，
  它穷举**每一个**默认值字段的"落在区间外"与"下限大于上限"两种坏值）。
  存量坏值（手工编辑过 `settings.yaml`）会走到运行时，那条路径必须**响亮**（`warn`），
  不能像"读不到"那样静默退回——否则表现为"保存成功但行为没变"。
- **优先级必须唯一，且以 dsh 的层叠语义为准**：`schema 默认值 < 组合层（base） < user 段（插件设置页）`。设置页的值在 user 段，因此对未被用户覆盖的键，组合层的取值继续生效。
- **宿主入口是这个命名空间的唯一注册者**。预设平面**绝不允许**自己注册设置命名空间：那样注册出来的 effect 挂在**设置服务自己的 fiber** 上，不随预设行卸载而撤销，于是预设里各行连撞 `already registered`，换会话再挂同一预设也撞。预设平面只**读**（`settings.get('async-tools')`）。
- **`base` 是宿主行的组合层配置**，不是工具行的 config：工具行的 `config` 不参与设置层叠，它是"设置不可用时的回退值"。这一条必须写进 README，否则使用者会以为改工具行的配置能覆盖设置页。
- **宿主平面这一行绝不允许把自身故障升级为启动失败**：命名空间撞名、存量设置段非法等都会让注册抛错，而行不激活会让整个 dsh 启动失败。因此注册与预设维护整体套 try/catch，失败只记可读日志并降级。
- **不得新增宿主平面的工具行**：宿主入口不注册任何工具（R6 的可见性要求）。
- **浏览器半边是设置卡片出现的必要条件，且它随本包交付**：本包在 `package.json` 里声明
  `dsh.client.platform === 'web'` 与 `exports['./client']`，并提供注册到 `settings.plugin.item`
  槽位、以命名空间为键的最小卡片。只有命名空间、没有卡片时，设置页**什么都不渲染**
  （标签页取"已服务的命名空间 ∩ 已注册的卡片"的交集）。行名必须能进客户端模块图
  （平名约束——客户端模块只认平名包），否则卡片**静默不出现**（服务端一切正常、无任何报错）。

### R11 `async_run` 的单次提权（补齐与同类工具对齐的缺口）
- **要补的东西**：`async_run` 必须与内置 `pwsh` / `bash` / `fs` 走**同一套单次提权三段式**：
  先经 `ctx.approval` 问审批 → 拿到更宽模式 → 再启动进程。**顺序不能反**。
  现场、根因与"为什么审批插件无法代为覆盖"见内部留档（一次提权路径排查的处置记录，不随公开仓走）。
- **为什么这是需求而不是锦上添花**：补齐前，受限会话里任何**需要启动外部程序**的命令
  （`node` / `git` / `cmd.exe` / 第三方 CLI）都在**进程创建层**被拒，等价于
  "这个工具在受限会话里只能跑纯 PowerShell 内建命令"。
- **参数必须成对且只在有约束执行器时广告**：`sandbox_permissions`（枚举为闭集
  `ESCALATION_TARGETS`）与 `justification` 必须成对出现、`justification` 必须是非空句子；
  且**只在 `ctx.shell.sandboxMode !== undefined` 时**才广告——没有沙箱执行器时没有可提权的目标，
  广告出去等于给模型一个永远失败的杠杆。未广告的键仍然要能被挡下
  （schema 校验只查广告过的键，所以工具实现里必须再挡一次）。
- **获批的模式只作用于这一次调用**：提权泄漏到后续调用等于永久加宽，比不提权更糟。
- **失败必须响且不许静默降级**：非严格加宽、缺审批服务、调用无 agent、用户拒绝、审批被取消——
  五种情形各自抛出**可读且互相区分**的错误，且**一个进程都不许启动**。
- **模型必须拿到可自纠的线索**：沙箱拒绝时，结果里要有**拒绝标记**
  （`[sandbox: file access denied under <mode> mode]`）与**同轮提权提示**
  （`[sandbox: escalation available — retry this exact command once with sandbox_permissions …]`）。
  这是原故障最直接的危害——模型看不到任何线索，只能换着法子瞎试。
  提示只在组合**确实广告了**提权字段时给出。
- **模型必须分得清成功与失败**：完成分支要在**模型可见文本**里给出
  `[exit code: N]`（非零时）或 `[killed by signal: X]`（信号杀死时），
  干净退出**不产生标记**——与内置 `pwsh` / `bash` 同一口径。
  结构化 `value` 里有 `exit_code`，但 `output.render` 只发 `output`，而模型只看得见
  `render` 的输出——不补标记，模型拿到一段文本无从判断成败。判据见
  `test/render-markers.test.mjs`。
- **已知缺口（如实登记，不在本包修）**：宿主的沙箱拒绝判定靠**英文子串表**
  （`dsh-sandbox-local` 的 `DENIAL_SIGNATURES["windows-acl"]` =
  `"access is denied"` / `"access to the path"` / `"permission denied"`）。
  若 Windows 把拒绝消息本地化，`proc.sandbox.denied` 会是 `false`、标记与提示都不产出。
  **内置 `pwsh` 同等受影响**（同样只看 `result.sandbox?.denied`），所以本包
  **不自造一套本地化判定**：那会造成"只有 `async_run` 认得出、`pwsh` 认不出"的不对称，
  等于掩盖平台缺口而不是修它。
  **真机探针 `verify/probe-sandbox-marker.mjs` 照实判定**：只有**在模型可见文本里真的
  看到那两行标记**才算成立；落在这条缺口里时记 FAIL 并写明"这一次没能证明标记会出现"。
  「已知缺口」是**归因**，不是**豁免**——不许让"没验到"长得像"验过"。
- **让出后的作业结局同样要带标记**：模型是通过 `async_wait_job` 读到那个 `detail` 的，
  只在完成分支给标记，"让出之后才发现被拒"这一整类现场就仍然没有线索。
- **可验证**：上面每一条都要有能失败的用例（见 `test/escalation.test.mjs`，条数现读现数，
  本文不写数字），外加一条**真机**判据——两个键是否真的出现在模型收到的工具表里，
  这是**组合事实**，任何替身都证明不了（`verify/probe-escalation-advertised.mjs`）。
- **依赖（已核实）**：提权辅助函数在 `@deepseek-ai/dsh-sandbox`
  （`ESCALATION_TARGETS` / `approveEscalation` / `validateEscalationArgs` /
  `sandboxDenialMarker` / `escalationHintMarker`），本包需要能解析到它——
  已加进 `dependencies` 并接了 `node_modules` 联接（成例：`dsh-tools`）。
  `approval` 是**可选服务**（`ctx.get('approval')`，**不进** `inject`）——与内置 `pwsh` 同口径，
  写进 `inject` 会让没装审批服务的部署整行不激活，把提权这个附加能力升级成插件不可用。

### R12 打断信号只认"插话"（steer）；排队（queue）消息不打断（不可裁剪，用户裁定）
- **定义**：**插话（steer）**指经宿主 steer 通道送达、落 `agent.inbox` 的 `next-step` 列表、
  会在**步骤边界**被领取的消息——它会与本工具结果**同批**进入模型的下一条输入。
  **排队（queue）**指落 `next-turn` 列表、只在**轮次边界**（本轮彻底结束后的下一轮）被领取的消息。
- `async_wait_job` / `async_wait_agent` 的"用户插话打断等待"**只对插话（steer）生效**；
  **排队消息不得打断等待**。
- **依据**：`agent/inbox/inserted` 事件对两种落点都会触发且 payload 不带目标列表，
  只判 `source.kind === 'user'` 的旧实现把排队消息也当成了插话——而排队消息本轮内**到不了模型手里**，
  打断只会产生"看得见通知、看不见内容"的悬空回合，工具文案还引导模型再进一次长等待。
  排队消息不需要打断：本轮结束后宿主会把 `next-turn` 领取进下一轮（活体已证）。
- **实现约束**：判定必须按 `message.id` 回查 `agent.inbox.nextStep`（事件本身分不出落点）；
  inbox 不可读时按"不是插话"处理——**宁可不少等（等待仍有界），不可错打断**。

### R13 `async_agent`：永远后台的子代理派生（立返 agent_id，可指定模型；不可裁剪）
- **定义**：第四个工具（`config.toolName: async_agent`，预设第四行）。它把"委托一个子代理"
  的**派生半边**包成结构保证：参数为 `description`（行标签）、`prompt`（完整任务书）与
  可选的 `provider` + `model`（**成对**传入，指定子代理的模型路由），**没有
  `run_in_background` 参数**——后台不是模型的选择，是工具的形状。执行只做一件事：
  `ctx.subagents.startContinuable(...)`（宿主公共契约）拿到 `childId` 后**立即**返回
  `{ status: "started", agent_id, note }`，note 指路 `async_wait_agent`（有界等待）、
  "最终回答会作为独立消息出现在对话里"，并**写明子代理实际生效的路由**
  （传入时回显所选，未传时报告继承的父路由）。
- **为什么是需求**：前台委托独占整个工具批次（同 R1 的批次串行根因），一次 `run_in_background: false`
  的委托能把同批的其他工具全部拖住——这正是本插件要消灭的空转形态。R5 的提示词约束
  （"尽量后台"）管不住显式传 `false` 的手；把参数从 schema 里拿掉才是硬规则（R14 的机制半边）。
  模型选择同理要进参数面与机制：`defineTool` 的参数根对象是开放对象，未声明的键被静默
  丢弃（参数根对象编译为隐式开放对象——未声明的键既不被校验拒绝、也不被实现读取）——模型传 `provider`/`model` 而 schema 不认时，调用照常成功、路由不变，
  调用方无从察觉。把这两个键纳进参数面、经 `agentOptions` 通道真正生效（spawn provider 声明 `agentOptions` 能力，request 带 `agentOptions` 即覆盖子代理路由），
  是消灭"传参不生效且无提示"的唯一途径。
- **实现约束**：
  - 无 `exec.agent` 时抛**可读**错误且**不派生**（与 R11 的 agent-less 同款纪律）；
  - 子代理后端（spawn 等）由插件设置 `subagentProvider` 决定（默认 `'spawn'`，进 R10 的设置面）；
    provider 未注册、或该 provider 不支持 continuable（无 `prepareContinuable` 预检）时
    抛**互相可区分**的可读错误；
  - request 形状按宿主契约：request 本体是 `{ label, prompt: [{type:'text',text}],
    parent: exec.agent }`；传入 `provider` + `model` 时**追加 `agentOptions` 键**承载
    所选路由（spawn provider 声明 `agentOptions` 能力，request 带 `agentOptions` 即覆盖子代理路由，白名单外显式拒绝）。`signal: exec.signal` 是 **`startContinuable({provider, label,
    request, signal})` 调用层**的键，不在 request 内。`persona`/`toolFilter`/`maxDepth` 仍**不透传**
    ——全功能入口仍是宿主的 `subagent` 工具，本工具是硬规则的载体不是替代品；
  - **参数纪律**：模型路由的 `provider` 与 `model` 必须成对，只传其一抛可读错误；`reasoning_effort`
    不暴露（换路由后用所选模型的默认档）；**未声明的键一律显式报错**（错误列出本工具
    支持的全部键），不得静默忽略——开放 schema 会吞掉多余键（参数根对象编译为隐式开放对象），这条是它的对冲；
  - 路由必须过会话的模型选择白名单（model-selection-policy）：越界的 `provider`/`model`
    抛可读错误且**不派生**（对齐宿主 `subagent` 的口径——越界路由被白名单校验显式拒绝）；
  - **不注册任何定时器、监听器、作业**——不等待就没有打断问题（R12 不适用于本工具），
    `note` 里的等待交给 `async_wait_agent`；
  - 只允许 `ctx.subagents` 的公共面（`startContinuable`/`getProvider`）与已 `inject` 的服务
    （R8 第一条同款守卫式判据）。
- **可验证**：单测（假 `subagents`：`startContinuable` 恰被调一次；request 形状逐字段——
  不传模型键时**无** `agentOptions`、传入时**有**且值正确；只传其一 → 红；未声明键 → 红；
  白名单外 → 红且不派生；**零**前台 `start` 调用；错误态互相区分；输出 schema 与 note
  含生效路由）；变异（把 `startContinuable` 换成前台 `start` → 必红；删掉未声明键的显式
  报错 → 多余键用例必红）；真机（`async_agent` 调用立返 agent_id 且 note 报告路由；
  传入 `provider:"zai", model:"glm-5.3"` 后子代理会话 descriptor 的 `agentProvider`/
  `agentModel` 与之一致，不传时与父路由一致——立返、可等、路由真实三者缺一不可）。

### R14 预设 persona 硬规则：子代理一律后台、结果用 async_wait_agent 取（不可裁剪）
- **定义**：`dsh-async` 预设的 persona prefix 追加硬规则条款：
  1. **委托子代理一律后台**——`async_agent`（它只有后台）或 `subagent`/`subagent_fork`
     带 `run_in_background: true`（预设里这两个工具行声明 `backgroundMode: continuable`，不传即后台；硬规则禁的是
     显式传 `false`）；
  2. **需要结果时用 `async_wait_agent` 有界等待**（`wait_ms` 显式传入），不许空转轮询、
     不许为"看看好了没"重派一个子代理。
- **为什么写在 persona**：预设平面能告诉模型"怎么用工具"的地方只有 persona 行
  （设计 §9 的既有论断）；机制半边由 R13 承担，行为半边（管住裸 `subagent`/`subagent_fork`）
  只能靠提示词硬规则。
- **可验证**：`tools/validate-preset.mjs` 校验模板 persona 含两条规则的关键句
  （可失败：删规则句 → 红）；真机判据——预设会话的 system prompt 转录含规则关键句，

### R17 影响随插件（不可裁剪）

- **插件的每一项影响都必须随插件存在而存在、随插件卸载而消失**，且**不得要求修改
  dsh 本体的配置**（profile 的 `dsh.profile.bundles` 里加包名属于"安装"，不属于本条禁止的
  "改本体配置"；改写 `settings.yaml` 的 **dsh 自有节**属于本条禁止）。
- 逐项要求：
  1. **预设**：0.1.7 起预设是**插件行**（一行 `@deepseek-ai/dsh-agent-preset` 声明，
     `Config = { id, name?, description?, order?, plugins: [] }`；注册表**不扫目录、也不接受
     预设路径**），所以预设的定义随包交付、由 loader 拥有其生命周期
     （每个声明急切创建 registry 拥有的 scope 与内存 Loader 树；更新或移除声明让上一个
     revision 退役，最后一个引用释放时处置整棵退役树），**不再由插件在用户目录里造文件**。
     "卸载 = 影响消失"必须成立，且不得依赖任何人工
     补救命令。交付形态：`package.json` 的 `dsh.bundle.patch` 为**数组**（第一项
     `cordis.patch.yml`，第二项预设补丁，后者 insert 一行 `@deepseek-ai/dsh-agent-preset`；
     数组按序应用、补丁后层胜出、整值替换、可插新行）。它只让 `dsh-async` 出现在预设
     列表里，**不抢默认**——注册表行的 `default` 属 web bundle，使用者的选择存在该行的
     volatile `selectedDefault`，使用者在 Web 编辑器里保存的改动会按 id 覆盖 preset 行的
     `config.plugins`。
  2. **默认预设**：**不得**由插件把默认预设定成本插件提供的预设。卸载后必须仍然是一个
     **存在且可用**的预设。插件**不做任何**让默认预设指向自己的事：不写 `settings.yaml`
     的 `agent-presets` 节，不改写 `agent-preset-registry` 行的 `default` /
     `selectedDefault`。默认预设是使用者自己的事——升级后旧 `settings.yaml` 的该节不被
     导入、默认回到部署声明值，这是 dsh 自身的迁移行为，**本插件既不改写也不补偿**。
  3. 工具注册、监听器、定时器、作业注册、浏览器半边（客户端模块注入行）**全部**属于当轮
     fiber，`stop` / `update` / 卸载后无残留（这是 R4 末条的强化与可验证化）。
- **禁止清单**（每条都要有能失败的反向判据）：
  - 不得写 `settings.yaml` 的 `agent-presets` 节；
  - 不得改写宿主 `agent-preset-registry` 行的 `config`（其 `default` 与 volatile 的 `selectedDefault`）；
  - 不得把工具行放进宿主平面（R4：会进全局工具层，强行塞给所有预设；宿主行的
    `toolName` 正是那个泄漏开关）；
  - 不得在卸载后留下 `%DSH_HOME%\.agent-presets\<本插件 id>\`、`.dsh-*-owner.json` 或等价残骸；
  - 本插件声明的预设行**不得**是"抛出即拖垮启动"的形态（预设行的注册失败沿 fiber 抛出，
    非必需行的失败在启动审计里只是警告、进程照常起；但**不得**给预设行加
    `disabled: !!js !ctx.get('agentPresets')` 之类的护栏——护栏会在服务就绪前求值为真、
    行被静默跳过 init、永不导入）。
- **风险边界（必须写进文档）**：在 0.1.7 上，**升级 dsh 本身会破坏同 profile 的其他第三方插件**——
  已核实 `dsh-subagent-router` 依赖的注册 API 在 0.1.7 已删除（0.1.7 的 `ctx.settings` 对外面
  改成了 `SettingsForms`，旧注册 API 不在其上），
  而它的 peer 范围在 semver 上"兼容"，所以**不会被 peer 校验拦下，只会坏**。
  这不属于本插件的缺陷，但属于 0.1.7 升级的验收范围：升级后必须逐个量同 profile 其他插件的状态。

### R21 设置页的可读性：毫秒字段显示换算后的秒数（不可裁剪）

- 设置页里本插件的**毫秒字段**必须同时给出**两条**秒数读数，使用者不必自己做除法：
  1. **生效读数**——当前生效值（用户覆盖 ?? 组合层 ?? 默认）相当于多少秒；
  2. **输入读数**——输入框里**此刻**的文本相当于多少秒，**在保存之前就实时跟随每一次键入**
     （不得等保存、也不得只在失焦后刷新）。
- **秒数格式**（用户裁定：值只写秒文本，毫秒原值输入框里本来就有）：整数秒不带小数、
  非整数保留两位（`20000 → 20 s`、`1500 → 1.5 s`、`250 → 0.25 s`）；**亚 10 毫秒的正数显示
  `< 0.01 s`**（不得显示 `0 s`——正数不能读成零）；不可换算（空文本、非有限值与非正数（`0`、
  负数））用 `—` 占位——不给会误导人的数字。
- **两段的形状与来源**（用户裁定：样式照兄弟仓 [approve-for-me](https://github.com/MC5Spear/dsh-approve-for-me) 的做法）：两段长在字段说明行里、
  与字段说明**换行**（行首不带点），段形如 `生效：{v}` 与 `输入：{v}`；输入段的数值是**解析后的
  换算值**（不是原始键入文本）；两段文案全部取本包词典（R25 的两语言键集相等约束照旧，不得硬编码
  中文）。
- 这一项**不改变**接口与配置的毫秒口径：参数仍叫 `yield_ms` / `wait_ms`，值与数值范围仍是
  毫秒；改的只是**呈现**。
- **两条实现路线，设计期择一并写明依据**：
  1. 给数字字段挂 schemastery 的单位角色 `.role('ms')`，由设置面按毫秒渲染——成例
     `cordis-plugin-hmr/lib/index.js:447`（`z.natural().role("ms").default(100)`）；
  2. 在插件自己的设置卡片里就地显示"= N s"的读法（卡片本体已在 `client.js`）。
- **承载位置**：读数落在字段的哪个位置，以 R27 的字段形态为准（= 字段说明行）。
- **验收判据**：
  1. 改一个预算字段并保存后，生效读数随之变化且与生效值一致（读数取自生效配置，不得写死）；
  2. **未保存时**在输入框里键入另一个数字，输入读数**当场**跟着变——可失败：把读数接到
     生效值而不接当前草稿，这条判据必须变红；逐位键入的中间态同样算数（键入 `4` 时输入段必须
     给出 `< 0.01 s`，不得出现 `0 s`）；
  3. 输入框清空或用非数字文本时不给误导性读数：空 = `—` 占位（清除覆盖的意图，不是非法）；非法
     与非正数 = `—` 占位加非法标记（与字段级校验的原因并存，不重复报错、也不留一个看似有效的
     秒数）。

- **（不可裁剪）客户端半边必须真的到达浏览器**：验收判据是**注入表内容或页面 DOM**，不是

### R25 中英文双开关：展示文案与 Agent 提示文案各自独立切换（不可裁剪）

本包的两类文案来源不同：**展示面**（设置表单的字段标签、字段
说明、覆盖态徽标与按钮、状态文案）由宿主的 locale 服务按**宿主全局语言**选（`client.js` 的 `DICTIONARIES`
经 `ctx.locale.register` 注册，`locale.setLocale` 是唯一写入入口——宿主语言是全局偏好）；**Agent 面**（四个工具的描述、参数
描述、`note` 与状态文案）**默认英文**（R22 的口径，
`tools/check-model-text.mjs` 以"零 CJK"钉住）。本条要求两块**各自**可切中/英，且互不牵连。

- **（不可裁剪）两个开关，互不牵连**：`uiLang`（`"auto" | "zh" | "en"`，默认 `"auto"`）与
  `agentLang`（`"en" | "zh"`，默认 `"en"`）是宿主行 Config 上两个**独立**的 volatile 字段
  （`.volatile()`，否则设置表单里既不显示也写不进）。判据必须是**行为差异**：
  只改 `uiLang` 时，从真实 `request/header` 读回的工具描述**逐字不变**；只改 `agentLang` 时，
  设置表单的可见文案**逐字不变**。
- **（不可裁剪）展示面（`uiLang`）**：`"auto"` 跟随宿主 locale（现行行为）；`"zh"` / `"en"` 由
  **本包自己**选词典渲染，不受宿主语言影响。宿主语言是**全局**偏好（`locale.setLocale` 是唯一
  写入入口）——本包**不得**调它来切自己的文案，那等于改整个应用的语言。
- **（不可裁剪）Agent 面（`agentLang`）**：两套完整文案；四个工具的描述、参数描述、`note` 与
  状态文案全部随开关走，**改设置后无需重启即生效**（复用 R5/R10 的就地刷新链：volatile 提交 →
  宿主行重物化 → refresh-bus 就地改写描述）。
- **R22 口径**：模型面文案口径是"**英文是默认档**；`agentLang:"zh"` 时
  中文档同样完整、无中英混排残留"。`tools/check-model-text.mjs` 的判据是四层：英文档零
  CJK；中文档**每个键都有中文**（缺译即红）；两档**键集一致**（少一个键就是少一句提示）；
  兜底层（硬编码文案必须进表 + 运行时两档取数比对）。
- **（不可裁剪）插件页标题与描述**：随包提供 `locale/zh.json` 与 `locale/en.json`（宿主的
  `readPluginMeta` 按**宿主语言**选）——它属展示面，但**不进**本包的独立开关：宿主没有
  "按插件覆盖语言"的能力。
- **字段集合的变化**：可编辑字段从 10 个变 12 个（新增两个语言字段）。`lib/config.js` 的
  `BUDGET_FIELDS` 仍是预算字段表（10 个），语言字段单列一组；界面判据用的键集是
  **两者之和**（`client.js` 的 `FIELDS` 与之一一对应）。本条的"逐项等价"、真机 DOM 判据的
  期望集合、T17 的默认值期望表都随这条同步（漏同步就是判据假绿）。
- **（不可裁剪）判据**：① 两块各有一条**行为差异**判据（见上）；② 真机 DOM：`uiLang` 切成
  另一种语言后设置表单可见文案整体换语言、而字段身份（官方控件的输入件 `id`，
  R27）**不变**；③ 真机
  `request/header`：`agentLang` 切换后工具描述换语言，且预算数字仍随设置变（R5 的链不断）；
  ④ 两条开关各自的默认值在出厂态下就是 `"auto"` / `"en"`（改错默认值只会静默改变所有人的
  界面语言与模型所见文案，R17/T17 同型）。

### R26 第二个 Agent 预设：异步创造模式（创造侧工具 ＋ 子代理有界可等；不可裁剪）
- **定义**：在现有 `dsh-async`（显示名「异步模式」，基于标准模式）之外，再交付一个 Agent 预设——
  显示名 **异步创造模式**，`config.id` 建议 `dsh-async-create`（最终 id 由设计定）。它的**行基线是
  shipped 的创造模式（`cordis`）预设补丁**（0.1.7 树内四份 shipped 预设补丁之一），不是 standard：创造侧的行（`tool-cordis`、
  `tool-workflow`、`tool-ralph`、`tool-subagent`/`-fork`/`-control`/`-list-agents`/`-codex`/
  `-claude-code`、`workflow-*`、`tool-web`、`tool-ask-user`、`tool-todo`、`plan-mode`、
  compaction 系、`tool-result-pruner`、skill 系、`present`、persona、agent-instructions）
  **逐项在场**（行基线含 0.1.7 补丁的全部顶层行，还包括 `tool-fs`、`tool-fs-search`、`tool-jobs`、
  `command-goal`、`tool-goal`、`tool-plugin-manager`；括号里列的是创造侧必查清单，基线其余行同样
  不得静默缺失），再按异步模式的既有手术接入本插件的工具行（`async_run` / `async_wait_job` /
  `async_wait_agent` / `async_agent` / `async_workflow`（第五行组内行，R35），按 `toolName` 分派（tool-subagent 系同款成例））。交付形态沿用既定形态：
  `dsh.bundle.patch` 数组再加一项，预设由插件行声明（注册表不扫目录、不接受预设路径），生命周期由 loader 拥有（revision 退役、末引用释放即处置）。
- **为什么是需求**：创造模式是做插件与预设创作时用的模式，但它**不含本插件的任何异步工具**（0.1.7 树的创造模式补丁亲读：只有宿主的 `tool-subagent`/`-fork` 两个派生入口）——
  派生入口只有宿主的 `subagent` / `subagent_fork`（`tool-workflow` 行同样会起子代理，但同样没有
  有界等待通道；`tool-ralph` 在 0.1.7 基线里禁用），而后台是这两个工具行的默认（`backgroundMode: continuable`、不传即后台），
  派生结果只能等它作为独立消息出现；用户的原始诉求即「在创造工作里派了子代理却等不回来」。
  异步模式解决了等待（R2/R3/R13/R14），却没有创造侧工具。**两者必须合流**：新模式要同时满足
  「创造侧工具齐备」与「子代理有界可等」。
- **实现约束**：
  - **派生入口唯一**：不得让模型同时面对两个语义相同、等待方式不同的派生工具（宿主的 `subagent`
    与 `async_agent`）而无判据。保留哪一个由设计裁定并写进设计，但**只能有一个派生入口**，
    且结果取回通道与它配套（`async_wait_agent` 有界等待，或该入口自带前台模式）；若保留
    `subagent`/`subagent_fork`，须按 R14 同款 persona 硬规则约束为后台并用 `async_wait_agent` 取结果。
  - **不做同步 shell**：沿用 R1/R6 的口径——`tool-bash` 无条件 `disabled: true`（两份异步预设补丁同款）、不挂
    `tool-pwsh`；命令执行只有 `async_run` 一条路。
  - **persona 规则**：按 R14 写入（一律后台派生；需要结果时用 `async_wait_agent` 有界等待；不许
    空转轮询），关键句由 `tools/validate-preset.mjs` 锚住；**创作指导不写回 persona**——0.1.7
    基线把它交给 skill 系行（`skill-filesystem` / `tool-skill`），这两行必须在场；若设计要把
    指导写回 persona，属对基线的显式增补，须在设计里定稿。
  - **不写用户目录**：预设只经插件行声明（R17 逐项要求 1 同款），
    `${DSH_HOME}/.agent-presets/` 不是交付面；卸载本包即预设消失。
  - **只能在新会话选**：已开始的会话不能换预设（宿主的预设切换入口对已跑过回合的会话强制拒绝），验收必须用新会话——本条的实机证据因此
    至少含一条「新会话选异步创造模式」的记录。
- **可验证**：
  - `tools/validate-preset.mjs` **按预设参数化**（现有实现写死 `row.id='preset-dsh-async'`、
    `config.id='dsh-async'` 与默认补丁路径，须改成「期望行 id／config.id／基线行集合随被测补丁切换」
    的两套期望：`dsh-async` 与第二份补丁）。第二份补丁的断言：①顶层行与 0.1.7 创造模式补丁（shipped，亲读基线）
    逐项比对，缺一即红，**含 `tool-plugin-manager`**（其 `disabled` 在与 `dsh-async` 补丁一致的
    手术下取布尔 `true`）；②五行 async 工具在位（含 `async_workflow`，第五行钉在 delegation 组内）；③persona 锚句在位；④**活 `tool-subagent` 行与
    `async_agent` 行同时在场时，persona 必须写明唯一派生入口与取回通道**，否则红。
  - 新会话（验证实例）工具目录逐项核对：五个 async 工具（含 `async_workflow`）＋ 创造侧启用行工具在位；禁用行（`tool-workflow`、`tool-subagent` 系）的工具不在目录（R35）；
  - **等待可复现**：一次真实子代理派生 → `async_wait_agent` 有界返回其结果；用户插话时立即返回
    且子代理继续跑（R3/R12 口径）；
  - 卸载后花名册回到没有本预设的状态。

### R27 插件页设置卡片的形态对齐官方设置表单（不可裁剪，用户裁定）

- **定义**：本包在插件页设置区（`plugins.bundle.config`，落点由 R24 锁定，
  不变）渲染的表单与字段控件**改用官方的共享设置控件**：`@deepseek-ai/dsh-client-ui-primitives` 的
  `SettingsForm`（框架）、`SettingsValueField`（值字段）、`SettingsFormModel` +
  `settingsNumberField` / `settingsTextField`（官方导出的设置表单框架、控件与暂存-保存模型）。形态、覆盖态、字段级校验、
  动作与失败呈现一律以官方控件为准——本包不再自绘等价物。12 个可编辑字段逐项在场（R24 的逐项等价
  不变）：8 个数字字段（7 个毫秒预算 + `maxResultChars`）走 `settingsNumberField`，2 个文本字段
  （`jobKind` / `subagentProvider`）走 `settingsTextField`，2 个枚举字段（`uiLang` / `agentLang`）
  官方没有对应控件（枚举字段官方也无 spec 工厂，只有自绘 select 的官方成例），按官方字段壳与输入件度量复刻——字段语义（暂存/覆盖态/校验）仍走官方模型，
  自绘的只有控件本体，**这是本条允许的两项形态偏离之一**（另一项是第 4 条的秒数读数），须在设计里逐项
  写明。
- **为什么是需求**：设置卡片是本包唯一的用户可见面（R10 / R21 / R24 / R25 都落在它上面），而它是一份
  手写复制品：字段标签与输入框并排、秒数读数并列在输入框右侧、没有覆盖态（无「已覆盖」徽标与
  「恢复默认」）、没有字段级说明与校验（说明只有表单底部一条全局文字，非法文本直接发给宿主）、
  动作是两个同款描边按钮（「放弃修改」/「保存」）。官方设置页自己是**同一套共享控件**的产物
  （四个宿主平面配置页都用它——它们全部经官方导出的控件渲染），两边不一致因此不是取舍差异，而是同一界面上的两种风格。
- **逐项要求**：
  1. **控件同源**：表单框架与值字段必须来自官方共享控件，不得复制其源码、不得自绘等价物；引用方式为
     客户端半边 `require("@deepseek-ai/dsh-client-ui-primitives")`（该模块在冻结平台模块表里，
     官方导出面没有枚举下拉控件），不得为它申报 `dsh.client.external` 之类的额外请求面。
  2. **字段形态**：字段 = label 行（label 在左，覆盖态徽标在右）→ 整行输入件 → 字段说明行（12px、
     `label-tertiary`）在控件下方；相邻字段之间有 0.5px 分隔线；输入件度量照官方（34px 高 / 13px
     字号 / 8px 圆角 / `bg-layer-3` / 0.5px `border-l4`；focus 用 `brand-primary`；禁用色
     `label-tertiary`）。"标签与输入框并排（flex 1:2）"与"全局底部一条提示"取消。
  3. **覆盖态**：字段在用户层里有键（presence，不是值比较）时显示官方 `Tag`「已覆盖」与「恢复默认」
     文案按钮；点「恢复默认」只**暂存**清除，保存才写（清覆盖 = `unset` op），未保存前宿主文档不得
     变化。字段显示**生效值**（用户层 ?? 组合层 ?? 默认），不是空串 + 占位文案。
  4. **秒数读数（R21 的承载与实时性）**：毫秒字段的**两条**读数——生效值与**当前输入值**——都改由字段
     说明行承载；输入读数必须**在保存之前实时跟随每一次键入**（R21 验收判据 2），生效读数仍取生效配置、
     不得写死；不得再为读数在输入件右侧自绘装饰。输入框清空或填入非数字文本时不给误导性读数（R21
     验收判据 3）。
  5. **动作**：只有一个「保存」主按钮（填充色 `label-primary`、字色 `bg-layer-3`、padding 5px 14px、
     禁用 `opacity .4`），无改动 / 有非法草稿 / 保存中时禁用，保存中显示「保存中…」；取消「放弃修改」
     按钮与「已保存」成功文案——丢弃 = 离开页面（卡片卸载）时清空草稿，成功不弹文案。
  6. **字段级校验**：数字字段的非法草稿（`Number()` 解析不出有限值的文本，如字母）必须**阻止保存**、
     输入件边框转错误色、字段下给出原因；不得把非法文本发给宿主。超出台数约束的值（小数、越界）由
     宿主裁决——保存失败时保留草稿并给出失败文案，不得静默接受。文本字段沿用官方"空草稿 = 清除"语义。
  7. **只写用户改过的字段**：保存只提交被暂存的字段，空暂存不得发写入；清覆盖发 `unset`、写值发
     `set`。"整表发 op 会清掉别人写入"的危险不得回退。
  8. **失败判定与呈现**：以宿主 `mutate` 的布尔应答判成败（保存一次原子 `mutate(ops, revision)`、布尔为假即失败并保留草稿）；保存失败保留草稿并在页脚显示官方
     失败文案；失败时不得显示成功，也不得清空用户输入。
  9. **只读与不可用**：部署只读时在控件上方显示官方只读提示；命名空间未被服务时不注册卡片
     （`whileServed` 守卫不变）。
  10. **主题变量**：本包自有样式只允许引用 0.1.7 确实存在的别名变量，判据是
      `tools/check-alias-tokens.mjs` 的 token 扫描对照 theme 包定义表（设计令牌只认主题包定义表里的名字）。
  11. **无障碍随官方控件**：label 的 `for` 与输入件 `id` 绑定、说明与错误经 `aria-describedby` 关联、
      非法态带 `aria-invalid`——由官方控件承担，本包不得留下自绘的"label 包裹 input"结构。

### R28 静默失败三防线：结果侧自诊断、描述侧警示、常驻执行纪律段（统一开关；不可裁剪，用户裁定）

- **问题**：受限沙箱里外部 EXE 被捕获形态（`2>&1` / 变量捕获 / `>` 重定向）包装后死在进程创建层——
  零输出、零 `[exit code]` 标记、`$LASTEXITCODE` 为空、`$?` 为 True（受限沙箱下捕获形命令可能整条没跑）。模型拿到空输出无从
  分辨"没跑"与"跑完没输出"，只能换着写法瞎试。R11 的拒绝标记只覆盖**看得见的拒绝**（有报错文本
  或 `proc.sandbox.denied`）；这一类是**看不见的死亡**，现有防线全部落空。
- **定义**：加三道防线，**全部由同一个 volatile 布尔开关控制**（设置卡新增 1 个布尔字段，**默认关**
  （用户裁定），保存后无需重启即生效——复用 R10/R21 的既有生效机制；字段命名与取值数据链
  由设计定，设置卡字段集合
  12 → 13，R27 的 12 项清单不变；官方共享控件若无布尔控件，与 R27 枚举字段同款处置——官方字段壳
  自绘输入件、逐项写明偏离）：
  - **a 结果侧自诊断**（`async_run`）：按两条签名在结算文本追加注记，出口与 R11 的标记同位
    （完成分支的 notes 与 `async_wait_job` 终态 `detail`）；
  - **b 描述侧警示段**（`async_run` 文案）：捕获形态警示一段；
  - **c 常驻执行纪律段**（宿主面 systemPrompt 全局段）：≤25 行的本机执行纪律，覆盖**全部预设**
    的会话，不限于本包两个预设。
- **为什么统一开关（用户裁定）**：根因在平台侧（受限沙箱的进程创建层、本机火绒），
  未来 dsh 更新可能修复；届时三道防线一起退化为噪音。开关**默认关**（用户裁定）：
  三防线是本部署的补丁行为，由用户显式打开；打开后仍可**一键全关**——关掉后 b 段消失、
  a 不再产出注记、c 段不再注入——三处都以**行为差异**验收，不得用"源码里还有这段代码"充数。
- **a 签名 1（静默捕获形，条件式）**：四条同时满足才产出：
  1. 命令文本含捕获形态启发式：`2>&1`、`$(...)`、变量赋值捕获、`>` / `>>` 重定向；**不含管道
     `|`**——管道形是可见拒绝（归签名 2），且 cmdlet 管道会大量误触发；多语句命令命中任一即算；
  2. 结算输出为空（模型可见文本无输出正文，空白算不算空由设计钉死并配用例）；
  3. 该次执行确以受限模式跑过（与现有 `sandboxMarkers` 的盖章事实同源），且本次**未走提权**——
     提权重试是本签名给出的出路，提权跑完再提醒等于噪音；
  4. 本组合存在约束执行器（判定与 `sandbox_permissions` 的广告同源；无沙箱执行器的部署不产出）。
  文案为**条件式**（"若你预期的输出缺失，可能是……"），不断言失败；必须同时给出**正向替代**：
  去掉捕获裸调用重试一次，或（仅当组合确实广告了提权字段时）带 `sandbox_permissions` 的同命令
  重试。双语（`t(lang,…)`——四个工具共用的同一词典面）。
  **误报口径（用户裁定）**：纯 cmdlet 命令（如空目录 `Get-ChildItem 2>&1`）命中条件式
  提醒**接受**——文案不断言失败，读作"若预期输出缺失"即为无害。
- **a 签名 2（可见拒绝文本，直陈式）**：结算输出含英文实测锚 `failed to run` + `Access is denied`
  （拒绝签名实测档案：`Access is denied`），或中文锚 `无法运行` + `拒绝访问`（zh-CN 语言包形态；本机不可实测，尚未核验）

  重试 / 提权重试）。**双语锚两条都在（用户裁定）**；中文锚匹配不上只损失提示、
  不损失功能。本签名是**附加提示**，不是第二套拒绝判定——R11 的"已知缺口"条款（不自造独立于
  宿主的本地化拒绝判定）不变。
- **b 警示段**：`async_run` 描述追加一段紧凑警示（受限会话里外部 EXE 的输出只有裸调用可靠，
  捕获形态会静默杀死它），仅在组合广告提权字段时出现（判定与 `sandbox_permissions` 广告同源）；
  **不复制 c 的纪律文本**；受开关控制。
- **c 常驻纪律段**：宿主半边经 `ctx.inject(["systemPrompt"])` 注册全局段（宿主面先例：宿主的沙箱策略基座行同款注入；
  `dsh-system-prompt` 是"每种模式都挂"的基座行，两实例 profile 均挂本包——覆盖面与加载安全都有
  结构依据，段名与段序由设计定）。内容 ≤25 行，语言取 `agentLang` 现行档（双语，同一词典面），覆盖：
  - **陷阱 1**（捕获形命令静默死）：判别——空输出且无 `[exit code]` 标记；纪律——判 EXE 可用必裸调用、受限

- **可验证**：
  - **单测（仓内假件；proc 假件带 `sandbox` 盖章——事实源与已跟踪 `lib/jobs.js` 的 `sandboxMarkers`

### R29 三线审查收敛：拒绝处理、入口取消、读失败可见性、预算上界与 killed 分流（安全/健壮性/异常处理审查轮）

- **问题**（安全/健壮性/异常处理审查发现的四类缺口）：四类缺口：
  1. **未处理拒绝**：`async_wait_agent` 的 `aborted` promise 在"创建后、首个竞速前"的屏障窗口内
     零 handler（`lib/wait-agent.js:219-225` 与 `:244`/`:246`/`:255`/`:323`）——宿主 installFailLoud
     语义（宿主进程装 `installFailLoud`：unhandledRejection 报 stderr 后整实例退出）下一次工具取消即可令整实例退出；`lib/settings.js:142-144` 浮动动态 import 无
     `.catch` 同类缺陷；`async_wait_job` 的接线段在 try 之外（`lib/wait-job.js:133-176`，try 起于
     `:179`），同步抛会泄漏监听器与定时器。
  2. **入口取消被静默忽略**：调用进入时 `exec.signal` 已中止的，两个等待工具都不报 interrupted——
     AbortSignal 已中止后挂监听器永不触发（abort 事件一次性），`async_wait_agent` 等满预算、`async_wait_job`
     早退但结算形态仍是 running 口径。
  3. **读层失败与"不存在/为空"合并**：`jobs.get` 查询失败并入"作业不存在"（`lib/wait-job.js:26-32`
     → `:111-114`，可能诱发副作用重跑）；`jobs.read` 读失败并入空串（`:43-45`）；drain 读失败与
     守卫触顶静默截断（`lib/jobs.js:68-72`/`:66-87`）不置丢失标记；结算通知缺 `senderSessionId`
     时的正文回退匹配可令无关通知误报 settled（`lib/interrupts.js:125`）。
  4. **预算可击穿与结局口径相反**：四个预算字段只有下限（`lib/config.js:91-111`），`maxWaitMs`
     越过 2^31-1 时定时器置 1ms 立即触发（Node 定时器溢出实测行为）；屏障重试耗时不计入 `wait_ms` 预算
     （`lib/wait-agent.js:141`/`:243-247`/`:301-303`）且 `pollIntervalMs` 无上界放大之；让出窗口内
     信号致死时宿主把 `proc.status` 置 killed 且 `done` 照常 resolve（shell 契约：done 从不 reject），
     前台分支不查
     status、无条件报 completed（`lib/jobs.js:576`/`:588`/`:163-185`），与已注册路径的 killed 分流
     （`:252-253`）口径相反。
     另有核验成立的低危边界项与暴露面登记缺口若干，归入定义 f/g（逐项判定见
     审查判定总表，内部留档）。
- **定义**：
  - **a 拒绝防线**：凡"只可能 reject"的 promise——`async_wait_agent` 的 `aborted`、`settings` 的
    浮动 import——创建点同步挂 no-op `.catch`（或首个 await 之前不存在可拒绝窗口）；`wait-agent.js:226-229`
    的"不会无 handler"注释同步改写为真实依据。`async_wait_job` 接线段（`lib/wait-job.js:133-176`）
    纳入 try/finally：同步抛也必须处置已创建的监听器、定时器与 abort 撤销。
  - **b 入口已中止**：两个等待工具在入口检查 `exec.signal.aborted`——已中止 → 立即返回 interrupted
    结局（不进屏障、不武装预算、不发查询）；`waited_ms` 如实为 0。既有 interrupted 文案复用（R12 引入、R28 沿用）。
  - **c 读失败可见性**：`jobs.get` 三分（`childOf` 同款）：查询失败报**可重试错误**（含"稍后重查"
    出路，不并入 unknownJob）；`jobs.read` 读失败 → note 标注"输出读取失败"；drain 读失败与守卫
    触顶 → 结算带丢失标记（与 `detail.lossy` 同一文案面）；结算通知的**正文回退**匹配命中后必须
    复查到"不再观察到运行"才可返回 settled——`source.kind === 'subagent-settled'` 的通知路径
    仍是权威信号、不加复查（投影滞后会误报 running）。
  - **d 预算上界**：`maxWaitMs` ≤ 2147483647（2^31-1）；`defaultYieldMs`、`pollIntervalMs` 设同量级
    上界（`pollIntervalMs` ≤ `maxWaitMs`），越界持久值在保存时被 schema 拒绝并给可读错误；`maxResultChars`
    设上界（与 `outputLimitBytes` 换算 `lib/jobs.js:330` 联动）。工具描述与 README 写明
    `wait_ms` 的实际覆盖口径：竞速段 + 屏障额外量（上界 = 3×`pollIntervalMs` + 查询往返），测试
    断言总等待不越过该上界 + 容差。
  - **e 前台 killed 分流**：让出竞速的 done 胜者先判 `proc.status === 'killed'` → 返回与
    `jobOutcome`（`lib/jobs.js:251-277`）同形的 killed 结局（含 signal 细节与丢失标记）；
    `completedResult` 不再是 done 胜者的唯一出口。
  - **f 边界小项**：`registerFailed` 的 `{detail}` 单行化并截断（500 字符，完整原文进操作者日志）；
    操作者日志插值单行化（CR/LF 转义）且字段名如实（`args.description` 标 `label=` 而非 `command=`，
    `lib/jobs.js:611-613`）；`routes` 消费前先验 `Array.isArray`，非数组按"无 policy"走词典错误
    （`lib/agent.js:101-110`）；`sandboxMode` 读取统一带 `?.`（`lib/jobs.js:522` 对齐 `:426`）；
    `listChildren` 透传 `exec.signal`（服务面接受——签名第二参即可选 signal）；`tools/` 开发脚本删硬编码本机路径候选，
    只认 env 推导（`tools/_host-resolve.mjs:49`、`tools/validate-preset.mjs:48/:50`；不随包分发，
    只影响开发机）。
  - **g 暴露面登记**：README 增补"信息暴露面"一节，登记：随请求下发给子进程的 `DSH_*` 变量
    清单（来源 `ctx.shellEnv.collect` 实际键集；"`DSH_WEB_URL` 不带令牌"为实测结论）、spill 落点为系统临时目录绝对路径（N5 取舍）、注册失败
    detail 的截断上界。纯登记，不改行为。
- **为什么**：宿主对未处理拒绝的处置是整实例退出（`installFailLoud` 终身有效），不是日志噪声——a 是存在性防线；
  已中止的调用返回 running 会诱导模型继续等或重试，b 让取消在第一时间有回音；"查询失败 ≠ 查无"
  与 R28 同一纪律的读取层延伸（R28 管沙箱拒绝的静默失败，本条管读取层）；d 让 R4 的有界性
  不被持久配置击穿——2^31 溢出是实测行为（定时器溢出置 1ms）；同一进程在两个路径上给出两种结局
  （completed vs killed）等于对模型说两套真话，e 消除口径分裂；f/g 是三份审查中核验成立的
  低危收敛项，并入本需求一并处理。
- **非目标**：不改宿主源码（所有修法落在插件侧）；不动 `verify/` 历史档案（其中的实例令牌是
  部署侧事务，建议用户轮换）；不剥离 `DSH_*` 环境变量（与内置 pwsh 同口径，g 只登记）；
  不给 `startContinuable` 半失败加防线（触发条件未证实，存疑留档）；不给 `!!js` loader 表达式
  另做安全层（与 shipped 基线同源）。
- **可验证**：
  - **单测（仓内假件）**：屏障窗口中止（barrierSleep 中途触发 fake signal）→ 无 unhandledRejection

### R30 提问接管：`ask_user_question` 超时放行、全局待答与迟到作答注入（统一开关默认关；不可裁剪，用户裁定）

- **问题**：根 Agent 在 Web 会话里调 `ask_user_question` 后，回合停在原地等人：该工具无超时、
  用户插话（steer）不打断它、浏览器断开也不取消（该工具的 execute 挂在一个永不超时、
  不受 steer 影响的等待上）——无人值守时整个会话冻住，
  直到用户回来作答或点停止。这是 R4"所有等待必须有界"在平台上撞到的最后一个无界等待：
  本插件各工具自身有界了，平台自带的提问工具没有。
- **定义**（四件套，全部受同一个 volatile 布尔总开关控制，**默认关**（用户裁定），
  保存后无需重启即生效——复用 R10/R21 机制）：
  - **a 接管点**：宿主半边在 `user-questions/request` waterfall 注册**抢先应答者**
    （`prepend` 注册——非 prepend 注册的监听器排在宿主转发器之后），四条接管条件全满足才接管，否则一律 `next()` 交还原生链：
    ①总开关开；②请求带 agent（无 agent 的编程式请求交还原生链），且该 agent 所属会话用
    本包预设（`dsh-async` / `dsh-async-create`）；③问题不带 `plan-review` intent（计划评审走
    原生，用户裁定）；④调用者是根 Agent（非根的提问在服务层已被拒，
    此条为防御性复验）。工具表与预设工具行**零变化**（不替换 `ask_user_question` 工具本体）。
  - **b 超时放行**：接管后等待窗口默认 60000 ms（volatile 字段，可配；上下限由设计定并
    登记进 §5）；
    窗口内用户经待答界面作答 → 返回真实 answers（与原生同形）；窗口耗尽 → 返回合成 answers
    （每题 `{ id, selected: [], custom: <超时说明> }`——空 selected 数组是官方认可的跳过形态），说明文案按 `agentLang`
    双语（同一词典），语义 = "用户暂未应答：请按你的最佳判断继续；用户作答后答案会以
    通知注入送达（见 d）"；调用被取消（signal 中止）→ 模型侧维持原生 `ASK_ABORTED` 语义
    （不得让合成答案盖过取消）。
  - **c 全局待答**（接管瞬间起挂起，无论是否已超时）：浏览器半边两种呈现**都做**，volatile
    枚举字段切换（用户裁定：现有描述信息不足以裁定优劣，两版齐备后实测再定
    去留）——`sidebar`（`sidebar.footer.action` 侧栏底栏座位，徽标本体自绘——座位契约
    只提供位置，不提供计数件）与 `overlay`（`shell.overlay` 内 portal 到右下角的浮动圆框——同一全局座位）；徽标
    注数 = 未答问题数，全部处理完消隐；待答列表
    按会话分组、可就地作答、可跳转会话、可单题**忽略**（忽略同样产生注入，见 d）。待答
    界面文案语言与设置卡同档三值（`uiLang`：auto/zh/en）——**auto = 宿主当前语言**（客户端
    `ctx.locale` 读取面——`getSnapshot().active` 渲染订阅 / `getLocale()` 一次性读 / `bind(ns)`），不得再有"auto 档落英文"的死角（用户裁定修正：
    现行实现 auto 恒英文）；zh/en 用本包词典；语言切换即时生效，不要求重开会话页。
  - **d 迟到作答注入**（用户裁定：**通知形注入**——作答不得伪装成用户发言）：
    用户对待答列表里的题作答或忽略 → 构造**自声明 `source.kind`**
    （`'async-tools-late-answer'`）+ `form:'notice'` + `summary` 的消息（子代理结算通知
    同形——user 角色消息、自声明 kind、form=notice+summary 配对）。**投递按 Agent 状态选通道，立即送达、不建队列**（用户裁定）：Agent 空闲且无未开跑的本包投递 → `agent.followup()`（唤醒开新回合，
    单条也立即）；否则（Agent 运行中，或空闲但本包 followup 尚未开跑）→ `agent.inject()`
    （next-step：折进当前或即将开始回合的下一个领取点，同窗口到达的多条由宿主**整批
    领取**）——宿主 next-turn 每领取点恰领一条，逐题 followup 会把多答退化成串行
    消化（空闲时逐回合、长步骤间逐边界滴流——next-turn 每领取点恰领一条；真机实录：等待期间三答排队、
    逐分钟滴流）；任何两次领取之间必有模型输出
    相隔；回合末步后的极短竞态（inject 落在最后一次领取之后）→ 空闲观察补一条极小
    followup 提醒开回合，不重复正文。注入正文**自含完整题面**（用户裁定）：
    稳定问题 id、题干全文、选项标签全集、multiSelect、作答内容（选中标签 + custom）或
    忽略、提问时间或时延——压缩或长对话后模型不依赖对原工具调用的记忆即可行动。
    `kind ≠ 'user'` → **不触发** `async_wait_*` 的插话打断（R12 判定不命中——迟到作答
    不是用户插话）；等待唤醒走**插件事件**（用户裁定，与投递解耦）：作答或
    忽略到达即刻发本包 ctx 事件，且 `async_wait_*` **等待开始时先查一次待读登记**——
    命中任一即提前返回"仍在运行"句柄 + note（对齐 `agent-message` 的提前唤醒先例，R3
    信号分类由三类扩为四类）；note 指明作答已到与题号、通知在下一领取点进上下文——
    起始检查堵住"作答先到、等待后开"的空窗（真机实录：已排队的作答没能唤醒后开的
    等待，干等至预算耗尽）。Web 呈现按宿主通知形（触发行或折叠正文随通道；自声明
    kind 在宿主分类器落通用标题，插件无扩展点）。
- **为什么**：见"问题"。另两条取舍：超时放行**不代答**（不自动选推荐项，用户裁定）——替用户做决定的风险大于停等；迟到作答走**通知形**而非用户消息（用户裁定）——插话判定、转录归类、Web 呈现三面都以
  kind 区分用户发言与系统通知，作答须以本包名义送达并保唤醒；投递按状态选通道
  （用户裁定）——逐题 followup 落 next-turn 每领取点恰领一条，实测
  多答串行消化、等待期间作答正文迟迟不进上下文（真机实录）；运行中改走 inject 折入
  当前回合，同窗口多答由宿主整批领取，见 d。
- **实现约束**：
  - 应答者与待答状态挂在**宿主行 fiber**上，可逆卸载（R4——副作用随 fiber 处置）；预设平面零改动（不新增
    工具行）。
  - 设置卡字段集合 13 → 16（R28 后 13 个 + 总开关布尔 + 超时毫秒 + 座位枚举）；布尔与枚举
    控件按 R27/R28 的"官方壳 + 自绘输入件"处置。
  - 会话预设判定路径已核验：`request.agent.id` → `ctx.sessions.get` →
    `ctx.sessionProjections.stateOf(session, "agentPreset")` 与两预设 id 全等比较；任一跳
    读不到或抛错 = 不接管（交还原生链，保守方向）。
  - 浏览器半边作答回传通道已核验并裁定（设计裁决 R30-D）：插件自有 typert remote
    命名空间（宿主 `TypertRemoteService` + `@Remote` 方法；客户端 strict descriptors 经
    `ctx.remote.$mount` 后直调）。待答状态因客户端无推送面（`$on` 仅白名单事件）采用轮询，间隔
    `ASK_STATE_POLL_MS`（§5）。
  - 一次调用多题：整批接管，超时对整批生效；迟到作答按题提交、待答界面按题出列；
    **投递按状态选通道**（`docs/design.md` §32.5 裁决 R30-C：空闲且无未开跑的本包投递
    → followup / 其余（运行中，或空闲但自家 followup 未开跑）→ inject，攒批由宿主领取
    语义原生完成，插件不建队列）。
  - 唤醒分支落在 `async_wait_*` 的信号分类（R3 三分类扩为四类：user 打断 / subagent-settled
    权威结束 / agent-message 唤醒重查 / 迟到作答**插件事件**唤醒交还）；载体为本包 ctx
    事件（作答或忽略到达即发）+ 等待开始时的待读登记检查，与投递解耦；与既有三类的
    判定互斥必须有专门单测。
  - 客户端 auto 档语言走 `ctx.locale` 读取面（`getSnapshot().active` 渲染订阅 /
    `getLocale()` 一次性读 / `bind`），只读不写（不调 `locale.setLocale`——它是全局偏好的唯一写入入口）。
  - 不改子代理提问行为（服务层在 waterfall 之前就拒绝子代理的提问，本插件无需也无法干预）；
    不动 `approval/request` 审批链（另一条 waterfall，提权由 R11 承载）。
- **非目标（本条不做）**：不接管计划评审（`exit_plan_mode` 的 plan-review intent 走原生卡片、
  照常等人，用户裁定）；不做自动选推荐项；不替换或遮蔽 `ask_user_question`
  工具本体；不改标准 / 创造等既有预设的提问行为（接管条件②已排除）；不做 Web GUI 之外的
  通知渠道（桌面通知、移动端推送一概不做，待答只在页面内呈现）。
- **可验证**：
  - **单测（假 waterfall / 假 agent / 假定时器）**：总开关关 → 应答者不接管（`next()` 被调，
    接管计数为 0）；四条接管条件逐一缺一 → `next()`；窗口内作答 → 真实 answers 原样返回
    （逐字段）；窗口耗尽 → 合成 answers 逐字段（每题 `selected: []`、custom 含超时语义句、
    id 与原题一一对应）；signal 中止 → 取消语义不被合成答案吞掉；投递通道：Agent 空闲
    时作答 → 立即恰一条 `followup`；运行中作答 → `inject`（next-step），同窗口多条 →
    同一领取点整批、零 `followup`；空闲且自家 followup 未开跑时后到作答 → 改 `inject`
    由该回合首次领取顺走；末步竞态 → 空闲观察补一条极小 followup（恰一次、不含正文）；
    注入消息 kind 为 `'async-tools-late-answer'`（≠`'user'`）、`form:'notice'`、
    summary 在册、正文逐字段自含题面（稳定 id/题干/选项标签全集/multiSelect/作答或
    忽略/custom/时延），忽略路径同形；等待中收到插件唤醒事件、或等待开始时待读登记
    非空 → 返回仍在运行句柄 + note（作答与忽略同形），不报 interrupted，亦不误报
    settled；auto 档语言跟随宿主 active（假 locale
    快照切换 → 文案整段切换），zh/en 走本包词典（T21/T22 同款判据）；
    待答计数随作答递减、清零消隐；座位枚举切换只换呈现层（注入与超时逻辑不随座位变）。
  - **可失败**：把等待改成无界（删超时竞速）→ 超时用例必红；删接管条件②的预设过滤 →
    非本包预设用例必红；运行中投递改回 `followup` → 通道断言与整批领取判据必红（运行
    中两题必产生两条 next-turn 消息）；删等待开始的待读检查 → "作答先到、等待后开"
    用例必红；删末步竞态补醒 → 竞态用例必红；把 kind 改回 `'user'` → kind 断言与互斥
    联测必红；把空闲投递改 `steer`/`inject`（不唤醒）→ 空闲唤醒判据必红；auto 档
    回退死写 en → 语言判据必红；删题面任一字段 → 逐字段断言必红；
    把总开关取值从活视图改成构造快照 →
    R10 同款行为差异判据必红。
  - **真机（验证实例）**：总开关关 → 提问行为与原生一致（原生问题卡片出现并照常等人、无徽标
    无浮框）；开 →
    ①本包预设新会话里提问在超时后模型继续工作（转录含合成答案与后续动作）；②待答徽标 /
    浮框出现且计数正确，作答后会话出现**通知形触发行**（非用户消息气泡），展开可见完整
    题面与作答，Agent 空闲时被唤醒开新回合；③标准预设对照会话提问仍走
    原生卡片（接管条件②的行为证据）；④两个座位各实测一遍且切换生效；⑤重启后设置与行为
    不变；⑥等待期间作答——Agent 正在 `async_wait_*` 时作答 → 工具提前返回运行句柄（非
    interrupted、非终态），作答正文在数秒内进模型上下文（下一条模型消息即引用作答）；
    ⑦宿主语言与
    `uiLang` 各档组合下待答界面文案语言正确（auto 跟随宿主）；⑧通道与攒批——子代理
    等待期间作答不排队（正文当回合进入上下文，非等待预算耗尽后）；空闲时连续作答多题
    （两秒内乱序）→ 首条立即开回合，其余并入该回合下一领取点整批处理（转录可见多条
    通知同一领取点）。

- **问题**：dsh 发布 0.2.0 预览版（0.2.0-rc.1，dist-tag `next`，2026-09-28），本包七项
  dsh 家族 peer 全部精确钉 0.1.7-rc.1，而宿主对 dsh peer 不匹配的 bundle 是**整包跳过**
  （工具行、设置命名空间与卡片、预设、客户端半边一起消失，不是降级运行）。两个在用实例共用同一份宿主安装与**同一个插件目录**（两份 profile 的
  junction 都指向本仓开发树）：验证实例与开发实例的 profile junction 都指向开发树，
  开发实例的 profile
  还带 `patchReload: "live"`。在现行目录直接做 0.2.0 适配——改 peer、改代码、改包内补丁
  ——开发实例下次装载即**整包消失**（工具、设置卡、预设一并失效），等于把在用实例的
  异步工具搞坏。适配必须做在**版本区分的独立插件包**上：0.2.0 适配线独立成包，开发实例现行
  包不动（用户裁定）。
- **定义**：
  - **a 独立包线**：0.2.0 适配代码只落在独立目录的独立包线（主仓分支 + worktree 或独立
    目录，形态由设计定稿）；开发实例挂载的主工作树在适配全程零运行时改动——不检出适配
    分支、不改 peer 声明、不改包内 `cordis.patch.yml` 与 `presets/*.patch.yml`。
  - **b peer 重钉**：适配包把七项 `@deepseek-ai/dsh*` peer 从 `0.1.7-rc.1` 精确改钉
    `0.2.0-rc.1`（预览线不写范围）；`cordis` / `cordis-plugin-timer` /
    `schemastery` 维持现行 tilde。**禁止以 profile version exemption 把 peer 不匹配的包
    强行挂进任一实例**——豁免绕过的是版本检查，绕不过接口不兼容，且 README 明言豁免有
    崩溃风险。
  - **c 挂载与宿主隔离**：验证实例的 profile junction 改指适配包目录，与其宿主升级（改用
    独立的 0.2.0-rc.1 安装目录）在**同一维护窗**完成——停服 → 改启动链指向 → 翻转
    junction → 启服；开发实例的 junction、宿主安装、profile 三不动。回滚 = 两处指回原值
    （部署动作与顺序细节的权威在 `dsh-local-deployment` 技能，本条只锁隔离约束与验收）。
  - **d 接口适配面**（调研核实的适配点：`dsh-subagent` 的 `listDescendants` 重写与
    descendant 行 `activity` 合成语义、`dsh-sandbox` 提权面增量、`dsh-tools` 的
    `displayReason` additive——逐包读数留内部调研档案）：① dsh-subagent
    列举语义——`listDescendants` 重写、descendant 行 activity 合成、`unsupported` 诊断会
    真实出现；本包屏障走的 `listChildren` 签名与返回行未变，屏障注释与「目录条目无 activity」的表述复核，
    若设计改用 `listDescendants` 须按新语义重写判据；② dsh-sandbox 提权面——五个在用
    导出全部仍在，新导出 `sandboxPermissionsDescription` 按"与内置一致"原则决定是否
    采用，`rejected` 错误文本加长，凡断言该文本的测试逐条复核；③ `displayReason`
    （dsh-tools / dsh-sandbox 两处 additive）按同一原则处置。
  - **e 稳定面只回归、不重适配**：`dsh-jobs` / `dsh-jobs-local` / `dsh-shell` /
    `dsh-shell-env` / `dsh-agent` / `dsh-system-prompt` / `dsh-user-questions` /
    `dsh-client-modules`（lib 零 diff）、settings-form 本包在用五面、
    `user-questions/request` waterfall 转发、本包在用的全部座位、web-app 四份 shipped
    预设补丁在 0.2.0-rc.1 逐字未变（逐包源码 diff 核实）——这些面在适配轮只做回归确认，禁止无差别
    重写。
  - **f 真机验收（验证实例升级后）**：按 R7 既有端到端判据复跑关键面（全部异步工具、两条
    可见性、预设隔离、设置生效），另加一条**负判据**：在验证实例故意挂现行 0.1.7 线包 →
    启动输出出现 skipped bundle 记录且插件不激活——证明 peer 跳过机制真实在场，也证明 c 的
    翻转是必经步骤。
  - **g 开发实例保护判据与 0.1.7 线去向**：适配期间与结束后，开发实例挂载目录三查不变
    （junction 目标、peer 值、包内补丁内容）；开发实例会话工具面照常。验证实例转为 0.2.0 后
    0.1.7 线失去真机验证环境——该线后续轮次（当前为 R30 实现与 R32–R36 轮）的真机判据要么在升级前
    完成、要么引用既有档案，如实登记不冒充。
- **为什么**：peer 跳过的失败形态是**整包静默消失**而非报错，"顺手在共享目录改"
  的破坏面最大且无提示；0.2.0-rc.1 是预览版，接口随 rc.2/正式版还会变，
  独立线让重钉与适配变更不波及在用实例；核心依赖面在 0.2.0-rc.1 逐字未变，适配
  成本集中在 d 项三处，独立线的维护代价因此有限。
- **非目标（本条不做）**：本条只立需求，不开发适配代码；不升级也不改动开发实例（宿主与
  插件都保持现状）；不做 0.2.0-rc.1 之后版本（rc.2/正式版）的适配——发布后重跑逐包
  diff 调研再重钉；不把 0.1.7 线轮次（R30 实现与 R32–R36 轮）搬到适配线，两线轮次去向由用户调度，
  本条只登记后果（见 g）。
- **实现约束**：适配包的版本号策略与两线同步策略（哪些轮次结果回流主线、方向是主线 →
  适配线单向还是双向）由设计定稿并写进两线 README；适配线从哪个 0.1.7 提交开分支由设计
  定稿。
- **可验证**：
  - **静态（两线各自）**：适配包 peer 七项 = `0.2.0-rc.1`、三方件 tilde 不变；主线 peer
    七项仍 = `0.1.7-rc.1`；主工作树相对开发实例挂载基线零改动（junction 目标 +
    `git status` 双查）。
  - **可失败**：把适配分支检进主工作树 → 静态判据必红；把任一 peer 改成范围写法
    （`^` / `~`）→ peer 判据必红；在任一 profile 写 version exemption 装不匹配包 →
    禁令判据必红。
  - **真机（验证实例）**：f 的复跑与负判据；升级后运行时版本读数 = 0.2.0-rc.1 且插件激活、
    无 skipped bundle 记录。
  - **开发实例（非破坏判据）**：适配全程开发实例现存会话与新会话的异步工具照常可用（以一次
    真实 `async_run` → `async_wait_job` 往返为准）；此判据**不要求重启开发实例**。

### R32 `async_run` 执行即注册，让出窗口改为可打断的首次等待（不可裁剪，用户裁定）

现行缺口：`async_run` 的让出竞速只有「命令结束 vs 预算到期」两个成员（`lib/jobs.js`），
yield 窗口内的用户插话与工具 abort 都无人接收——插话已在窗口内到达并正确落入
`next-step`，但要等预算足额耗尽、工具自然返回后才在步骤边界交付；GUI 停止的 abort
同样要等预算到期才生效（真机实录：一次 900 s 窗口内插话 +889.8 s 到达、+901.7 s 才随
预算到期交付；一次 60 s 窗口内插话 +5.3 s 到达、+63.1 s 交付；同型实录里 GUI 停止也是
等预算到期才以 abort 收场）。用户裁定：改变执行形态，而不是给竞速单独补接线。

- **R32-a 执行即注册**：顺序固定为 提权审批（R11）→ 注册表准入 → 命令进程启动。
  作业注册成功后才启动进程（与内置 `pwsh` 一致：进程在 starter 内、准入之后启动——
  准入触顶时 `start()` 在 producer 运行前抛错，进程不存在）；
  准入触顶时进程尚未启动，走 R8 错误文案。审批仍在最前，顺序不变。注册必须带 owner
  （调用会话）——abort 恢复通道依赖完成通知，而无主作业不发完成通知；
  无 agent 语境的调用如何处置（拒绝或如实降级）是**设计轮必须回答的问题**。
- **R32-b 让出窗口=首次等待**：让出窗口实现为一次有界等待（`jobs.wait` 语义），以下任一
  信号出现即结束等待；任何信号都**只结束等待，不得终止命令**（等待被中断不取消作业——
  `jobs.wait` 的 abort 仅在作业存活期 reject）：
  1. 命令结算（completed/killed/failed）；
  2. 用户插话（steer；R12 判定口径，排队消息不打断）；
  3. 工具调用 abort（GUI 停止，`exec.signal`）；
  4. 迟到作答到达（R30-d 第四类信号，与 wait 工具对称——用户裁定）；
     等待开始时同样先查待读登记，堵「作答先到、等待后开」的空窗（R30-d 口径）；
  5. 预算到期。
- **R32-c 各信号的返回形状**（模型可见契约）：
  - 预算内结算 → 与现行完成路径一致：完整输出 + 退出码 + 既有标记（killed 分流照旧），
    短命令体验不变。
  - 插话 → 转后台句柄（running 形状），note 含既有让出指令并注明因用户到达提前让出；
    不新增 output schema 分支。
  - 迟到作答 → 转后台句柄 + 既有 lateArrived note（与 wait 工具同口径）。
  - abort → 工具结果由宿主改写为 `Error: tool call aborted`（运行中的取消在 body
    settle 后被整体替换为该 canonical 形状，模型看不到句柄）；
    作业必须在注册表存活，结算时 tool-jobs 补发完成通知，作为模型恢复通道。
  - 预算到期 → 与现行让出分支一致：转后台句柄 + 既有 note。
- **R32-d 完成优先于打断**：信号到达时命令已结算 → 返回结算结果，不返回句柄
  （与 wait 工具同一口径，防模型重复等待）。
- **R32-e 完成通知不重复**：预算内结算的等待是活 waiter（awaited）→ 不补发完成通知
  （`tool-jobs` 只对未被活等待覆盖的结算补发完成通知）；
  插话/abort/到期后撤销等待 → 结算时通知照发（两者都以带 owner 注册为前提——无主
  作业不发完成通知）。
- **R32-f 既有口径不变**：`elapsed_ms` 自调用起算；输出截断、丢失标记、沙箱标记与提权提示照旧；
  `yield_ms` 夹紧区间与配置默认值照旧。

### R33 后台作业呈现：label=命令原文，描述进 progress 行（不可裁剪，用户裁定）

- **R33-a label=命令原文**：注册时 `label` 传 `command` 原文，不截断（与内置 `pwsh`
  一致——`JobSpec.label` 的内容惯例就是命令原文；界面自行做视觉截断）。完成通知与 `async_wait_job` 错误文案里的作业行随之显示命令文本。
- **R33-b 描述进 progress 行**：注册时把 `description` 写入作业 progress 行（活动期可见，
  结算时清除——宿主既有行为）。转录的工具调用卡现状已是 title=命令、description=描述，不变。
- **R33-c 执行期可见**：随 R32-a，注册时点即任务面板可见：命令、运行状态、已运行时长、
  实时输出（输出经拉式源进输出环——作业输出由环形缓冲承载）。

### R34 `async_workflow`：作业化的子代理编排（包装宿主 workflowEngine；不可裁剪，用户裁定）

现行缺口：批量子代理编排只有宿主 `workflow` 工具一条路，前台是其默认形态——脚本执行
占满整个工具批次：父会话步骤不结束，迟到作答（R30-d）悬置无法交付（真机实录：前台
workflow 冻结 15 分钟以上、迟到作答已 splice 进 next-step 却交付不出去），插话同理只能等
步骤结束（R12 的 queue 机制）；作业层完全缺席（前台
不注册作业、脚本内 `agent()` 的子代理也不注册——引擎子代理是调用会话名下的 one-shot
子会话）——任务面板不可见、不进
owner 并发上限（每 owner 默认 10 个存活作业）。用户裁定：编排纳入本插件范围，形态为**包装宿主
workflowEngine**，不重写引擎。

- **R34-a 形态与依赖**：新工具 `async_workflow` 调用 `ctx.workflowEngine.start(...)`；
  `script` / `meta` / `args` 参数面与宿主工具同形，不发明新脚本格式；引擎的沙箱、并发
  与总量 cap、结构化输出校验全部沿用。依赖 `workflowEngine` 服务：服务缺席时工具仍
  注册、调用点给可读错误（文风对齐 `error.providerNotRegistered`），预设独立性不破坏。
- **R34-b 执行即注册**（R32-a 对称；本工具无提权环节）：参数校验 → 注册表准入
  （owner=调用会话）→ 引擎启动；准入触顶走 R8 错误文案；注册成功才启动。编排作业进
  每 owner 并发上限（默认 10 个存活作业/owner）。
- **R34-c 让出窗口=首次等待**（R32-b 五信号逐条对称）：run 结算 / 用户插话（R12 判定
  口径，排队不打断）/ 工具调用 abort / 迟到作答到达（等待开始时先查待读登记，堵
  「作答先到、等待后开」空窗）/ 预算到期；任何信号**只结束等待，不得终止 run**。
- **R34-d 各信号返回形状**（R32-c 对称）：预算内结算 → 完整结果，文本形态对齐宿主
  `renderResult`（`workflow "<meta.name>" completed (<N> agents)` ＋ 返回值 JSON 按
  `maxResultChars` 截断）；插话 → 转后台句柄，note 含既有让出指令并注明因用户到达
  提前让出；迟到作答 → 句柄 ＋ 既有 lateArrived note；abort → 工具结果由宿主改写为
  `Error: tool call aborted`（运行中的取消在 body settle 后被整体替换为该 canonical 形状），作业在注册表存活、结算时 tool-jobs 补发完成通知
  作为恢复通道；预算到期 → 句柄 ＋ 既有让出 note。**不设 `run_in_background` 参数**
  ——本工具没有前台模式，「永远后台」由构造保证（async_agent 同款设计取向）。
- **R34-e abort 语义与宿主前台刻意分歧**：宿主前台把 `exec.signal` 接到 `run.cancel`
  （abort 即整批取消）；本工具**不接**（裁定，与 R32 对称）——abort 只结束等待，run
  存活；真取消走 `job_kill`（编排作业的 `cancel()` 才接 `run.cancel`）。
- **R34-f 完成优先于打断 / 通知不重复**：同 R32-d / R32-e——预算内结算的等待是活
  waiter → 不补发完成通知；插话/abort/到期后撤销等待 → 结算时通知照发（带 owner
  注册为前提——无主作业不发完成通知）。
- **R34-g 呈现**（R33 对称）：注册时 `label` = `meta.name`（宿主后台形态的既有取值），
  `meta.description` 进 progress 行、结算清除（与 R33 同款词汇）；注册时点即
  任务面板可见。
- **R34-h 描述门槛**：宿主工具的「仅用户明确要求编排时使用」门槛文案随 R35 行禁用
  消失，由本工具描述承接（R5 措辞约束适用）；判据：描述门槛锚句在场，删句必红
  （并入 R35-g）。
- **设计轮必答**：① GUI 运行记录面——宿主工具自带的 recorder / mirror
  （`dsh-client-ui-workflow-run` 消费的运行记录）能否复用；不能则明确接受损失（作业卡
  与输出环仍在）并写进设计。② 输出环内容最小面（script log / agent 起止事件 / 仅
  最终返回值）。③ 无 agent 语境调用的处置（照 R32-a 口径：拒绝或如实降级）。
  ④ 宿主描述的伴生引导（一两个委托用普通 subagent 调用）的承接改写——预设内
  subagent 工具已禁用，字面照搬会指向不可用入口。

### R35 两份异步预设：创建与等待只走异步工具（不可裁剪，用户裁定原则）

原则（用户原意）：预设里**创建子代理（单发与编排）只保留异步工具**（`async_agent` /
`async_workflow`）、**等待只保留** `async_wait_agent` / `async_wait_job`；**检查/管理
沿用宿主原行**——判据是该工具非阻塞（返回即确认、不持步骤）。凡存在「可被前台调用而
锁死批次」的宿主创建入口，一律禁用。

- **R35-a 接入第五行工具**：两份补丁新增 `async_workflow` 行——**插进 delegation
  组内 `tool-workflow` 行之后**（组内隔离服务 `workflowEngine` 只有组内行取得到，
  G-1；行位以 design §35.1-1 为权威）；`toolName` 分派，形态同四行，成例即 tool-subagent 系的工具行同款。
- **R35-b 禁 `tool-workflow`**：两份补丁把 `tool-workflow` 行置 `disabled: true`（该行
  现无 config，手术即加一行禁用；成例 tool-ralph）。
- **R35-c 禁 `tool-subagent` / `tool-subagent-fork`**：`dsh-async.patch.yml` 两行置
  `disabled: true`、config 逐字保留（`dsh-async-create.patch.yml` 已是此形态，既有形态即成例）。
- **R35-d 保留行**：`workflow-ptc`（引擎服务行，为 R34 供电，必须在场且 `provider:
  spawn`——并入两份补丁的既有形态判据，设计判据⑨）；`tool-subagent-control` /
  `tool-subagent-list-agents`（检查/管理面：`list_agents` / `interrupt_agent` /
  `send_message`，均非阻塞）。
- **R35-e 功能损失显式登记**：宿主 `subagent` 的前台模式与 `reasoning_effort` /

### R36 提问接管的会话级暂停计时（不可裁剪，用户裁定）

现行缺口：超时窗口是固定倒计时（R30-b，默认 60 s、10–600 s 可配）——用户已在读题但
剩余时间不足时，只能眼看超时放行、真实作答降级为迟到注入（R30-d）。「用户不在」与
「用户在场但需要更多时间」共用一个固定倒计时，无法区分。用户裁定：给待答
界面加会话级暂停开关，**无限期**（直到恢复或会话结束）、暂停期间新到批次**自动处于
暂停态**。

- **R36-a 作用域与语义**：会话级布尔标志，作用于该会话全部在答批次；预算语义 =
  倒计时时间而非墙钟——暂停期间不计入超时窗口，到期不触发、不产生超时合成答案
  （超时放行不进该路径）。暂停无限期，直到手动恢复或会话结束（插件卸载随之消失）。
- **R36-b 计时机械**：pause = 撤 `cancelTimer` 并记录剩余；resume = 按剩余重挂
  timer、`expiresAt` 平移（暂停 = 撤 `cancelTimer` 并记录剩余；恢复 = 按剩余重挂一次性定时器）。
  暂停期间该会话新到批次以暂停态登记、timer 不启动。
  轮询载荷（`state()` 的 items）带暂停标记（走既有轮询通道），两座位（徽标/浮框）倒计时
  显示冻结并示「已暂停」态。
- **R36-c 入口与通道**：待答界面每个会话组一个暂停/恢复开关；动作走 `async-tools-ask`
  既有远端面新增的 `pause` / `resume` 方法（与 `answer` / `ignore` 同路——同一 typert remote
  命名空间上的 `@Remote` 方法）。
- **R36-d 生命周期**：内存态、随会话与插件生命周期（会话结束/插件卸载即清），不持久
  化、不跨宿主重启；**批次清空不清除标志**——连续提问场景下暂停持续有效。
- **R36-e 边界**：只影响未到期批次；已超时放行的照旧走迟到作答（R30-d 不动）；暂停中
  作答走正常 delivered 路径；整个功能随 R30 统一开关——接管未开启时无计时亦无暂停
  按钮。
- **可验证（可失败判据）**：暂停后暂停标记置位，且墙钟越过原 `expiresAt` 亦不触发
  超时放行（转录无合成答案）；恢复后 `expiresAt` 平移（= 恢复时刻＋剩余）并到点正常
  放行；暂停期到的新批次首次轮询即带暂停标记，且恢复前不得放行——墙钟越过其全额
  窗口（含误挂 timer 的到期点）亦无超时合成答案；按钮随 R30 统一开关在场/缺席。

> **写作约定（R37 起生效，见 R38-5）**：面向模型与使用者的表述用抽象名——「验证实例（0.2.0）」「0.2.0 树」「验证实例（0.1.7）」；路径用仓库相对路径或 `<DSH_HOME>`、`<DSH_INSTALL>`、`<INSTALL_ENTITY_ROOT>` 占位；本机绝对路径只进不随公开仓走的过程档案。R37 的执行记录是本地部署实录，按现状原样记录，R39 清理轮统一处置。

的 `error.noPolicy`）。目标态：在不放弃 R35 入口裁决的前提下（或经明示重审后），
两预设会话的模型选择策略**在位**，`async_agent` 指定路由调用被接受且子会话真的跑在
指定路由上（note 锚 requested 标记；子会话 descriptor 断言）。

**裁定（用户）**：R13 指定路由 × R35 禁用宿主委托行的终局关系裁定为**恢复指定路由能力**。
R35-e 的限制登记按「已知缺陷、R40 修复在途」口径维护（README 限制段同口径）。

**宿主 0.2.0 源码调研（2026-10-02，0.2.0-rc.1 树；三候选路线的可行性事实）**：

机制基线（`@deepseek-ai/dsh-tool-subagent`，0.2.0 树 `lib/index.js`）：
- 行装载即注册投影（`apply()` 内 `ctx.sessionProjections.register(...)` **无条件**）；
  `modelSelectionSettings: true` 时 `selectForSession()` 在会话创建时采样——投影现值 →
  父会话继承 → 全局设置（Host 单例服务 `subagentModelSelection` 的 `current()`，
  volatile 的 `enabled`+`allowedModels`）——并追加**持久会话事件**
  `subagent/model-selection-policy`（幂等：已有策略则 no-op）；投影键
  `subagentModelSelectionPolicy` 从该事件 fold 出路由表。后续设置编辑不改已记录策略，
  子会话继承。
- 策略在场 ⇒ `list_subagent_models` 发现工具**必注册**（不依赖 provider 在场）；
  委派工具的注册在 provider 在场时（`mount()`）。宿主**没有**受支持的「装载行但不注册
  工具」形态。
- shipped `standard` 预设的 delegation 组自带 `tool-subagent` 行
  （`modelSelectionSettings: true`）——「策略在位」形态的活体参照。
- 投影注册表（`@deepseek-ai/dsh-session-projection`）：同键同 `stateVersion` 的注册
  **合并计数**（多次装载共存，最后卸载才消失）；`stateVersion` 不同则拒共享。插件侧
  同键注册合法。
- 包内 invariant 组合（`dsh-tool-subagent/invariant`）：agent/pre-step 断言
  「可选招牌（`provider`+`model`+`reasoning_effort` 三键）或发现工具在场 ⇔ 持久策略
  在位且两件齐」。本包 `async_agent` 无 `reasoning_effort` 参数故不触发；R40 若增发现
  工具或改参数面须对齐该断言。

三候选路线（设计轮据此选型，顺序非优先级；三线均**不改宿主源码**——对宿主只做
配置组合与公开 API 消费）：
- **A 宿主行装载不注册工具形态**：宿主无此受支持形态（见上）；启用行 +
  `modelSelectionSettings: true` 的标准形态会带回宿主 `subagent` 工具与
  `list_subagent_models`（须重审 R35「结构性唯一入口」裁决 + 复核 R4 隔离面判据的
  工具面计数）；「provider 指向永不注册的 id」变形可让委派工具永不挂载，但发现工具
  仍泄漏且骑在未定义行为上。改动面最小（两份预设补丁），契约最弱。
- **B 插件侧自注册 policy 投影**：本包预设行以同键、同 `stateVersion`(=1)、同 fold
  注册投影（注册表合并语义，与宿主行共存）；在预设组合作用域按宿主 standing 分支的
  会话归属过滤复刻采样（投影现值 → 父继承 → 全局 `current()`），追加同形持久事件
  （宿主 fold 校验非空/无重复；宿主后续行若再启用，见已有策略 no-op，前向兼容）。
  语义与宿主形态一致、无工具泄漏、不动 R35 裁决；代价是 fold/事件形状与宿主内部
  耦合（`stateVersion`/模式须随宿主钉住，导入级与判据级看护）。
- **C 直读全局白名单自任裁定**：`async_agent` 校验步直接读
  `subagentModelSelection.current()` 自判放行。改动最小，但语义漂移：调用时活值 ≠
  会话创建时采样、无持久记录（客户端读投影看不到）、无父会话继承、操作者事后关
  白名单**会**收紧既有会话（宿主是创建时定格、事后编辑不收紧——方向恰反）——与
  「无 policy 会话不暴露模型参数」的宿主管控口径相逆；
  若补「读后照记持久事件」则收敛为路线 B。

**可验证（目标态判据，设计轮细化）**：两预设会话内带 `provider`/`model` 的
`async_agent` 调用被接受（note 锚 requested 标记）；子会话 descriptor 报告指定路由；
无策略会话仍可读拒绝（`error.noPolicy` 锚）；R4 隔离面判据（standard 对照 + 工具面
计数）与 R35 既有判据（被禁行不复活，除非明示重审）不回归。

### R45 公开面与内容边界（常驻要求，不可裁剪）

R39 管的是**上传前那一次**清理；这一条管的是**此后一直成立**的规则：**新内容诞生时就要决定
它属于哪一半**，而不是等到上传前再筛一遍。

1. **单一例外目录。** 公开面 = 版本库跟踪的一切，**除了 `.local/`**。`.gitignore` 对本机内容
   **只准有 `.local/` 一条**（外加 `node_modules/` 与编辑器产物），**不得新增零散条目**——
   "这一条要不要 ignore"每次都要重新想，散着长必然长出永远清不完的例外表。
2. **代码公开、数据本地。** 脚本留在公开面，但**不得硬编码机器事实**（机器路径、实例端口、
   服务名、用户名）。需要时经 `tools/_local-config.mjs` 取，解析顺序是
   **环境变量 → `.local/config.mjs` → 文档化跳过**；形状见 `tools/local-config.example.mjs`。
3. **缺席与损坏是两件事。** 本机平面整个不在 → **文档化跳过**（CI 与外部 clone 的正常形态，
   退出 0）；本机平面在、但配置缺失或装载失败 → **红**。不分开的话，开发机上误删一次配置
   文件就会让**所有**本机判据静默变绿。
4. **文档自包含。** 公开文档（`README.md`、本文、`docs/design.md`、`verify/README.md`）所依赖
   的事实**直接写在文档内部**。**可以引用**：公开仓内文件、上游公开包源码
   （`[包名@版本] 文件:行号`）、公开 URL。**不得引用**：`.local/` 下的一切、事实登记簿的编号、
   过程稿、历史运行产物、本机路径与实例。
5. **判据常驻。** 以上由 `tools/check-public-surface.mjs` 的三族判定（**结构 / 本机指纹 /
   内部引用**）常驻看守，挂进 CI，并配变异证明（`verify/mutate-public-surface.mjs`）。
   **指纹族连注释一起扫**——注释里的机器路径一样会泄露。
6. **历史在发布时新生**（R39-2 的常驻形态）：公开仓以净化后的内容为起点，内部过程史另存私有。

## 5. 约束与既有数字（不得自创）
- `MAX_WAIT_MS = 600000`：对齐 dsh 既有的 `maxWaitTimeoutMs` 与 `maxTimeoutMs`（两者默认均为 600000）。
- `MIN_WAIT_MS = 250`：对齐 dsh 既有的 `MIN_YIELD_TIME_MS` 量级（codex 让出下限同为 250），避免 0 值与抖动。
- `DEFAULT_YIELD_MS = 20000`：**本包定的默认值**。理由：dsh 命令普遍偏重（编译/装包），低于 10 s 会让大量普通命令白跑一次"让出→取回"往返；高于 30 s 则长命令收益变差。codex 用 10000（其让出常量为 250–30000 ms 区间、默认 10 s），仅作参照。
- `DEFAULT_WAIT_MS = 30000`：对齐 codex `DEFAULT_WAIT_TIMEOUT_MS = 30000`，也是 dsh `waitTimeoutMs` 的既有默认（宿主默认 30000、上限默认 600000）。
- `MAX_JOB_CHARS`：等待返回给模型的输出上限，对齐 dsh 既有的 `maxOutputBytes` 量级（内置 `pwsh` 的输出上限同为宿主配置项）。现值见 `lib/config.js` 的 `maxResultChars`。
- `ASK_TIMEOUT_MS = 60000`（R30-b，用户裁定默认值）：提问接管等待窗口。下界 **10000** / 上界 **600000**（R30 设计轮裁定，`docs/design.md` §32.1）：下界 = 在场用户读完题并点选的最短可用窗口，再短会让"在场也来不及答"成为常态；上界对齐 wait 预算上界（600000 量级）。经设置字段 `askTimeoutMs` 可配（volatile）。
- `ASK_STATE_POLL_MS = 1000`（R30 设计轮定）：待答界面的状态轮询间隔。客户端对宿主无插件可用的推送面（客户端 `$on` 仅白名单事件、宿主→客户端亦无插件可用推送），轮询是唯一通道；1 s 对本地 JSON RPC 足够小、对徽标/浮框更新足够快。无宿主对齐对象，依据即本条。
- 设置卡落点（裁决 D13）：挂 `plugins.bundle.config`（插件页，描述与组件行之间），键 = **包名** `dsh-async-tools`——设置必须在插件页上，不得埋进组件行子页（R24）。
- 以上数字在 R10 之后都是**默认值**，运行时可被插件设置覆盖；上下限本身也可配置。

## 7. 风险与已知未知
| 风险 | 处置 |
|---|---|
| 让出阈值太小导致短命令白跑往返 | 默认 20 s；端到端测一条 10~25 s 的命令观察实际代价（已测 6 s 与 25 s 两条，真机端到端实录） |
| 模型不按新契约使用（仍想"一条命令等到死"） | 描述与预设人设明确写；端到端观察模型真实行为（已测三组自然行为会话，模型按预期先做别的事再 `async_wait_job`） |
| `async_wait_agent` 的 `activity` 不能可靠判定"是否已结束" | **权威信号是结算通知（`source.kind === "subagent-settled"`）与 `agent/status` 转 idle**；`inactive` 只用来提前结束等待、且承诺降到"不再观察到它在运行"（判别联合行的 `activity` 只反映"子会话是否驻留"，两个固定值都不来自实时状态查询）。该限制已写进工具描述 |
| 打断竞态：作业完成与用户插话同时发生 | 时间戳比较；工作完成优先于打断（模型必须知道已完成，否则会重复等待） |
| 让出后 `tool-jobs` 会补发完成通知，而它消不掉（注册即终态的同步复查窗口在现行作业实现上永不命中——`spec.run()` 同步调用、结算至少晚一个 microtask） | 实测它只在"模型完全没在等"时发出、且模型收到后仍按人设走 `async_wait_job`（真机端到端实录） |
| **R9 的最大风险：误删用户的预设** | 四道所有权判据（固定 id + 所有权标记 + 无额外文件 + 路径在根内），任何一条不满足即放弃删除；"同名用户预设不被删"必须有能失败的用例 |
| R9 的清理依赖"卸载时还有代码在跑" | 若 dsh 在移除 bundle 后不执行 disposer，则自动清理不成立；**这条必须先核实**（研究结论为准），核实不通过就改成"卸载后由用户执行一条清理命令"，并在文档里写清 |
| R10 的设置改动对已捕获配置快照的插件不生效 | 工具必须在**调用时**读取当前设置，而不是在构造时快照；设计里明确取值数据链，并用行为差异测试锁住 |

## 8. 流程要求（本项目的元需求）
按兄弟仓 approve-for-me 的同款流程推进，并留下可审查的记录：

```
需求 → 设计 → 设计审查 → 实现 → 实现审查 → 测试 → 修正 → 再审查 → 再测试
```

- 需求与设计分离；设计审查与实现审查**分别留档**，按轮次命名。
- 事实必须登记进内部事实登记簿（四字段：现行值 / 依据 / 核销日期 / 更新入口；登记簿不随公开仓走），未核验的结论一律不写。
- **测试与审查一律由独立子代理执行**；主会话不充当测试者与审查者。
- **文档与技能遵循 `chinese-doc-editing` 技能**：正文只承载"现在是什么、现在该怎么做"，历史与推导进档案或 git；错误值直接改写为正确值，不留"原文 + 注"。
- **文档与技能自身的改动同样要过子代理审查、修正与复审**。
- 该流程本身要由子代理固化为一个 dsh 插件开发技能（D10），产出物必须包含：阶段定义、每阶段的产物与验收、留档命名规范、以及本项目踩过的具体坑（如：动态宿主沙箱按能力逐项放行——未在 `inject` 声明的服务、带 cordis Context 的 `ctx.get` 读取、枚举服务对象键都会被拒，正式插件包不受这些限制；作业 kind 在运行时未被强制约束，自定义 kind 实测可用）。
