## 1. 安装身份与前提

| 项目 | 当前适用版本 |
| --- | --- |
| 插件版本 | `0.2.8+dsh.0.2.1-rc` |
| 支持的宿主版本 | `0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5` |

DSH 必须是表中四个版本之一。它们属于同一条兼容线；集合外的正式 `0.2.1`、`0.2.0`、`0.2.2` 及未列入的新 rc 均不放行。

建议 Node.js 24。插件清单的 `>=20` 只是插件声明；宿主依赖 commander 15 要求 `>=22.12.0`，也只是已知下界，不是整套宿主经验证的最低版本。确认目标宿主依赖能在所选运行时解析后，再安装。

### 验证范围与部署选择

已有验证限于本机 Windows、隔离实例：四个支持宿主各自通过本包全量模块套件与静态检查；真实浏览器检查了设置页、提问浮层的关键行为和无障碍树；真实模型会话抽样检查了五工具核心行为（后台交付、等待与插话、子代理续接、提问迟答）。安装件还经官方 CLI 装入隔离实例，检查了工具名册、预设补丁和依赖树。这些检查不能合并理解为所有宿主、所有功能均已逐项实机验证。

部署前需考虑以下缺口：

- Linux 实机行为（含命令、单次提权）未验证；macOS 和远程环境无验证结论。
- 真实操作系统输入法、读屏与触屏未验证。
- 工具结果已构造、提交前被宿主改写为取消错误的精确时序，尚未在真实宿主验证。
- rc.3／rc.4 真机逐项重验未完成，套件与静态检查已覆盖。
- 远端 CI 已配置四版本矩阵，但远端执行尚未发生。

涉及上述环境或行为时，先与维护者安排隔离验证。旧 rc.2／rc.5 安装的实测结论不自动覆盖后续机制变化。逐项记录见匹配源码提交的 `docs/design.md` §9.3。设计、变更记录和开发验证资料不随包分发，需从[源码仓库](<https://github.com/MC5Spear/dsh-async-tools>)取得与安装来源对应的检出；变更历史不是本机已安装版本查询。

### 安装、固定来源与版本核对

包不从 npm 分发。在终端运行，或在 DSH 插件管理页的安装对话框中填入同一 GitHub 地址：

```powershell
dsh plugin --profile web add github:MC5Spear/dsh-async-tools#adapt/dsh-0.2.1
```

该地址跟踪移动分支。不带分支或提交限定的地址（如仅 `github:MC5Spear/dsh-async-tools`）不能自动选择正确的宿主适配。需要固定来源时：

1. 检出准备安装、实际可从仓库取得的目标源码，用 `git rev-parse HEAD` 取得并记录完整提交号。
2. 将安装地址中 `#` 后的分支名换成该完整提交号。本地存在的提交不一定已在远端可取。
3. 安装后检查目标 profile 中本包安装目录的 `package.json`，核对 `version` 与所选源码一致；保留实际安装地址和完整提交号作为来源记录。版本号不能单独证明提交身份，不要用变更记录代替安装核对。

安装结束后，打开本包详情页确认设置表单可见；新建会话，确认可选 `dsh-async` 和 `dsh-async-create`。选择其中一个后，Agent 应能使用本参考列出的五工具。

### 安装排查与开发链接

取不到源码时，先核对仓库地址和提交号，再检查网络或代理；仍无法获取时，向提供来源的维护者询问可用安装件。若设置或工具缺席：

1. 核对 DSH 版本是否在支持集合内，并查看装载日志是否因版本不匹配跳过本包。
2. 在目标 profile 中核对 dependency（安装依赖登记）与 bundle（宿主行和预设的组合声明）。两者职责不同，仅有一处登记不能确认全部入口已加载。
3. 更改组合或客户端入口后，重新装载实例并重新打开页面。重启前安排活动会话安全收尾，从服务进程树外执行；普通合法设置保存无需重启。

开发链接只用于明确的开发环境，稳定部署与编辑树分开：

```powershell
git clone https://github.com/MC5Spear/dsh-async-tools.git
cd dsh-async-tools
git checkout adapt/dsh-0.2.1
npm install
dsh plugin --profile web add <克隆目录的绝对路径>
```

链接目录须能解析匹配的宿主依赖。单独用 Node 导入只能检查部分模块解析，不能证明宿主服务、工具和页面接入完整。

## 2. 首次使用与设置

### 第一次任务

两个预设都直接提供五工具，不改写原有预设；检查、消息和显式停止继续使用宿主管理工具。新建会话时选择 `dsh-async` 进行通用编码，或选择保留插件与预设创作工具的 `dsh-async-create`。

在 Windows PowerShell 环境，可把这段无害请求粘贴给 Agent：

> 请演示后台执行，不修改文件、不访问网络、不创建子代理。先用 async_run 执行 `Write-Output SHORT_OK`。再执行 `Start-Sleep -Seconds 30; Write-Output LONG_DONE`，显式设置 yield_ms=20000。保存返回的 job_id；需要等待时，用 async_wait 指定该作业并显式设置 wait_ms=30000。报告两个标记与真实退出信息，不重复运行命令来查进度；编号未收到时先用 job_list 找回。

预期短命令直接显示 `SHORT_OK`，长命令在首次最多等待 20 秒后返回 `job_id`；稍后结果直接附在等待返回或完成消息中，出现 `LONG_DONE`。完成仍须核对退出信息。以下是 Agent 工具调用示意，不是终端命令：

```text
async_run(command="Write-Output SHORT_OK", description="Print a harmless test marker")
async_run(command="Start-Sleep -Seconds 30; Write-Output LONG_DONE",
          description="Wait then print completion marker", yield_ms=20000)
async_wait(targets=[{kind:"job", id:"<返回的job_id>"}], wait_ms=30000)
```

`yield_ms` 出厂默认 20000 ms，请求边界为 20000–600000 ms，超出时按边界生效。后台运行期间继续独立工作，需要结果时再等待；每次必须显式填写 `wait_ms`，没有默认值。更多等待方式见[参数参考](<#32-async_wait>)。

### 修改与保存设置

1. 打开插件列表 → 本包详情页 → 描述与组件行之间的设置表单。
2. 修改所需字段，选择保存。编辑只产生草稿；离开丢弃未保存草稿，保存失败则保留。帮助按钮只展开说明。
3. 保存后核对字段值与覆盖标记。普通合法设置保存无需重启。

写入需要宿主本机回环入口；非回环或只读时，按页面提示切换到可写入口。

每个字段的“恢复默认”只暂存删除该字段的用户覆盖，也须保存，不影响其他字段。保存后先采用宿主组合配置的值，组合也未配置时才用出厂默认值。例如组合为 `45000`、用户覆盖为 `90000`，删除覆盖并保存后得到 `45000`，不是 `20000`。正常配置下，该字段应不再标为“已覆盖”。若仍有降级警示，按[配置恢复](<#配置降级与恢复>)继续处理，不能仅凭保存成功判断已修复。

### 2.1 全部20项设置

表中“范围”表示允许保存的配置值。单次调用超出当前 min/max 时，工具把请求值调到对应边界，这叫“夹紧”。新的非法配置保存会被拒绝，不会自动改成边界值；已有损坏配置的原样重存例外见表后的恢复说明。毫秒（ms）是存储单位，1000 ms 等于 1 秒。

| 字段 | 类型 | 默认 | 范围 | 单位 | 生效 |
| --- | --- | --- | --- | --- | --- |
| `defaultYieldMs` | number | `20000` | 1..2147483647，可小数 | ms | 下次run/workflow省略yield_ms时 |
| `minYieldMs` | number | `20000` | 1..2147483647，可小数 | ms | 下次首次等待请求下限 |
| `maxYieldMs` | number | `600000` | 1..2147483647，可小数 | ms | 下次首次等待请求上限 |
| `defaultWaitMs` | number | `30000` | 1..2147483647，可小数 | ms | 等待示例基准；wait_ms仍必填 |
| `minWaitMs` | number | `20000` | 1..2147483647，可小数 | ms | 下次wait请求下限 |
| `maxWaitMs` | number | `600000` | 1..2147483647，可小数 | ms | 下次wait请求上限 |
| `pollIntervalMs` | number | `500` | 1..2147483647，可小数 | ms | 新等待的状态轮询及存在检查间隔；挂起中的周期复查按此值取间隔（实际不低于 50 ms 定时下限；单次查询超窗顺延到下一周期，全程上界为有效wait_ms+300ms） |
| `maxResultChars` | integer | `12000` | 1..1000000 | JS String.length | 结果渲染 |
| `jobKind` | string | `async-command` | 非空 | — | 新命令作业的类型标识 |
| `subagentProvider` | string | `spawn` | 后端名；trim后空值回spawn | — | 下次子代理创建；不是LLM provider |
| `uiLang` | enum | `auto` | auto / zh / en | — | 界面；auto跟随宿主 |
| `agentLang` | enum | `en` | en / zh | — | 描述、结果和执行纪律的语言 |
| `silentFailureGuard` | boolean | `false` | true / false | — | 名单内会话的命令诊断与提示 |
| `workflowProgressLog` | boolean | `false` | true / false | — | 编排结果是否保留各阶段进度行 |
| `fullCommandEcho` | boolean | `false` | true / false | — | 后台结果交付时附上完整命令与工作流脚本原文 |
| `askTakeover` | boolean | `false` | true / false | — | 每次普通提问请求 |
| `askTimeoutMs` | number | `60000` | 10000..600000，可小数 | ms | 新接管批次的初始期限 |
| `askExtendMs` | number | `60000` | 1..2147483647，可小数 | ms | 每次延长动作，在原期限上追加 |
| `askUiSeat` | enum | `sidebar` | sidebar / overlay | — | 待答面板位置，不重置期限 |
| `boundPresets` | string[] | `dsh-async, dsh-async-create` | 预设ID数组，元素非空且不重复；空数组合法 | — | 按会话当前实际预设匹配 |

跨字段须满足 `minYieldMs <= defaultYieldMs <= maxYieldMs`、`minWaitMs <= defaultWaitMs <= maxWaitMs`、`pollIntervalMs <= maxWaitMs`。预算数字须有限。首次等待和后续等待的出厂上限均为 600000 ms。`defaultWaitMs` 只是示例基准，不补全缺失的 `wait_ms`。

### 适用预设：名单与两个开关

`boundPresets` 决定哪些会话使用本包的操作要求和辅助功能，按会话**当前实际预设**匹配。同一工具被多个预设复用时，未选预设的会话不受影响。

| 功能 | 生效条件 |
| --- | --- |
| 异步操作要求（加入 Agent 的系统提示） | 当前预设在名单内；没有独立开关 |
| 命令静默失败诊断与提示 | 当前预设在名单内，且 `silentFailureGuard=true` |
| 待答面板处理普通提问 | 当前预设在名单内，且 `askTakeover=true` |

名单默认包含 `dsh-async`、`dsh-async-create`，两开关默认均关闭。全部取消并保存，即保存合法空数组 `[]`，解除全部绑定。**绑定不会增删工具，也不会改写预设组合。** 自建预设要使用全部异步功能，仍须手工挂五工具并满足编排引擎条件，见[高级组合](<#7-高级组合>)。

设置页从宿主预设注册表取得候选，点击“刷新”可重读。已绑定但当前目录缺席的条目仍显示并可取消；装载失败条目显示宿主诊断原文，未绑定时不可新选，已绑定时仍可取消。读取名单失败时，页面保留已保存绑定供取消，不把失败显示为空名单。

### 高级文件配置与旧配置迁移

取值优先级为：**用户覆盖 > 组合配置 > schema 默认值**（配置定义中的默认值）。用户层存在该字段就算覆盖，即使数值恰好等于默认值。

文件中的设置写在宿主行 `config.settings.<字段>`，不要直接放在 `config` 根上。0.2.5 平铺形态 `config: { agentLang: zh, … }` 在 0.2.8 不生效：行可能正常激活，但组合预置值回落默认。升级前改为 `config: { settings: { agentLang: zh, … } }`。完整对照、症状和装载警告见匹配源码提交的 `CHANGELOG.md`「从 0.2.5 形态的行配置迁移」节；该文件不随包分发，获取方式见第 1 节。

工具优先读取宿主发布的当前配置快照；仅在快照缺席时使用合法工具行备用值，并提示设置未接入。`toolName`、`owningPreset` 和委托行配置是固定行配置，不属于上述 20 项界面设置。

### 配置降级与恢复

**出现降级警示时，工具采用哪些值？** 启动时，损坏的布尔值或不满足跨字段约束的配置可进入可修复降级：表单仍显示原配置，工具改用合法出厂默认值。运行期间遇到新的非法配置，则继续使用上一份合法值；普通新非法写入在保存前被拒绝，不会替换合法配置。数值或枚举的 schema 校验失败还可能使插件行无法加载，此时先查看装载日志，修正日志指出的字段。

**保存成功不一定表示已修复。** 若把已有损坏配置原样重存，可能得到成功应答，但工具仍处于降级状态，警示和回退取值不会因此解除。这不表示可以保存其他新的非法值。

要恢复正常，先修正全部非法字段和跨字段关系，使整份配置合法，再保存。保存后检查降级警示是否解除，并核对工具描述中的实际采用值是否符合预期；不要只看保存成功或表单中的“生效”读数。若警示仍在，按警示或装载日志继续修正。正常合法设置保存无需重启。

## 3. 五工具参数与返回

参数表中的“必填”适用于每次调用。未知键不能当作任意宿主配置透传。预算取当前设置夹紧后的值。

### 3.1 async_run

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `command` | string | 必填 | 执行的命令原文 |
| `description` | string | 必填 | 主动语态5—10词进度说明 |
| `yield_ms` | number | defaultYieldMs | 有限数字，夹紧至minYieldMs..maxYieldMs |
| `workdir` | string | 会话当前有效目录 | 相对路径以当前有效目录解析；启动后目录固定 |
| `sandbox_permissions` | string enum | 条件可选 | 仅有约束执行器时出现，模式取宿主工具声明 |
| `justification` | string | 与 `sandbox_permissions` 一起提供 | 解释同轮刚被拒命令的一次性重试为何需要更宽权限 |

权限仍走宿主审批；不得拿更宽权限启动另一个任意任务。目录解析失败在启动前返回可读错误，不偷偷换目录。显式 workdir 准备失败的诊断保留请求值、解析路径、会话目录、失败时核实结论和修正出路；ENOENT本身不证明目录不存在。

首次等待完成返回 `{status, output, truncated, exit_code?, signal?, note?}`；`completed` 不代表退出码为0，读取退出标记。`signal` 是进程终止信号。被终止可返回 `{status:'killed', detail?, output?, truncated?}`。后台返回 `{status:'running', job_id, elapsed_ms, note}`。作业从启动时注册，不等到首次等待到期才出现。

### 3.2 async_wait

统一等待入口：无目标等待消息与作业结果，或等待指定作业与子代理目标。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `wait_ms` | number | 必填，无默认 | 正值夹紧至minWaitMs..maxWaitMs；0合法＝零等待即时检查 |
| `targets` | array | 可选，默认无目标 | 元素为 `{kind, id}`；kind枚举job/agent，id非空；重复项按同一目标去重 |

按目的选择调用；下面都是 Agent 工具调用示意，每次均显式填写 `wait_ms`：

| 目的 | 调用示例 | 何时交回 |
| --- | --- | --- |
| 等消息或作业结果 | `async_wait(wait_ms=30000)` | 先交付就绪结果；确认有自己的运行中作业或子代理时，才等待新消息或结果 |
| 等指定作业 | `async_wait(targets=[{kind:"job", id:"<job_id>"}], wait_ms=30000)` | 作业到终态、收到用户插话或本次预算到期 |
| 等指定子代理变化 | `async_wait(targets=[{kind:"agent", id:"<agent_id>"}], wait_ms=30000)` | 目标产生变化或目标消息、收到用户插话或本次预算到期；最终回答另行送达 |
| 只检查、不等待 | `async_wait(wait_ms=0)` | 返回当前状态和未交付内容；也用于领取被延后的结果 |

可在 `targets` 中混合多种目标，任一目标满足条件即可交回；非目标通知不提前结束指定目标等待。输出续取与恢复副本见[第 4 节](<#4-等待状态与直接交付>)。

**返回字段**：

```text
作业终态：{status:'completed'|'killed'|'failed', job_id, output, truncated, waited_ms}
子代理变化：{status:'changed'|'settled', agent_id, waited_ms, note}
等待出口：{status:'running'|'budget'|'interrupted'|'message'|'cancelled'|'no-work'|'unconfirmed',
          waited_ms, note}
```

同一领取窗口就绪的其他作业正文放在 `outputs` 中分条返回，`delivered` 是批次元数据。多目标返回还带结构化 `targets`；可见文字至多显示 8 行目标状态，超出给出数量。状态意义与下一步见第 4 节。

**等待时长细节**：入口查询、存在检查、重试和实际等待共用一份预算。无目标等待期间按 `pollIntervalMs` 周期复查，确认全部工作结束就提前交回；复查读取失败则继续等待，不据此判无工作，到期会注明未确认项数。实际查询间隔不低于 50 ms，单次查询超窗顺延到下一周期，全程上界为有效 `wait_ms+300 ms`。

零等待也需要完成检查：所有检查共享 1000 ms 窗口，每项查询只发起一次，窗口内未完成的查询按 `unconfirmed` 标记。`waited_ms` 记录实际检查耗时，不因没有进入等待就固定为 0。

**入口校验失败**：所有目标须先完成校验，再决定是否交付目标通知或终态。混合目标中任何一个不合法，整次调用拒绝，不是某一行的状态更新；即使已有结算通知也不能跳过校验。

- 作业清单中查无目标 ID：返回可读错误，用 `job_list` 核对仍在册的 ID。
- 作业清单读取失败：返回另一错误，作业可能仍在，稍后重试原目标，不等于查无。
- 正等待下子代理目录暂时查无：至多重查三个查询周期，受总预算限制；仍查无时附已知子代理清单。查询未完成而预算先到，按 `unconfirmed` 交回。零等待不做这类重复查询。

无目标入口若读取失败且没有任何已确认运行工作，按 `unconfirmed` 交回；若已确认至少一项运行，则可继续等待。若只有子代理目标，其中存在读取失败等未知状态，且没有任何已确认运行的目标（可以与已静止目标混排），则按 `unconfirmed` 提示重查，不仅为未知状态挂满预算。全部目标已确认静止时，按静止状态立即交回。

### 3.3 async_agent

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `description` | string | 必填 | 提供3—5词展示标签 |
| `prompt` | string | 必填 | 提供完整任务；spawn独立子代理看不到父对话 |
| `cwd` | string | 继承父当前有效目录 | 指定子代理初始工作目录；相对父当前目录解析，后续目录变化互不影响 |
| `provider` | string | 条件可选，与 model 成对 | 后端声明支持路由选项时可用；准确 LLM 供应商 ID |
| `model` | string | 条件可选，与 provider 成对 | 同上；准确模型 ID，先按第 5 节查询 |
| `reasoning_effort` | string | 条件可选 | 同上；可单独提供，按最终有效模型校验推理强度 ID |
| `agent_preset` | string | 条件可选 | 为子代理指定独立预设；仅行配置允许集非空且后端支持时出现，取值须在允许集合中 |

无 `run_in_background` 参数，也不等待最终答案。成功立即返回 `{status:'started', agent_id, note}`，说明实际路由来源及等待入口；拒绝不返回虚构编号。默认两预设未配置允许预设集合，因此不暴露agent_preset。继承上下文型后端的子代理可见父上下文；任务书按实际后端编写。

通常只需标签和完整任务书，模型采用配置默认或继承。`subagentProvider` 是执行后端（默认 `spawn`），不是这里的 LLM 供应商。只有后端声明支持路由选项时，三个模型参数才出现在工具参数中；未声明支持时传入会被可读拒绝，不会静默忽略。模型查询、创建和等待的完整路径见[第 5 节](<#5-模型目录授权与继承>)；高级默认值合并也在该节说明。

### 3.4 async_workflow

仅在用户明确要求workflow或大规模编排时使用；一两项委托用async_agent。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `script` | string | 必填 | 纯JavaScript函数体，允许顶层await，以return返回JSON可序列化值 |
| `meta` | object | 必填 | name、description必填字符串；whenToUse可选；phases可选数组 |
| `args` | object | 可选 | 脚本内args原样可用；裸列表包在对象字段中 |
| `yield_ms` | number | defaultYieldMs | 与run同样夹紧 |

meta名称建议短kebab-case；阶段项title必填，detail/provider/model可选字符串。工具入口 schema 允许 meta 与阶段项携带额外键通过形状校验，但当前编排引擎在启动前拒绝 meta／阶段中的未知字段并返回 `META_INVALID`；参数实际使用只采用上表列出的键。script不是TypeScript或模块，不写`export const meta`。

| 脚本钩子 | 合同 |
| --- | --- |
| `agent(prompt, opts?)` | Promise；无schema返回最终文本，有schema返回校验对象；普通子代理失败为null。opts仅label/phase/provider/model/schema；provider/model可独立覆盖，不套成对规则 |
| `schema` | 对象根JSON Schema，支持type/properties/required/additionalProperties/items/enum/const/oneOf；不支持pattern/format/数值边界 |
| `pipeline(items,...stages)` | 条目独立逐阶段推进，无跨阶段全体屏障；stage(prev,item,index)普通异常将本条目置null并跳过余下阶段 |
| `parallel(thunks)` | 并发零参函数并全体await；普通异常对应null |
| `phase(title)` | 精确匹配meta阶段标题 |
| `log(message)` | 报告进度 |

坏钩子参数、未知选项（含effort/isolation/agentType）、不支持schema及触发总量/组合上限会终止整脚本，不化成局部null。并发与总量由宿主约束，无固定通用数值。脚本没有文件系统、网络、定时器或Node API；子代理执行实际工作。

```javascript
const results = await pipeline(args.items,
  async (_, item) => agent(`Review this item: ${item}`, { label: 'Review item' }));
return results.filter(value => value !== null);
```

脚本须显式返回根值；漏写 `return` 导致 `undefined` 会报运行错误，合法 `return null` 则可用。

完成返回 `{status:'completed', result}`，result是渲染后的字符串，并非直接返回JSON对象；终止返回 `{status:'killed', detail?}`，后台返回 `{status:'running', job_id, elapsed_ms, note}`。后台运行的结果经async_wait或完成消息交付；job_kill才请求取消。缺编排引擎时在启动前返回可读错误、不创建作业；正确组合见第7节。

### 3.5 async_list_subagent_models

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `provider` | string | 可选 | 准确供应商ID；省略可浏览供应商或跨供应商搜索 |
| `model` | string | 可选 | 必须同时有provider；准确模型详情 |
| `query` | string | 可选 | 去首尾空白后搜索；全空白视为省略，非空时与model详情冲突 |
| `target_tool` | string | 可选 | 当前会话可见的创建工具名称，含用户配置名称 |
| `page` | integer | 1 | >=1；大于1须带version |
| `page_size` | integer | 20 | 1..100 |
| `version` | string | 首页可省略 | 续页必须绑定同一筛选与目标版本 |

```text
async_list_subagent_models(query="coding", target_tool="async_agent", page_size=20)
→ 继续查询时复用返回的next对象，不自行拼接旧页。
async_list_subagent_models(provider="<准确ID>", model="<准确ID>", target_tool="async_agent")
```

结果固定包含 `mode`、`entries`、`total`、`version`、`complete`、`target`、`verdict`、`basis`。它们分别说明查询模式、本页条目、匹配数、版本、完整性、目标、适用结论和依据。其他可能字段为 `page`、`page_size`、`provider`、`query`、`has_next`、`beyond_end`、`failed_providers`、`example`、`unlisted_provider`、`unlisted_had_routes`、`next`。

需要下一页时，直接复用 `next`。它带有 `page`、`page_size`、`version`，以及本次使用的 `provider`、`query`、`target_tool`。结果先筛选后分页，同版本内按 ID 字典序稳定排列。版本失效就从第一页按相同条件重查，不拼接新旧页；超过末页会得到空页和总数，不自动回到首页。

搜索匹配 ID 与显示名，忽略大小写。部分供应商读取失败时，`complete=false`，`total` 只计算已取得的结果，不能理解成失败供应商没有模型。允许名单中的准确 ID 即使未列入目录，仍可查询和列入结果；目录缺席本身不证明模型不受支持。

## 4. 等待状态与直接交付

### 先判断等待为什么结束

等待结束不等于后台工作停止。预算到期通常为有目标的 `running` 或无目标的 `budget`；先看各目标实际状态，再决定是否继续等。

| 状态或现象 | 含义与下一步 |
| --- | --- |
| `running`／`budget` | 本次预算已用完。处理独立工作；确实依赖结果时再用原目标等待 |
| `interrupted`／`message` | 用户插话或可处理消息使等待提前交回。先处理新内容，不据此判断目标完成 |
| `cancelled` 或宿主取消错误 | 本次等待被取消，后台工作不因此停止；编号未收到时用 `job_list` 或完成消息找回 |
| `no-work` | 已确认没有可等待工作：可能入口即返回，也可能等待期间复查确认全部工作已结束。`note` 区分两种过程，`waited_ms` 是实际检查或等待耗时 |
| `unconfirmed` | 查询失败或超时，尚不能确认等待条件。它不表示没有工作；按提示重查原目标 |
| 作业 `completed` | 读取结果并检查退出码，完成不等于退出 0 |
| 作业 `failed`／`killed` | 保留错误、信号与已有输出，再决定修正或停止 |
| 子代理 `changed`／`settled` | 只说明目标变化或当前不再观察到运行；最终回答独立送达，不是任务成功证明 |
| 查询或读取失败 | 按错误重试原目标，不重新启动原任务；读取失败不消耗当次增量 |

用户插话、可领取通知（notice）、代理转达（relay）和本包迟到答案都会触发消息检查，入口前已到的消息也有效。排队消息留到下一轮，不打断本次等待。指定目标时，非目标消息不会提前结束等待。

真正停止作业用 `job_kill`；停止子代理用宿主 `interrupt_agent`／管理入口，续谈用 `send_message`。不要重复执行可能有副作用的任务来查进度。

`settled` 不表示子代理永远不会再运行。若最终回答尚未到，先处理其他工作；没有其他工作就报告当前进展并结束回合，让消息自行送达。已经静止的目标会使 `async_wait` 立即返回，反复调用不能把最终文本等出来，也不要另建睡眠作业维持等待。子代理关系与运行状态分别确认，查询失败不能当作 `not_found` 或 `settled`。

多目标返回只陈述已确认状态：读取失败单独标注，已查无的作业标为 `not_found`；到期提示区分全部、部分或无一仍在执行，不把未知状态算成运行中。

### 正常结果直接送达

作业结束时，正文直接附在首次等待返回、进行中的 `async_wait` 返回（`output`／`outputs`）或完成消息中，无需专门调用领取工具。读取会推进已读位置：首次成功读取终态时最终结果只交付一次，后续通常不重放已读内容。及时保存需要留档的结果。

若读取失败，返回会注明失败和重试方法，不是空输出；失败当次不推进增量位置，恢复后用同一零等待调用可取回未读内容。

### 正文截短或条目延后：继续领取

```text
async_wait(wait_ms=0)
```

这用于领取尚未交付的内容。`maxResultChars` 是**同一交付批次**全部结果内容共享的额度，出厂为 12000，按 JavaScript `String.length` 计数，不是字节数。首次等待直付、等待返回与完成消息同批共享；触发本次交付的目标优先，其余按就绪先后分配。每批至多 10 条，空正文条目也计数。

单条超出额度时保留首尾并标出省略量，中段仍在缓冲中，后续批次或零等待可续取；条目超限则延后。两者都不等于宿主缓冲真丢失。状态、必要结局说明、丢失说明和临时文件线索不占正文额度。

`fullCommandEcho=true` 时，后台批次还会附命令或脚本原文，与正文共享额度：正文优先，原文用剩余额度，按 6:4 保留首尾并标出省略量，同批每作业至多一次。首次等待直接结果和查询清单不附原文；命令作业的清单名称为调用的 `description`，编排作业则为 `meta.name`。

### 调用结果可能未送达：请求恢复副本

当宿主把已构造的工具结果改写为取消错误，Agent 可能没收到其中的正文。找回原作业 ID 后，显式点名它并零等待：

```text
async_wait(targets=[{kind:"job", id:"<原job_id>"}], wait_ms=0)
```

尚有未读中段或延后条目时先续取；否则，未被宿主确认送达的份额可按顺序重发，标为“恢复副本／可能重复”。大份额分批按字符位置续取，不反复重发同一切片。确认由宿主处理，无需用户额外点击确认。已确认的内容只返回状态与已交付说明，不能任意重放历史。

恢复副本默认**最多保留 30 分钟**，还受每会话最多 10 条记录、合计 2×`maxResultChars` 字符限制。超限先逐出最旧，插件行卸载时清理，因此可能提前失效，不保证 30 分钟内总能找回。副本不可用时只说明终态事实与已知留存线索，不生成正文。

### 宿主报告缓冲丢失：检查已知留存位置

`lossy` 表示宿主缓冲已经丢失内容，不是上述展示裁剪。宿主若报告 `spillPaths`，会随结果给出这些留存路径，无论是否带 `lossy`；位置由宿主决定。在有权限的环境打开并及时保存所需内容，分享前脱敏。

临时文件可能被清理，也不保证含完整结果。没有返回路径时，本包没有已知找回途径，不应假定磁盘上有完整副本，更不要直接重跑有副作用的命令。

## 5. 模型目录、授权与继承

### 从查询到创建、等待

通常省略模型参数即可使用配置默认或继承；只有需要指定模型，且后端声明支持路由选项时，才走下面的路径。下例 ID 是占位符，须替换为查询返回的准确值。

1. 查询对当前创建工具可用的模型，明确 `target_tool`，避免多个入口的规则混淆：

   ```text
   async_list_subagent_models(query="coding", target_tool="async_agent", page_size=20)
   async_list_subagent_models(provider="<供应商ID>", model="<模型ID>", target_tool="async_agent")
   ```

2. 检查 `verdict` 和 `basis`。需要下一页就原样复用返回的 `next`，版本失效则从第一页重查。`allowed` 只说明对该目标适用，不验证凭据或远端可用性；目录查询不创建子代理、不调用模型推理。
3. 用准确 ID 成对选择供应商和模型，提供自包含任务书；需要强度时使用该模型支持的 `reasoning_effort`：

   ```text
   async_agent(description="Review one isolated item", prompt="<完整任务、材料与完成条件>",
               provider="<供应商ID>", model="<模型ID>")
   async_wait(targets=[{kind:"agent", id:"<返回的agent_id>"}], wait_ms=30000)
   ```

4. 创建立即返回 `agent_id`。保存编号并继续独立工作，依赖结果时再等待目标变化；最终回答作为独立消息到达，不能把 `changed`／`settled` 当作回答正文。

### 当前策略与拒绝

`async_agent` 的显式模型或强度请求在**每次创建**时读取宿主当前策略开关和允许名单，已有会话也适用，启动前再次确认许可。保存策略影响后续创建，不切换运行中的子代理。关闭选择开关会拒绝显式请求；全部省略仍走默认／继承。

读取失败、名单非法或许可撤回时，按真实原因拒绝，不自动换模型。策略值不是对象，或 `allowedModels` 缺席、不是数组、含非对象元素时返回 `policyShapeRejected`；后端路由查询失败返回 `providerQueryFailed`，保留宿主原因，不误报为开关关闭或名单拒绝。

查询的 `allowed`／`not-allowed`／`unconfirmed` 仅针对选定目标，不是通用授权。省略 `target_tool` 时，仅一个可识别候选才自动采用，多或零候选为 `unconfirmed`；具名目标不可见时为 `not-allowed`，目录仍可返回。目录缺席本身不证明模型不支持；部分供应商读取失败时只统计已取得结果。

分页和搜索参数不传给创建工具。被拒时保留目标重新查询，不换入口绕过限制。原生创建工具按自己的会话策略，工作流 `agent()` 也有独立规则，尤其不受 `async_agent` 的供应商／模型成对要求约束。

### 高级行配置：合并与创建前检查

`agentOptions`／`agentPreset`／`allowedAgentPresets` 是固定行配置，不是调用参数，也不属于 20 项界面设置。

- 显式路由或推理强度，或行 `agentOptions` 含 `provider`、`model`、`reasoningEffort`，会触发创建前支持检查（预检）。只有 `maxTokens` 等非路由选项则不触发。
- 触发预检时才合并后端 `agentRouteDefaults`。优先顺序为显式参数 > 行选项 > 后端默认，缺少的路由部分由父路由补齐。允许名单检查仍只针对显式选择，行默认触发预检不使请求变为显式选择。
- 任何一层贡献选项时，创建请求携带合并后的 `agentOptions`；没有贡献则省略，由宿主继承父选项，不额外套用后端路由默认。
- 预检临时采用的兼容父推理强度或模型默认，不会回填创建请求。换路由而未指定强度时，预检不沿用旧路由不兼容的值。最终继承以实际请求与宿主合并为准，不能仅凭预检值推断。

## 6. 提问接管与静默失败

### 开启并找到问题

在设置中开启 `askTakeover` 并保存，它默认关闭。开启后，`boundPresets` 名单内预设的根 Agent 普通提问进入待答面板；计划评审、审批和名单外预设仍走宿主流程。

选择 `sidebar` 时，侧边栏底栏显示未处理问题数，点击展开；选择 `overlay` 时，问题显示在右下角。面板可打开原会话、作答、忽略或增加等待时间。新题以温和的辅助技术提示报告新增数量，不移动当前焦点，不自动朗读整题；倒计时与重复刷新不重复播报。

### 回答或忽略

回答时先确认题型。单选只能选预设选项或自定义回答中的一项；多选可以组合，自定义文本也作为独立答案提交，不是附注。初始没有任何选择，“推荐”不是已选中。点击自定义输入框或输入非空白文本，会选中自定义项；仅移动键盘焦点不会选中。

自定义回答用多行输入框：第一行是选择控件和标题，下方输入框独占可用宽度，初始约三行高，可纵向调整。Enter 键换行、不提交，中文输入法组字确认不会误提交；提交走按钮。答案中的换行与文本原样交付，空白校验与预设选择关系的规则不变。

取消自定义选择后，草稿可以保留，但不会提交。再次点击输入框或输入有效文本会重新选中；清空已选自定义文本不会恢复旧选择。没有选择或选中了空白自定义项时，不能提交，即使多选题还有其他已选项也一样。确实不答时使用独立的“忽略”。服务端同样校验选项和选择关系。

输入法仍在组词时，提交按钮暂时禁用并说明原因，草稿和选择保留；组词结束后重新校验，需要再次明确提交，不会延后自动补发。

### 到期、加时与补答

一次提问调用中的题目共用期限。到期保留已答和忽略状态；未答题返回 `selected=[]` 和说明超时的 `custom`，Agent 继续处理任务，不替用户选择答案。超时未获答复不构成许可——必要决定缺少答复时说明受阻，不把到期当作同意。

需要更多时间时，点击该会话组的增加等待时间。它给点击时尚未到期的批次在原期限上增加 `askExtendMs`，不影响新批次，也不能使已到期批次重新等待。若未收到明确确认，先刷新并核对实际期限，再决定是否重试，避免重复累加。

到期后仍可在面板补答。迟到通知送回原会话，包含完整题干、全部选项与说明、多选关系、实际答案或忽略状态，以及时间。题目选项与实际选择分开，未选中的自定义草稿不会进入答案。

原会话空闲且没有本包待启动投递时，迟答会启动新回合（宿主 `followup`）；否则在会话下一次处理消息时交付（`inject`）。只有宿主接受投递后，本包才唤醒等待。

### 提交未确认或失败

提交后先看确认结果。迟答投递明确失败时，题目会恢复待答状态，可按面板提示重新提交；也可打开原会话直接回复。记录缺席（批次不在册，或题号不在批内）且标有 `undelivered` 时，到原会话直接回复，作答与忽略同判。若只是未收到确认，先等面板刷新核对，不直接断言未送达。`gone` 若表示其他客户端已经回答，不要重复提交。

### 记录保留与请求校验

24 小时是清扫阈值，不是迟答截止时间：到期超过 24 小时的 `expired` 记录，仅在下一次新批接管时清扫，没有新批可能保留更久。迟答不会仅因超过 24 小时被拒。重启或卸载会丢失内存中的过期记录，未结请求交回原生流程；所需答案及时写入原会话。

供调用者排错：`questions` 必须是数组。同一题内标签与说明都相同（或同标签且都无说明）的重复选项，会使整批按可读错误拒绝，面板不显示；同标签不同说明不算重复，多题批次也不部分接管。

### 命令预期有输出，却没有结果

`silentFailureGuard` 默认 `false`。开启后，仅对 `boundPresets` 名单内会话按条件提供结果诊断、工具说明警告和附加操作要求。适用会话第一次看到工具说明时就有警告，无需先执行命令；这与名单直接控制的异步操作要求是两回事。

某些受限环境中，把输出赋给变量、使用子表达式或重定向（例如 `2>&1`）的命令，可能在进程创建前静默失败。**本应有输出却没有，且缺少真实退出信息时，先核实是否执行**，不把空结果当成功，也不凭提示就断定未执行。

在 PowerShell 中可用无害、不捕获输出的 `Write-Output EXEC_CHECK` 核实执行通道，并检查宿主日志。不要重跑可能有副作用的原命令来验证。只有部署确实提供更宽权限参数、同轮命令刚被拒绝且经宿主审批时，才可按规则做一次性重试；没有该入口时不能靠提示提权。

## 7. 高级组合

### 给自建预设挂入全部五工具

自建预设可以使用本包全部异步功能，不必改用随包预设。配置分两步：先挂工具，再决定哪些会话使用操作要求和辅助功能。

1. 在自建预设组合中手工加入下列五工具行。每行 `config.toolName` 选择一个工具；不带 `toolName` 的本包行用于宿主配置，不是自动挂五工具。
2. 将 `async_workflow` 与编排引擎放进同一组，并设置 `isolate: { workflowEngine: true }`，让该工具取得该组的引擎。下例组名为 `delegation`。
3. 核对后文四项宿主服务可解析，安全重新装载后，在自建预设会话中确认五工具可见。
4. 若需要本包异步操作要求，将该预设 ID 加入 `boundPresets` 并保存；若还需要静默失败提示或待答面板，分别打开 `silentFailureGuard`、`askTakeover`。

**绑定名单不会安装工具；挂工具也不会自动加入名单。** 这两个步骤分别控制工具可用性和三项功能的适用范围，关系见[名单与开关](<#适用预设名单与两个开关>)。查询工具可与原生查询并存，自建组合不会自动禁用原有同步工具。

下例包含全部五工具；自建预设的其他功能仍按需要配置：

```yaml
- id: async-run
  name: dsh-async-tools
  config: { toolName: async_run }
- id: async-wait
  name: dsh-async-tools
  config: { toolName: async_wait }
- id: async-agent
  name: dsh-async-tools
  config: { toolName: async_agent }
- id: async-list-subagent-models
  name: dsh-async-tools
  config: { toolName: async_list_subagent_models }
- id: delegation
  name: cordis:group
  group: true
  isolate: { workflowEngine: true }
  config:
    - id: workflow-ptc
      name: '@deepseek-ai/dsh-workflow-ptc'
      config: { provider: spawn }
    - id: async-workflow
      name: dsh-async-tools
      config: { toolName: async_workflow }
```

引擎上下文还须能解析 `subagents`、`ptcRuntime`、`sandboxPolicy`、`workingDirectory` 四项宿主服务。缺少服务时，查看宿主组合和引擎装载日志，补齐合法的服务提供行。重新装载前先确认活动会话与作业已安全收尾。若引擎无法执行当前受限策略，保留真实错误；选择支持该策略的引擎与宿主条件，或停止该编排，不自动升权或绕开沙箱。

## 8. 停用、恢复与报障

**移除前先改默认预设。** 默认若指向dsh-async/dsh-async-create，停用或卸载后新会话报`agent-preset/not-found`，宿主不自动清除。先在宿主设置改为可用预设。已经移除时，在宿主默认预设入口清空或重选，再建会话验证。

停用或移除按以下顺序进行：

1. 用 `job_list` 检查自己的活动作业，完成所需读取，显式停止不需要的任务。重启可能终止活动进程，先安排收尾。
2. 按上一段更改默认预设。
3. 在宿主 GUI 管理本包的安装依赖登记（dependency）与组合声明（bundle），按页面提示重新装载。CLI 操作使用对应宿主版本的管理说明。
4. 新建会话确认可用预设正常；需要恢复时清空或重选默认预设。

删除开发链接不会卸载已加载模块，旧会话可能仍用原组合版本。移除工具不会自动停止由会话启动的作业，须在移除前完成读取和所需停止操作。

命令继承宿主权限、审批、沙箱和宿主提供的执行环境，命令、输出与环境信息都可能含秘密。模型可见注册错误为单行、最多 500 字符，完整错误在操作者日志。检查日志时不要把令牌、cookie、密码、私有 URL 和秘密环境值贴入 issue。

报障使用[项目issue](<https://github.com/MC5Spear/dsh-async-tools/issues>)，提供：完整插件/宿主/Node版本、OS、预设、已脱敏相关设置、最小无害复现、预期与实际状态、job_id/agent_id及时间关系、真实退出标记和脱敏日志片段。保留原任务身份便于查找，不重复运行破坏性命令。个人维护接受issue、不接受外部PR，响应和修复没有固定时限。
