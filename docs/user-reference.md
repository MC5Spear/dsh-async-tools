## 1. 安装身份与前提

| 项目 | 当前适用版本 |
| --- | --- |
| 插件版本 | `0.2.8+dsh.0.2.1-rc` |
| 支持的宿主版本 | `0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5` |

“宿主”指加载插件的 DSH。只有表中四个版本可以加载本包；正式 `0.2.1`、`0.2.0`、`0.2.2` 和未列出的 rc 都不能加载。

建议使用 Node.js 24。包清单虽声明 Node `>=20`，但 DSH 的 commander 15 依赖至少需要 `22.12.0`，不能据此选择 Node 20。其他依赖还可能有更高要求；选择 Node.js 24 以外的版本时，先确认目标 DSH 的全部依赖可用。

### 使用限制与结果保存

Linux 的命令执行和单次提权尚未实机验证；macOS、远程执行环境没有验证结论。rc.3／rc.4 尚未完成全部功能的实机复验。在这些环境中使用前，先用独立测试会话确认所需功能，尤其是命令权限、等待和结果送达。

待答面板尚未用真实操作系统输入法、读屏软件或触屏完成验证。需要这些输入方式时，先确认能够完成选择和提交；面板不可用时，可打开原会话直接回复。

取消工具调用时，DSH 可能把返回结果替换成取消错误，导致 Agent 没看到已经生成的正文。本包提供[有限恢复副本](<#调用结果可能未送达请求恢复副本>)，但这一瞬间的取消与恢复尚未在真实宿主上验证。重要输出及时保存；恢复失败时，先查界面原始记录及结果附带的留存路径，不自动重跑有副作用的任务。

### 安装、固定来源与版本核对

包不从 npm 分发。在终端执行：

```powershell
dsh plugin --profile web add github:MC5Spear/dsh-async-tools#adapt/dsh-0.2.1
```

`web` 是目标 profile（DSH 运行配置）的名称；使用其他 profile 时换成对应名称。GUI 安装则打开 DSH 插件管理页，在安装对话框中填入 `github:MC5Spear/dsh-async-tools#adapt/dsh-0.2.1`。

该地址跟踪会变化的维护分支。需要重复安装同一份源码时：

1. 在仓库中选定可取得的提交。已有目标源码检出时，可运行 `git rev-parse HEAD` 取得完整提交号；尚未上传的本地提交不能用作远端安装来源。
2. 把安装地址 `#` 后的分支名换成完整提交号，再安装。保留实际使用的完整地址，便于以后重装和报障。
3. 安装后打开本包详情页，核对标题旁的版本，或底部“来源信息”中的“当前版本”。同一区域可查看安装来源。版本应与所选源码一致；同一个版本号仍可能对应不同提交，因此固定提交的安装地址也要保留。

安装完成后，在详情页确认设置表单可见。再新建会话，选择 `dsh-async` 或 `dsh-async-create`，确认 Agent 有本参考中的五工具。两份预设随包提供，无需另建预设目录。

### 安装排查

取不到源码时，核对仓库地址、分支或提交号，再检查网络和代理。仍无法获取时，向提供安装来源的维护者询问可用安装件。省略地址中的 `#adapt/dsh-0.2.1`，不会自动选择正确的宿主适配版本。

设置、预设或工具缺失时，按以下顺序检查：

1. 确认 DSH 版本在支持列表内。查看装载日志，处理版本不匹配或依赖缺失的错误。
2. 在目标 profile 的插件管理页确认本包已安装，并已加载其组合声明。安装依赖（dependency）负责提供包，组合声明（bundle）负责启用本包设置行和两份预设；只安装包而未加载组合，入口仍可能缺失。
3. 若刚修改过组合或客户端入口，按宿主提示重新装载实例并重新打开页面。重启可能终止活动进程，先保存所需结果并安排任务收尾。普通设置保存不需要重启。

只需使用插件时按上述方法安装。需要修改源码或配置自建预设时，另见[高级组合](<#7-高级组合>)。

## 2. 首次使用与设置

### 第一次任务

新建会话，选择 `dsh-async` 进行通用编码，或选择还保留插件与预设创作工具的 `dsh-async-create`。两个预设都直接提供五工具，不改动原有预设；查询状态、发送消息和停止任务仍使用 DSH 管理工具。

以下演示使用出厂等待设置。在 Windows PowerShell 环境，可把这段请求发给 Agent：

> 请演示后台执行，不修改文件、不访问网络、不创建子代理。先用 async_run 执行 `Write-Output SHORT_OK`，再执行 `Start-Sleep -Seconds 30; Write-Output LONG_DONE`，第二次显式设置 yield_ms=20000。保存返回的 job_id；需要结果时，用 async_wait 指定该作业并设置 wait_ms=30000。报告两个标记与真实退出信息，不重复执行命令来查进度；编号未收到时先用 job_list 查找。

短命令应直接显示 `SHORT_OK`。长命令在首次最多等待 20 秒后返回 `job_id`；稍后结果随等待返回或完成消息送达，包含 `LONG_DONE`。仍须核对退出信息，运行结束不代表退出码为 0。

以下是 Agent 工具调用示例，不是终端命令：

```text
async_run(command="Write-Output SHORT_OK", description="Print a harmless test marker")
async_run(command="Start-Sleep -Seconds 30; Write-Output LONG_DONE",
          description="Wait then print completion marker", yield_ms=20000)
async_wait(targets=[{kind:"job", id:"<返回的job_id>"}], wait_ms=30000)
```

后台任务运行时先做独立工作，依赖结果时再等待。`wait_ms` 每次必填；出厂正等待范围为 20000–600000 ms，`wait_ms=0` 用于只检查不等待。参数详见[async_wait](<#32-async_wait>)。

### 修改与保存设置

1. 打开插件列表 → 本包详情页。设置表单位于描述和组件列表之间。
2. 修改字段，选择保存。离开页面会丢弃未保存的草稿；保存失败则保留草稿，供修正后重试。帮助按钮只展开说明。
3. 保存后核对值和“已覆盖”标记。合法设置会用于后续调用，无需重启。

写入只允许通过宿主的本机回环地址。页面只读或地址不符时，按页面提示打开可写入口。

设置可能来自三个位置，优先级从高到低是：设置页保存的**用户覆盖**、DSH 组合文件中的预置值、插件出厂默认值。字段只要存在于用户层，就算覆盖，即使数值与默认值相同。

“恢复默认”先暂存删除该字段的用户覆盖，仍须保存，其他字段不受影响。删除后先采用组合文件的值，没有预置才用出厂值。例如组合预置 `45000`，用户改为 `90000`，恢复后得到 `45000`，不是出厂的 `20000`。

### 2.1 全部20项设置

毫秒（ms）用于设置等待时长，1000 ms 等于 1 秒。表中范围是**设置本身可以保存的值**；一次工具调用的等待时长则受当前 min/max 限制，低于下限取下限，高于上限取上限，称为“夹紧”。新非法设置会拒绝保存，不会自动改成边界值。

#### 等待与结果长度

| 字段 | 类型 | 默认 | 可保存范围 | 单位 | 用途与生效时间 |
| --- | --- | --- | --- | --- | --- |
| `defaultYieldMs` | number | `20000` | 1..2147483647，可小数 | ms | 下次 run/workflow 省略 yield_ms 时的首次等待时长 |
| `minYieldMs` | number | `20000` | 1..2147483647，可小数 | ms | 下次 run/workflow 首次等待的请求下限 |
| `maxYieldMs` | number | `600000` | 1..2147483647，可小数 | ms | 下次 run/workflow 首次等待的请求上限 |
| `defaultWaitMs` | number | `30000` | 1..2147483647，可小数 | ms | 工具说明中的等待示例值；不会补全缺失的 wait_ms |
| `minWaitMs` | number | `20000` | 1..2147483647，可小数 | ms | 下次 async_wait 正等待的请求下限；不影响零等待 |
| `maxWaitMs` | number | `600000` | 1..2147483647，可小数 | ms | 下次 async_wait 正等待的请求上限 |
| `pollIntervalMs` | number | `500` | 1..2147483647，可小数 | ms | 新等待检查任务状态的间隔；影响状态变化的发现速度，不延长总等待时长 |
| `maxResultChars` | integer | `12000` | 1..1000000 | JS String.length | 每批交付的结果内容总长度，续取见第 4 节 |

所有数值须有限，并同时满足：

- `minYieldMs <= defaultYieldMs <= maxYieldMs`
- `minWaitMs <= defaultWaitMs <= maxWaitMs`
- `pollIntervalMs <= maxWaitMs`

min 值不是工具必须等满的时间。任务完成或收到适用消息时仍会提前返回。修改配置不会重置正在进行的等待。

pollIntervalMs 可以保存低至 1 ms 的值，但实际检查的定时间隔不会短于 50 ms；设成 1 ms 不会每毫秒查询一次。

#### 执行、语言与结果展示

| 字段 | 类型 | 默认 | 可保存范围 | 单位 | 用途与生效时间 |
| --- | --- | --- | --- | --- | --- |
| `jobKind` | string | `async-command` | 非空字符串 | — | 新命令作业的类型标识，便于在作业清单中识别 |
| `subagentProvider` | string | `spawn` | 后端名称；去首尾空白后为空则用 spawn | — | 后续创建子代理的执行后端，不是模型供应商；改前先确认 DSH 已注册该后端 |
| `uiLang` | enum | `auto` | auto / zh / en | — | 本包设置页和待答面板语言；auto 跟随宿主 |
| `agentLang` | enum | `en` | en / zh | — | 本包工具说明、结果和操作要求的语言，与 uiLang 独立 |
| `silentFailureGuard` | boolean | `false` | true / false | — | 名单内会话的命令静默失败诊断与提示，见第 6 节 |
| `workflowProgressLog` | boolean | `false` | true / false | — | 编排结果中是否向 Agent 保留阶段进度行，不改变界面原始记录 |
| `fullCommandEcho` | boolean | `false` | true / false | — | 新交付批次是否向 Agent 附命令或脚本原文，与正文共享长度额度，见第 4 节 |

#### 提问与适用预设

| 字段 | 类型 | 默认 | 可保存范围 | 单位 | 用途与生效时间 |
| --- | --- | --- | --- | --- | --- |
| `askTakeover` | boolean | `false` | true / false | — | 后续普通提问是否进入待答面板，仅对名单内预设的根 Agent（主会话 Agent）生效 |
| `askTimeoutMs` | number | `60000` | 10000..600000，可小数 | ms | 新一批提问的初始等待时间，不重置已有问题的期限 |

| `askUiSeat` | enum | `sidebar` | sidebar / overlay | — | 侧栏或右下角浮窗；切换不重置期限 |
| `boundPresets` | string[] | `dsh-async, dsh-async-create` | 元素为非空且不重复的预设 ID；允许空数组 | — | 指定操作要求和辅助功能适用的预设，按会话当前预设匹配 |

### 适用预设：名单与两个开关

`boundPresets` 名单控制三项功能：

| 功能 | 生效条件 |
| --- | --- |
| 在 Agent 系统提示中加入异步操作要求 | 当前预设在名单内，无独立开关 |
| 命令静默失败诊断与提示 | 当前预设在名单内，且 silentFailureGuard 开启 |
| 用待答面板处理普通提问 | 当前预设在名单内，且 askTakeover 开启 |

默认名单包含本包两份预设，两个开关默认关闭。取消全部选择并保存，等于保存空数组 `[]`，三项功能便不再绑定任何预设。**名单不会增加或移除工具。** 自建预设仍须先[挂入工具](<#7-高级组合>)；没有绑定的预设即使使用同一工具，也不会获得这些辅助功能。

候选来自 DSH 预设注册表，“刷新”会重新读取。已绑定但当前找不到的预设仍可取消。装载失败条目显示宿主原因，不能新选，但已有绑定可以取消。读取失败时会保留已保存的名单，供取消，不会把失败误显示为没有绑定。

### 配置降级与恢复

看到“配置降级”警示时，表单中的存储值可能不是工具正在使用的值。启动时遇到损坏的布尔值、名单或不合法的字段关系，工具可改用出厂默认值，并保留表单供修复；运行中收到非法配置，则保留上一份合法值。数值或枚举超出定义范围还可能使插件行无法加载，此时从装载日志定位字段。

修复时先改正全部非法字段和字段关系，再保存。即使原样重存损坏配置得到成功应答，警示也不会因此解除。保存后确认警示消失，并核对工具说明中的实际取值；警示仍在时按详细原因或装载日志继续修正。

只有需要预置组合值或迁移旧文件配置时，才需要编辑文件，方法见[文件配置](<#文件配置与旧配置迁移>)。

## 3. 五工具参数与返回

以下参数供 Agent 调用工具，不是终端命令或 DSH 设置。标为必填的参数每次都要提供；不要把未列出的宿主配置键当作调用参数。

### 3.1 async_run

执行一条命令。短命令同次返回结果；超过首次等待时长，返回 `job_id`，命令继续后台运行。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `command` | string | 必填 | 命令原文，使用宿主提供的 PowerShell 或 shell 语法 |
| `description` | string | 必填 | 主动语态的进度说明，5–10 词 |
| `yield_ms` | number | defaultYieldMs | 有限数字，按 minYieldMs..maxYieldMs 夹紧 |
| `workdir` | string | 会话当前目录 | 相对路径以会话当前目录解析；进程启动后目录固定 |
| `sandbox_permissions` | string enum | 条件可选 | 仅有约束执行器时提供，可选模式以当前工具声明为准 |
| `justification` | string | 与 sandbox_permissions 一起提供 | 解释同轮刚被拒绝的原命令为何需要更宽权限重试 |

命令继承会话权限和沙箱。更宽权限只用于同轮刚被沙箱拒绝的原命令的一次性重试，并仍需宿主审批，不用于启动另一项任务。当前工具没有这两个参数时，不能通过传参取得提权入口。

`workdir` 解析或准备失败会返回错误，不会悄悄换目录执行。按错误中列出的请求路径、解析路径和目录检查结果修正；`ENOENT` 也可能来自执行环境，不能仅凭该代码认定工作目录不存在。

根据返回内容继续：

- `status=running`：保存 `job_id`；`elapsed_ms` 表示已过时长，`note` 说明为什么结束首次等待。需要结果时等原作业，不重新执行命令。作业从启动就已登记，可用 `job_list` 查找。
- `status=completed`：读取 `output`，检查 `exit_code`、`signal` 和说明。`completed` 不代表退出码为 0；`signal` 表示进程终止信号。
- `status=killed`：保留 `detail` 和已有 `output`，判断是否还需处理未完成工作。

`truncated` 表示显示内容被截短，续取方法见第 4 节。

### 3.2 async_wait

需要后台结果或消息时使用。它结束的是本次等待，不会停止任务。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `wait_ms` | number | 必填，无默认 | 正值按 minWaitMs..maxWaitMs 夹紧；0 表示只检查不等待 |
| `targets` | array | 可选，默认无目标 | 每项含 kind 和非空 id；kind 为 job 或 agent；重复目标合并 |

以下示例均为 Agent 工具调用：

| 需要什么 | 调用 |
| --- | --- |
| 等任一可处理消息或作业结果 | `async_wait(wait_ms=30000)` |
| 等一个作业结束 | `async_wait(targets=[{kind:"job", id:"<job_id>"}], wait_ms=30000)` |
| 等一个子代理有变化 | `async_wait(targets=[{kind:"agent", id:"<agent_id>"}], wait_ms=30000)` |
| 检查当前状态、续取未交付内容 | `async_wait(wait_ms=0)` |

无目标时，先交付已有结果；没有就绪内容时，只有确认存在自己的运行中作业或子代理，才等待后续消息。确认无工作会立即返回 `no-work`，不会单纯等未来消息。查询失败无法判断时返回 `unconfirmed`，按说明重查。

`targets` 可混合作业和子代理。任一目标达到条件、用户插话或预算到期，等待即交回；非目标通知不会提前打断。作业目标等待终态，子代理目标等待状态变化或目标消息，**子代理最终回答另行送达**。

所有目标先一起校验。某个 ID 无效会拒绝整次调用，先修正目标再等：作业查无时用 `job_list` 核对编号；清单读取失败则重查原目标，不要新建任务。子代理刚创建、目录暂时查无时，正等待可在总预算内重查，至多三个查询周期；零等待不重试。

返回中的 `status` 解释见第 4 节。`waited_ms` 是实际检查和等待耗时；`targets` 提供各目标状态，可见文本至多展示 8 行，更多目标报告数量。作业正文在 `output` 中，同批其他作业在 `outputs` 中，`delivered` 提供交付批次信息。

查询、重试和等待共用本次预算，不逐段重新计时。零等待也要检查状态，可能耗时，全部检查共用 1000 ms 窗口；没能完成的查询标为 `unconfirmed`。正等待预留 300 ms 的调度容差，不能作为精确定时器使用。

### 3.3 async_agent

在后台创建可续谈的子代理，启动后立即返回 `agent_id`，不等最终回答。没有 `run_in_background` 参数。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `description` | string | 必填 | 3–5 词的展示标签 |
| `prompt` | string | 必填 | 完整任务书；默认 spawn 子代理看不到父对话，须附材料、条件和完成目标 |
| `cwd` | string | 继承父当前目录 | 子代理初始目录；相对路径以父当前目录解析，后续切目录互不影响 |
| `provider` | string | 条件可选，与 model 成对 | 准确 LLM 供应商 ID |
| `model` | string | 条件可选，与 provider 成对 | 准确模型 ID，先查询再使用 |
| `reasoning_effort` | string | 条件可选 | 可单独提供，使用最终模型支持的非空推理强度 ID |
| `agent_preset` | string | 条件可选 | 选择允许名单中的子代理预设，配置方法见第 7 节 |

模型参数只在执行后端支持时出现，不支持时传入会报错。`subagentProvider` 设置选择执行后端，默认 `spawn`；调用中的 `provider` 选择模型供应商，两者不同。改用继承父上下文的后端时，子代理可见范围按该后端处理。

通常只需标签和完整任务书，模型使用默认或继承。成功返回 `status=started`、`agent_id` 和说明，包含所用模型的来源；创建被拒绝时不会返回成功编号。保存 ID 后先做独立工作，依赖进展时再用 `async_wait` 等目标变化。需要续谈用 `send_message`，停止用 `interrupt_agent`。

随包预设未配置可选子代理预设，因此不提供 `agent_preset`。指定模型、查询许可和默认继承的说明见第 5 节。

### 3.4 async_workflow

仅用于用户明确要求的 workflow 或大规模多代理编排。一两项委托使用 `async_agent`，无需写脚本。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `script` | string | 必填 | JavaScript 脚本体，允许顶层 await；用 return 返回可 JSON 序列化值 |
| `meta` | object | 必填 | 编排名称、说明和可选的阶段声明，结构见下文 |
| `args` | object | 可选 | 脚本中通过 args 读取的输入；列表应包在对象字段中 |
| `yield_ms` | number | defaultYieldMs | 与 async_run 使用相同的首次等待范围 |

`meta` 是工具参数中的 JSON 对象，不写进脚本：

- `name`、`description` 为必填字符串，名称建议短 kebab-case。
- `whenToUse` 是可选字符串；`phases` 是可选阶段数组。
- 每阶段必填 `title`，可选字符串 `detail`、`provider`、`model`。阶段声明用于进度标记，不自动执行阶段或切换模型。

不要添加其他 meta 或阶段字段，当前引擎会在启动前以 `META_INVALID` 拒绝。`script` 不是 TypeScript 或模块，不写 `export const meta`。

脚本负责协调，实际文件和网络工作交给子代理。脚本环境没有文件系统、网络、定时器或 Node.js API。可用函数如下：

| 函数 | 用法与失败处理 |
| --- | --- |
| `agent(prompt, opts?)` | 返回 Promise，等待一个子代理完成。默认结果是最终文本，普通子代理失败返回 null。opts 只接受 label、phase、provider、model、schema；provider 和 model 可独立覆盖，不要求成对 |
| `pipeline(items, ...stages)` | 每个条目独立流经各阶段，不等全部条目完成前一阶段。阶段收到 (prev, item, index)，可使用上一阶段结果和当前条目。普通阶段异常将该条目置为 null，并跳过其余阶段 |
| `parallel(thunks)` | 并发执行一组零参数函数，并等待全部完成。普通异常使对应结果为 null；只有确实需要全部结果后才能继续时才使用 |
| `phase(title)` | 标记当前进度阶段，title 必须与 meta.phases 中标题完全相同 |
| `log(message)` | 记录进度说明；是否进入 Agent 结果由 workflowProgressLog 控制 |

需要结构化子代理结果时，在 `agent` 的 `opts.schema` 中提供对象根 JSON Schema。支持 `type`、`properties`、`required`、`additionalProperties`、`items`、`enum`、`const`、`oneOf`，不支持 `pattern`、`format` 和数值边界。还可用 `description`、`title`、`default`、`examples` 添加注解，它们不参与校验；前两项为字符串，后两项须能用 JSON 完整表示。提供 schema 后，`agent` 返回通过校验的对象。

例如，将 `args` 设为含 `items` 列表的对象，再用以下脚本逐条审查：

```javascript
const results = await pipeline(args.items,
  async (_, item) => agent(`Review this item: ${item}`, { label: 'Review item' }));
return results.filter(value => value !== null);
```

这个例子只保留成功结果；任务要求报告失败项时，应另行保留条目与失败的对应关系。脚本必须显式返回根值，漏写 `return` 得到 `undefined` 会报运行错误，主动 `return null` 合法。

坏参数、未知选项（如 `effort`、`isolation`、`agentType`）、不支持的 schema 或超过总量/组合上限，会终止整段脚本，不会转成局部 null。并发和总量由宿主限制，并发槽满会排队。

同次完成时返回 `status=completed`，`result` 为渲染后的字符串，不是原始 JSON 对象；后台运行时返回 `status=running` 和 `job_id`，之后通过等待返回或完成消息送达结果。`status=killed` 表示运行被终止，可带 `detail`。停止等待不会取消编排，`job_kill` 才请求取消。缺少引擎时会在启动前报错，不创建作业；自建预设的引擎配置见第 7 节。

### 3.5 async_list_subagent_models

只读查询 DSH 提供的模型目录及选择许可，不创建子代理，也不调用模型推理。不要把显示名称当作模型 ID。

| 参数 | 类型 | 必填/默认 | 规则 |
| --- | --- | --- | --- |
| `provider` | string | 可选 | 准确供应商 ID；不填时可浏览供应商或跨供应商搜索 |
| `model` | string | 可选 | 与 provider 一起查询准确模型详情，含可用推理强度 |
| `query` | string | 可选 | 按 ID 和显示名搜索，忽略大小写及首尾空白；非空时不能与 model 详情同用 |
| `target_tool` | string | 可选 | 要使用的创建工具名称，支持用户配置名称；对当前会话不可见时结论为不允许选择 |
| `page` | integer | 1 | 至少为 1；续页须带 version |
| `page_size` | integer | 20 | 1..100 |
| `version` | string | 首页可省略 | 续页使用上页返回的版本，绑定同一筛选和目标 |

不填 provider 和 query 时列供应商，填 provider 时列该供应商的模型，填 query 时搜索。全空白 query 视为未填；只填 model 会要求补 provider。

```text
async_list_subagent_models(query="coding", target_tool="async_agent", page_size=20)
async_list_subagent_models(provider="<准确ID>", model="<准确ID>", target_tool="async_agent")
```

读取结果时重点看：

- `entries` 是本页条目，`mode` 说明查询方式；`total` 是匹配数量。
- `target` 是判断所针对的工具，`verdict` 和 `basis` 是结论及依据，含义见第 5 节。
- `complete=false` 表示部分供应商读取失败，`failed_providers` 列出失败来源；此时 total 只计已取得结果，不能据此断定其他供应商没有模型。
- 有下一页时直接复用 `next` 对象发起下一次查询，它已包含页码、大小、版本及本次筛选条件。版本失效则从第一页重查，不拼接新旧页。

同版本结果按 ID 稳定排列。超过末页会返回空页及总数，不会跳回第一页。允许名单中的准确 ID 即使没有列在目录中，也仍可查询；目录缺席本身不是“不支持”的结论。

## 4. 等待状态与直接交付

### 先判断等待为什么结束

等待结束不等于任务结束。先看 `status`，再决定处理消息、继续工作还是再次等待。

| 状态或现象 | 含义与下一步 |
| --- | --- |
| `running`，或正等待的 `budget` | 本次等待时长用完。先做独立工作，确实依赖结果时再等原目标 |
| `budget`（wait_ms=0） | 本次即时检查已完成，不表示等待超时。按返回内容和目标状态决定下一步 |
| `interrupted`／`message` | 用户插话或可处理消息使等待提前结束。处理新内容，目标可能尚未完成 |
| `cancelled` 或宿主取消错误 | 本次调用被取消，任务没有因此停止。缺失编号时用 job_list 或完成消息查找 |
| `no-work` | 已确认没有可等待工作；可能一开始就没有，也可能等待期间工作全部结束 |
| `unconfirmed` | 查询失败或超时，无法确认状态。按说明重查原目标，不新建任务 |
| 作业 `completed` | 读取正文并核对退出码 |
| 作业 `failed`／`killed` | 保留错误、信号和已有输出，再决定如何处理未完成工作 |
| 子代理 `changed`／`settled` | 目标有变化，或目前未观察到运行。最终回答另行送达，状态本身不是成功结论 |
| 查询或读取失败 | 重试读取原目标，不重跑任务；失败读取不会把未读正文算作已读 |

用户“插话”会结束等待，“排队”消息留到下一轮，不打断等待。无目标等待也可被代理消息、通知和本包迟到答案唤醒；指定目标时，非目标消息仍留待宿主正常处理。

真正停止作业用 `job_kill`；停止子代理用 `interrupt_agent`，续谈用 `send_message`。如果子代理已 `settled` 但回答还没到，先做其他工作；没有其他工作就报告当前进展并结束回合，让独立消息送达。反复等已静止目标会立即返回，不能据此催出最终文本，也不必创建睡眠作业维持等待。

多目标返回分别说明各目标已知状态。`not_found` 表示确认查无，读取失败则表示未知；不要把未知计作正在运行或已经结束。

### 正常结果直接送达

作业结果直接出现在首次调用的返回、进行中的 `async_wait` 返回或完成消息中，无需另找领取工具。正常读取只发送尚未交付的内容，不能随意重放已读历史。需要留档时及时保存。

读取失败会给出失败说明和重试方式，不是“结果为空”。按提示重试原目标，成功后继续取得未读内容。

### 正文截短或条目延后：继续领取

结果标为 `truncated`、说明省略了中段或有条目延后时，用零等待继续读取：

```text
async_wait(wait_ms=0)
```

多项作业一起进入下一次模型输入时，共享一份结果长度额度，称为一批交付。`maxResultChars` 默认 12000，按 JavaScript `String.length` 计字符，不是字节；不是每个作业各有 12000。触发交付的目标优先，其他按就绪顺序分配，一批至多 10 条，空正文也计一条。

单条过长时先保留首尾，中段留待后续读取；条目过多时整条延后。状态、必要错误说明和留存路径不占正文额度。**展示截短不等于内容已经丢失。**

`fullCommandEcho=true` 会在后台结果中附命令或脚本原文，正文先用额度，原文用余量，过长时按 6:4 保留首尾并标出省略量。同批每作业最多附一次；首次调用直接完成的结果和作业清单不附原文。界面原始调用记录不受这个开关控制。命令在作业清单中使用 description，编排使用 meta.name。

### 调用结果可能未送达：请求恢复副本

如果调用被取消，Agent 没收到原本应出现的正文，先用 `job_list` 找回原作业 ID，再点名它零等待：

```text
async_wait(targets=[{kind:"job", id:"<原job_id>"}], wait_ms=0)
```

尚未交付的中段或延后内容会先送达。没有未读内容时，本包可重发尚未得到宿主送达确认的副本，并标为“恢复副本／可能重复”。大段内容分批续取；已经确认送达的内容只返回状态及说明，不重放正文。送达确认由宿主处理，无需用户另做确认操作。

副本默认最多保留 30 分钟，但每会话最多 10 条记录、合计 2×maxResultChars 字符，超限先删除最旧记录，插件行卸载也会清理，因此可能更早失效。副本不可用时，检查界面原始记录和已知留存路径；没有正文来源时不能保证找回。

### 宿主报告缓冲丢失：检查已知留存位置

`lossy` 表示宿主确实丢失了部分缓冲内容，与上述展示截短不同。结果若附 `spillPaths`，这些是宿主报告的输出留存文件位置，无论有没有 lossy 都可提供。在权限允许时打开，并及时保存所需内容，分享前脱敏。

临时文件可能被清理，也不保证包含完整结果。没有返回路径时，本包没有已知找回途径，不要假定磁盘存在完整副本，更不要直接重跑有副作用的命令。

## 5. 模型目录、授权与继承

### 从查询到创建、等待

“模型路由”指准确的供应商 ID 与模型 ID 的组合。通常省略模型参数，子代理使用默认或继承模型；需要显式选择，且当前执行后端支持时，再按以下步骤操作。示例 ID 均为占位符。

1. 明确要使用的创建工具，再查目录：

   ```text
   async_list_subagent_models(query="coding", target_tool="async_agent", page_size=20)
   async_list_subagent_models(provider="<供应商ID>", model="<模型ID>", target_tool="async_agent")
   ```

2. 读取 `verdict` 与 `basis`：`allowed` 表示目标工具允许选择，`not-allowed` 表示不允许，`unconfirmed` 表示缺少足够信息。allowed 不检查凭据和远端服务可用性。需要续页直接用 next；版本失效从第一页重查。
3. 把查询返回的准确 ID 成对传给创建工具，并提供完整任务书：

   ```text
   async_agent(description="Review one isolated item", prompt="<完整任务、材料与完成条件>",
               provider="<供应商ID>", model="<模型ID>")
   ```

   需要指定推理强度时，再填该模型支持的 reasoning_effort；它也可以单独用于默认或继承模型。
4. 保存返回的 agent_id，先做独立工作。需要进展时再调用：

   ```text
   async_wait(targets=[{kind:"agent", id:"<返回的agent_id>"}], wait_ms=30000)
   ```

   等待返回目标变化，最终回答作为独立消息送达。需要追问同一子代理时，用 send_message 续谈，不再创建一个子代理替代。

### 当前策略与拒绝

选择权限由 DSH 的子代理模型选择开关和允许名单管理，不在本包设置页中另设一份。显式选择模型或强度时，`async_agent` **每次创建**都读取当前策略，并在启动前再次确认许可；已有会话也采用新设置。保存影响后续创建，不切换运行中的子代理。

关闭模型选择开关会拒绝显式 provider、model 或 reasoning_effort；全部省略时仍使用默认或继承。名单非法、读取失败或路由被撤回时会说明原因，不自动换模型。策略数据损坏需由实例维护者修正；执行后端查询失败则需检查宿主错误，两者都不能靠随意换一个模型解决。

许可总是针对一个创建工具。省略 target_tool 时，仅有一个可识别入口才会自动选中；多个或没有入口时结论为 unconfirmed。具名入口对会话不可见时为 not-allowed，仍可能返回目录信息。

原生创建工具使用自己的会话策略，工作流 agent() 也有独立规则。不要把 async_agent 的许可或参数要求套给其他入口；分页、搜索参数也不能传给创建工具。创建被拒后，保留原目标重新查询，不换入口绕过限制。

自建预设若预置子代理默认模型，继承和覆盖的具体规则见[子代理默认值与可选预设](<#子代理默认值与可选预设>)。

## 6. 提问接管与静默失败

### 开启并找到问题

开启 `askTakeover` 并保存后，boundPresets 名单内预设的根 Agent 普通提问进入待答面板。审批、计划评审、子代理提问和名单外预设仍由 DSH 处理。

askUiSeat 为 sidebar 时，侧边栏底部显示未处理问题数，点击展开；为 overlay 时，问题显示在右下角。面板可打开原会话、回答、忽略或加时。新问题会向辅助技术提醒新增数量，不抢键盘焦点、不自动朗读整题；倒计时不会反复播报。

### 回答或忽略

单选题只能选择一个预设选项或自定义回答；多选题可以组合选择，自定义文本也是一个独立答案，不是选项的附注。初始不选任何项，“推荐”也不表示已经选中。

自定义回答使用多行文本框，标题和选择控件在上方，输入框在下方，约三行高，可纵向调整。点击输入框或输入非空白文本会选中自定义项；只用键盘移入焦点不会改变选择。Enter 换行，提交使用按钮。输入法仍在组词时，提交暂时禁用；结束组词后要重新明确提交，不会自动补发。

取消自定义项后可保留草稿，但不会发送。清空已选自定义文本则仍保持选中，需要填入有效文本或取消该项。没有任何选择，或选中了空白自定义项，都不能提交，即使多选题还有其他已选项也是如此。确实不答时，使用独立的“忽略”。

答案正文和换行原样交付；未选中的选项和草稿不会进入答案。

### 到期、加时与补答

一次调用中的题目共用期限，默认 60 秒。到期后已答和忽略的状态保留；未答题向 Agent 返回 `selected=[]`，并在 custom 中说明超时，Agent 不会代选答案。**超时不是许可**：缺少必要决定时仍须说明无法继续的原因。

需要更多时间时，点击会话组的增加等待时间。它在点击时尚未到期的各批次原期限上增加 askExtendMs，默认再加 60 秒；不影响新题，也不能重新开启已到期调用。没收到确认时先刷新核对实际期限，避免重复加时。

到期后仍可在面板补答或忽略。通知返回原会话，包含完整问题、选项及说明、实际答案或忽略状态和时间，便于 Agent 判断答案针对什么。原会话空闲且没有本包消息等待启动时，迟答会启动新回合；否则在会话后续处理消息时收到。只有宿主接受通知后，才会唤醒无目标的 async_wait；指定作业或子代理的等待不会被无关答案打断。

### 提交未确认或失败

提交后先看面板回执。明确投递失败时，问题恢复待答，可按提示重试，也可打开原会话直接回复。若面板说明批次或题目已不存在且答案未送达，应到原会话回复。只是没收到确认时，先等面板刷新再判断；若显示其他客户端已经作答，不要重复提交。

过期记录只保存在内存中。到期超过 24 小时的未处理记录，在下一批新问题接管时清理；没有新批时可能保留更久，所以 24 小时不是固定迟答截止。重启或卸载会丢失这些记录，未结束的提问交回宿主流程。重要答案及时写入原会话。

调用提问被整批拒绝时，检查 questions 是否为数组，以及同题是否有标签和说明都相同的重复选项。同标签不同说明可以使用；一批多题不会只接管其中部分。

### 命令预期有输出，却没有结果

`silentFailureGuard` 默认关闭。开启后，对 boundPresets 名单内会话提供命令诊断、工具说明警告和操作要求；它用于提醒核实执行情况，不替代宿主执行日志。

某些受限环境会让带输出捕获的命令静默失败，例如把输出赋给变量、使用子表达式或 `2>&1`。预期输出缺失，且没有真实退出信息时，不要把空结果当成功，也不要直接断定原命令未执行。

先用无害、不捕获输出的 `Write-Output EXEC_CHECK` 检查 PowerShell 执行通道，再查看宿主日志。不要重跑有副作用的原命令来试验。只有当前工具提供更宽权限参数、原命令同轮刚被拒且宿主批准时，才可一次性重试；提示本身不会增加权限。

## 7. 高级组合

本节供编辑 DSH 组合和自建预设的作者使用。普通安装只需选择随包预设；调整等待、语言和提问功能优先使用设置页。

### 文件配置与旧配置迁移

DSH 组合由插件“行”组成，每行用 name 选择插件，用 config 配置这一行。本包有两种行：

- **宿主配置行**：ID 为 async-tools-host，不带 toolName。它提供共享设置、设置页面和提问服务，随安装包自动加载。
- **工具行**：放在预设的插件列表中，config.toolName 指定本行注册哪个工具。

要预置第 2 节的设置，修改目标 profile 的覆盖文件，不编辑安装包。先确认目标实例实际使用的 DSH_HOME：未设置时默认为操作系统用户目录下的 `.dsh`，服务启动器也可能另设目录，不能从当前终端默认值推断。

1. 找到 `<实际DSH_HOME>/profiles/<profile>/cordis.patch.yml`。需要查看组合时，在同一 DSH 安装、同一 DSH_HOME 下运行 `dsh --profile web --dump-config`（其他 profile 替换 web）。它是只读输出，不会查询运行中实例；内容可能含私有配置，不要直接公开。
2. 在覆盖文件中找到 ID 为 async-tools-host 的项；尚无覆盖项时添加下例。已有覆盖时，将需要的值合入原项的 config.settings，**保留原有其他设置**。宿主按整份 config 替换，不做深合并；不要再追加第二份同 ID 覆盖，以免丢掉已有预置。

   ```yaml
   - id: async-tools-host
     config:
       settings:
         agentLang: zh
         defaultYieldMs: 30000
   ```

3. 保存文件后，先安排活动任务安全收尾，再按宿主要求重新装载。打开设置页和新会话，核对实际取值；设置页保存的用户覆盖仍优先于文件预置。

0.2.5 形态的平铺配置，例如 `config: { agentLang: zh }`，在 0.2.8 不生效。升级前改成 `config: { settings: { agentLang: zh } }`，其他设置同样移入 settings。否则行可能加载成功，但语言、等待时长和开关回到默认；清除用户覆盖也不能修复放错位置的值。装载日志可能列出被忽略的平铺键，迁移后仍须读回核对。

工具通常使用宿主配置行提供的共享值。该行未接入时，工具才采用工具行中合法的 settings 备用值并给出警告；若设置页已保存但工具仍报“设置未接入”，先修复宿主配置行，不继续在各工具行重复配置。

### 从完整预设创建自建预设

尚无自建预设时，从随包的完整预设复制，保留命令、子代理和编排所需的基础服务，不从几个工具行拼空外壳。

1. 打开随包分发的[完整异步预设](<../presets/dsh-async.patch.yml>)。复制其中整份 `- insert:` 声明，包括内部完整的 config.plugins 列表。
2. 找到上一节说明的目标 profile 覆盖文件。保留文件原内容，把复制的声明作为新的顶层列表项追加；不要覆盖原文件。
3. 只改外层预设声明的身份：将声明行 id 从 preset-dsh-async 改为唯一值，例如 preset-my-async；将其 config.id 从 dsh-async 改为 my-async，config.name 改为新的显示名，也可修改 description。保留 config.plugins 内部全部内容，不全局替换 dsh-async，也不再插入一份使用原 ID 的预设。
4. 保存并安排活动任务收尾，按宿主要求重新装载。新建会话，选择新的显示名或 ID，确认五工具可见。
5. 在插件设置的 boundPresets 中选择 my-async 并保存，让新预设获得异步操作要求。候选尚未出现时先刷新名单；静默失败提示和待答面板仍需分别开启对应开关。

之后只在复制得到的预设中调整工具和默认值。它保留原预设的基础服务与异步入口，随包原预设不受影响。

### 给已有自建预设挂入全部五工具

已有自建预设、希望保留其组成时，把以下行合入该预设的 config.plugins 列表。片段不是独立预设，不能代替前面的完整复制路径；它也不会自动禁用原有同步工具。

```yaml
- id: async-run
  name: dsh-async-tools
  config: { toolName: async_run }
- id: async-wait
  name: dsh-async-tools
  config: { toolName: async_wait }
- id: async-agent
  name: dsh-async-tools
  config: { toolName: async_agent }
- id: async-list-subagent-models
  name: dsh-async-tools
  config: { toolName: async_list_subagent_models }
- id: delegation
  name: cordis:group
  group: true
  isolate: { workflowEngine: true }
  config:
    - id: workflow-ptc
      name: '@deepseek-ai/dsh-workflow-ptc'
      config: { provider: spawn }
    - id: async-workflow
      name: dsh-async-tools
      config: { toolName: async_workflow }
```

前四行分别挂工具；最后一组把编排工具与引擎放在一起。workflowEngine 隔离使这组工具使用本组引擎；把 async_workflow 放到组外可能取不到引擎。有现成 delegation 组时先合并，避免重复组或重复工具行。

引擎还需要 DSH 的 subagents、ptcRuntime、sandboxPolicy、workingDirectory 服务。缺少服务时，从组合与引擎装载日志定位缺失的提供行；不要删除依赖检查来强行启动。若引擎无法执行当前沙箱策略，选择支持该策略的引擎和宿主配置，或停止编排，不自动升权。

安全重新装载后，新建使用该预设的会话，确认五工具都可见。再按需将预设 ID 加入 boundPresets 并保存，以获得异步操作要求；需要命令提示或待答面板时，再分别开启 silentFailureGuard、askTakeover。**挂工具不等于绑定，绑定也不挂工具。** 查询工具可与原生查询共存。

### 子代理默认值与可选预设

以下字段放在 **async_agent 工具行的 config** 中，与 toolName 同级，不放进 settings，也不是 Agent 的调用参数。修改后按组合配置重新装载。

| 字段 | 类型与作用 |
| --- | --- |
| `agentOptions` | 对象，可预置 provider、model、reasoningEffort 字符串，以及正整数 maxTokens（最大 Number.MAX_SAFE_INTEGER） |
| `agentPreset` | 非空字符串，子代理默认预设 ID；未配置时继承父预设 |
| `allowedAgentPresets` | 可选择的非空预设 ID 数组；提供时至少一项且不能重复，agentPreset 若同时提供必须在其中 |

例如，将已有 async-agent 行改为以下形态，即可在后端支持独立预设时允许 Agent 选择 reviewer 或 writer。两个 ID 必须已在目标 DSH 中注册：

```yaml
- id: async-agent
  name: dsh-async-tools
  config:
    toolName: async_agent
    agentPreset: writer
    allowedAgentPresets: [reviewer, writer]
    agentOptions:
      maxTokens: 4096
```

配置允许名单后，且后端支持独立预设选择，工具才显示 agent_preset。它与 boundPresets 不同：前者允许父 Agent 选择子代理的预设，后者决定哪些会话使用本包辅助功能。没有 allowedAgentPresets 时不提供选择参数；空数组非法。

预置模型时，先查询准确 ID，再写 agentOptions.provider/model；配置键 reasoningEffort 使用驼峰，调用参数 reasoning_effort 使用下划线。模型默认值按以下顺序确定：

1. 本次显式参数优先于工具行默认值。
2. 请求显式模型/强度，或工具行预置 provider、model、reasoningEffort 时，会先检查有效模型是否受支持，并把执行后端的 agentRouteDefaults 作为更低优先级默认值。缺项由父代理模型补齐。
3. 工具行只有 maxTokens 等非模型选项，或完全没有默认选项时，不额外套用后端模型默认值；模型仍由宿主按父代理值继承。没有任何选项时，创建请求也不附 agentOptions。

显式模型选择才受 DSH 当前允许名单检查，工具行预置值触发支持检查不意味着本次变成显式选择。变更模型却没有指定强度时，检查不会照搬旧模型不兼容的强度；检查临时采用的兼容值也不会写回创建请求。需要确定强度时显式指定支持的 reasoning_effort，最终模型与继承来源以创建回执为准。

### 开发链接

只有需要修改插件源码时才用开发链接，稳定部署不要链接正在编辑的目录：

```powershell
git clone https://github.com/MC5Spear/dsh-async-tools.git
cd dsh-async-tools
git checkout adapt/dsh-0.2.1
npm install
dsh plugin --profile web add <克隆目录的绝对路径>
```

链接目录须能解析匹配的宿主依赖。安装后仍按第 1 节确认设置、预设和五工具均已加载；单独用 Node 导入模块不能确认这些入口。

## 8. 停用、恢复与报障

停用或卸载按以下顺序进行：

1. 用 job_list 检查活动作业，读完并保存所需结果，用 job_kill 显式停止不需要的作业。子代理另用 interrupt_agent 停止。移除工具不会自动停止会话启动的工作。
2. 在 DSH 设置中更改默认预设。若仍指向 dsh-async 或 dsh-async-create，移除后新会话会报 `agent-preset/not-found`，宿主不会自动清除选择。
3. 在目标 profile 的插件管理页停用或移除本包的组合声明与安装依赖，按宿主提示重新装载。重启可能终止活动进程，先确认收尾完成。CLI 操作使用对应 DSH 版本的管理说明。
4. 新建会话，确认可用预设正常工作。若已移除后才遇到 not-found，到宿主默认预设入口清空或重选，再新建会话。

删除开发链接目录不会卸载内存中的模块，旧会话也可能继续使用原组合；不要以目录已删除判断工具已经停用。

报障使用[项目 issue](<https://github.com/MC5Spear/dsh-async-tools/issues>)。附上插件、DSH、Node 完整版本，操作系统、预设、相关设置，以及最小无害复现。后台问题同时保留 job_id/agent_id、事件顺序、真实退出信息和相关日志，不重复运行破坏性命令来补材料。

命令、输出和环境信息可能含秘密。公开前删除令牌、cookie、密码、私有 URL 和秘密环境值；模型看到的部分错误只保留单行、最多 500 字符，排障需要完整原因时由实例操作者查看宿主日志，再脱敏提供。

项目由个人维护，接受 issue，不接受外部 PR，响应与修复没有固定时限。
