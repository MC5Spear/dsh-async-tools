# 发布前待处理问题清单

本清单记录当前需要修正的缺陷、验证缺口和待处理事项。修正后删除对应条目，历史由 Git 保存；删除条目不代替独立复核。当前尚不具备发布条件，已有测试通过不能替代下列行为的验证。

范围为本公开仓库的 `adapt/dsh-0.2.1` 分支，目标版本 `0.2.8+dsh.0.2.1-rc`。批准目标以[需求](<requirements.md>)为准。`maxResultChars=12000` 已确定，不再作为待决策建议；[GB-01（Windows Git Bash 开关）](<requirements.md#92-gb-01windows-git-bash-开关暂缓>)继续暂停，不纳入本轮实施与验收。推送、标签和 Release 需另行授权。

本清单中的既有实测取自 2026-11-01 对提交 `e933b30` 及需求工作区的受控探针和隔离实例检查；WAIT-EMPTY-01 与 WAIT-GUIDE-01 是按当前等待要求对同一实现进行静态核对确认的差距，YIELD-DEFAULT-01 是首次等待默认下限调整后的静态差距，均尚未完成对应行为验收。UI-ASK-01 依据用户实际页面截图及当前客户端结构登记。替身、静态检查和真实运行分别说明，不相互代替。优先处理第一节的交付可靠性与等待缺陷、YIELD-DEFAULT-01 和 RESULT-01 默认值以及 SAFE-01 的重复执行风险；第二节除 DOC-OPT 外同样是本轮必改项。

## 一、结果交付与等待缺陷

### WAIT-EMPTY-01：缺少挂起条件检查，无工作或静止对象仍可耗尽等待预算

[当前统一等待](<../lib/wait.js#L328-L336>)只按显式目标构造等待对象；[入口检查](<../lib/wait.js#L528-L633>)不在省略目标或空列表时查找本主体可等待的工作。[正等待循环](<../lib/wait.js#L776-L818>)可直接等待消息或预算，未实现“确认无工作立即返回”和“无法确认等待条件”两类出口；[静止子代理入口](<../lib/wait.js#L609-L633>)也没有在无新变化、无其他可等待工作时拒绝挂起。此处静态差距按[需求 9.3.1](<requirements.md#931-等待条件目标检查与唤醒>)登记，不作为已完成的行为实测。

- **处理**：补齐指定／未指定目标的工作检查，已就绪消息、结果和变化先按规则交回；仅有已确认非终态作业或运行中合法子代理时允许挂起。自动检查不扩大权限，显式目标不借列表外工作取得资格。区分无工作、条件未确认、目标终态、实际取消和预算到期；状态未知不伪造运行或结束。挂起后确认已无可等待工作时及时交回，不因结果读取失败继续等已结束工作；检查及必要状态观察共用总预算，退出不终止后台工作、不阻断后续交付。
- **完成条件**：按[9.3.6 第 1、2、6、11、12 项](<requirements.md#936-可判断的验收结果>)覆盖空列表、未指定目标、终态作业、静止子代理、混合目标、查询失败／挂起、检查与事件交接、工作全部结束及零等待。真实长任务不返回时等待仍有界，后台工作继续；不能用“没有指定目标”代替“没有可等待工作”。入口既有结果的读取与交付同时遵守 WAIT-READY-01、WAIT-READ-01，子代理状态通道与基准问题仍按 WAIT-AGENT-01/02 分别修正。

### WAIT-GUIDE-01：等待说明缺少工作前提，到期提示把再次调用当作默认下一步

[英文工具描述与参数](<../lib/text.js#L364-L379>)及[中文对应文案](<../lib/text.js#L725-L740>)仍将未指定目标解释为直接等待未来消息，并在预算到期后提示再次调用。[英文预设纪律](<../lib/text.js#L340-L341>)与[中文预设纪律](<../lib/text.js#L701-L702>)没有明确阶段完成后结束回合、后续消息再驱动的分工。[设计的无目标等待](<design.md#L403-L405>)也缺少工作前提；[中文首页工具表](<../README.md#L59-L65>)仍以消息等待概括职责。上述说明与[需求 3.1](<requirements.md#31-两个预设>)、[9.3.5](<requirements.md#935-工具可见性与提示一致性>)存在差距。

- **处理**：统一设计、工具描述、参数说明、两预设纪律、返回提示及两语公开资料，明确无工作不挂起，阶段完成只等后续派工时报告并结束回合。到期后重新判断，不自动续等或为保持活跃增加预算；延时、监控和外部条件使用真实任务或相应调度，不无条件建议另建睡眠作业，也不靠等待次数或长期无输出自动判定死循环、终止任务。保留有效依赖下的有界等待、零等待和未交付内容恢复，说明普通通知仍按宿主机制投递。
- **完成条件**：中英文规则一致，不只检查固定句子是否出现；按[9.3.6 第 13 项](<requirements.md#936-可判断的验收结果>)用真实模型验证阶段完成后不空等、父代理后续消息可续接，并以实际运行中依赖及延时／监控任务作正向对照。原等待用例和夹具按新要求修订，不能继续把无工作耗尽预算或反复等待静止对象当作正确行为；未验行为不得写成已通过。

### YIELD-DEFAULT-01：首次等待下限默认值尚未调整为 20 秒

[需求 5.2](<requirements.md#52-默认值与范围>)已确定命令与编排共用的 `minYieldMs` 默认值为 `20000` ms，`defaultYieldMs` 仍为 `20000` ms、`maxYieldMs` 仍为 `600000` ms。当前[配置定义](<../lib/config.js#L132-L134>)的 `minYieldMs` 默认仍为 `1000`；秒级命令可因模型显式请求短预算而转后台，后续等待发起时已完成，增加消息交接和辨认成本。此项按静态差距登记，不把调高下限当作结果交付缺陷已经修复。

- **处理**：更新真实默认值和适用的备用值，同步设计、两语公开资料、工具描述与参数、设置说明、测试及未发布版本说明。仅在宿主配置行和用户层均无该字段时应用新默认；保留已有合法显式设置，包括低于新默认的下限。恢复默认只清用户覆盖，再按配置优先级取值；安装或升级后的实际生效值须核对，不能只凭源码默认值推断。设置字段合法范围和配对规则不变，不将 `20000` 变成配置字段的固定最小合法值；不调整 `async_wait` 的正等待下限。
- **完成条件**：按[需求 8.2“首次等待默认下限”](<requirements.md#82-必须证明的结果>)分别验证 `async_run`、`async_workflow`：无覆盖且请求 `yield_ms=1000` 时有效首次预算为 `20000`；数秒内完成直接交付、不等满预算，超过预算则返回句柄且作业继续；用户插话和取消仍及时结束等待。覆盖宿主与用户层合法显式值、升级保留、恢复默认、后续调用及中英文描述刷新；真实结果只交付一次且可恢复的要求仍由 WAIT-READ-01、WAIT-RECOVER-01、WAIT-COMMIT-01 等条目验证。

### RESULT-01：落实 12000 默认值，保留已有显式配置

[需求 5.1–5.2](<requirements.md#51-来源生效与失败处理>)已确定 `maxResultChars` 默认 `12000`，当前[配置](<../lib/config.js#L157>)及[命令备用值](<../lib/jobs.js#L322>)仍为 `30000`；[中文参考](<user-reference.md#L81>)、[英文参考](<user-reference.en.md#L81>)和测试也沿用旧值。本次隔离实例设置接口确认无用户覆盖时仍返回 `30000`。

- **处理**：更新实际默认值与备用值，同步设置说明、设计、两语资料、测试和未发布版本说明。宿主配置行和用户层均未设置该字段时采用新默认；保留全部已有合法显式值，包括显式 `30000`。恢复默认并保存只清除用户覆盖，随后按配置优先级取值。核对 `outputLimitBytes` 换算与宿主读取行为，不能把它误述为环形缓冲留存容量。
- **完成条件**：无覆盖、宿主覆盖、用户覆盖、升级保留、恢复默认及后续调用生效分别有验证；范围、字符计量和共享批次规则不变。

### RESULT-02：首次等待直接结果未先分配批次剩余额度

[命令直接返回](<../lib/jobs.js#L1132-L1155>)与[编排直接返回](<../lib/workflow.js#L476-L487>)先各按完整上限构造结果，再由[交付登记](<../lib/delivery.js#L299-L342>)扣减余额。本次同主体、同批预算 `100` 的两个并行命令各返回 `80` 字符，合计 `160`；两个并行编排同样超限。

- **处理**：首次等待结果在构造返回前参与共同分配，与等待返回及完成消息共用批次和交付事实。额度不足时裁剪，耗尽时保留未交付条目并提供继续方式。
- **完成条件**：命令、编排及混合载体并行时，保留正文合计不超过一份生效预算；覆盖额度耗尽、延后、取消和失败重试，不重复、不丢失。不能用事后把余额减到零代替分配。

### WAIT-READ-01：读取失败被当成空结果交付，后续重试仍收不到正文

[结算读取](<../lib/delivery.js#L440-L489>)失败后已写入终态；[批次收集](<../lib/delivery.js#L578-L626>)仍把空条目标为已交付。同步抛错还可能使 `readInFlight` 留下已失败的 Promise。本次分别强制同步抛错和异步拒绝：第一次返回空正文并登记交付，恢复读取后仍无法正常取得结果。

- **处理**：区分已证实终态、读取成功、正文就绪和已经交付；读取失败立即给模型可见标记及 `async_wait` 重试方式。清除失败的在途读取，不消费未成功取得的最终结果，不把失败空条目标为已交付。
- **完成条件**：同步失败、异步失败、失败后成功、并发重试及无输出成功均可区分；恢复后正文恰好交付一次。不得要求重跑原任务。

### WAIT-RECOVER-01：裁剪时清空原文，未交付中段没有恢复路径

[批次分配](<../lib/delivery.js#L619-L666>)按首尾裁剪后清空整段缓冲并标为已交付；完成消息也在[构造时清空](<../lib/delivery.js#L730-L750>)。本次将正文预算设为 `10`，第一次只收到首尾和省略标记，第二次等待仅称已交付；中段已从宿主游标消费，却没有可用副本或继续方式。

- **处理**：按[需求 9.3.2](<requirements.md#932-作业内容首次交付>)保留已消费但尚未交付内容的恢复方式，或交付确实存在的完整输出位置。区分本包裁剪、宿主输出丢失和整条延后；不能以截断标记或“已交付”代替找回方式。
- **完成条件**：首次直接结果、等待返回、完成消息及运行中增量的裁剪均可解释省略范围；未交付内容可以按说明恢复，确无副本的宿主丢失则如实说明，不虚构路径。

### WAIT-STATUS-01：模型可见结果丢失目标身份、真实结局和留存位置

[等待渲染](<../lib/wait.js#L294-L308>)只拼 `output/note/outputs`，触发作业被排除在附加条目之外，其 `job_id`、终态及详情未进入模型文本。本次非零退出只显示输出，信号终止只显示部分输出，失败且无输出渲染为空串。宿主给出 `spillPaths` 但 `lossy=false` 时，触发目标的路径也未显示。

- **处理**：所有出口在模型实际收到的文本中保留归属、真实终态、非零退出／信号／引擎失败原因及宿主报告的输出位置；必要诊断独立于可关闭日志和正文额度。同步 schema、结果对象与渲染，不能仅在结构化字段中存在。
- **完成条件**：真实非零命令、显式终止、编排失败、无输出成功、无输出失败和有／无 `lossy` 的 spill 均经宿主输出校验及渲染验证；其他目标已证状态也在模型需要时可见。

### WAIT-TIME-01：入口慢查询不受总预算、插话和取消约束

[子代理入口查询](<../lib/wait.js#L597-L608>)直接等待 `listChildren`，没有与总截止、消息和取消竞速。本次查询耗时约 `450 ms`，`wait_ms=25` 实耗约 `460 ms`；零等待同样阻塞。第 `15 ms` 到达的插话或取消也要等查询完成才返回。

- **处理**：入口查询、存在检查、诊断、重试和必要返回处理共用一份截止；慢调用不得阻塞已满足的插话、取消或预算出口。零等待只做立即检查，不启动额外等待或重试；无法立即证实的状态保持未确认。
- **完成条件**：慢／悬置查询、忽略取消信号的服务、消息和取消在准备阶段到达、零等待分别有受控验证；不重置或抬高剩余预算，不将查询失败说成查无。

### WAIT-WAKE-01：非目标迟到作答提前结束有目标等待

[迟到作答入口与竞速出口](<../lib/wait.js#L682-L694>)、[正等待入口](<../lib/wait.js#L762-L773>)及[事件出口](<../lib/wait.js#L943-L949>)无条件返回 `message`。本次等待运行中作业，另一题迟到答案到达后提前返回，目标尚未终结。[设计](<design.md#L94>)还将此行为写成例外，与[批准规则](<requirements.md#931-等待条件目标检查与唤醒>)及两语用户参考冲突。

- **处理**：按当前需求修正设计和实现：未指定目标时，可处理答案在入口立即交回，满足工作前提的活等待也可被其唤醒；指定目标等待不因非目标迟到答案提前结束，答案仍按宿主正常领取语义交付。先到答案和等待中新到答案一致，未指定目标的挂起条件按 WAIT-EMPTY-01 处理。
- **完成条件**：纯作业、纯子代理、混合目标、无目标及先到／后到答案均验证；用户插话仍及时结束等待。现有规则已批准，不需要重新决定；只有拟改变规则时才申请需求变更。

### WAIT-TARGET-01：其他目标未校验便从首个满足条件的目标返回

[入口终态分支](<../lib/wait.js#L528-L596>)早于后续子代理存在性检查。本次目标列表为“已完成作业＋不存在的子代理”，调用返回完成并把不存在目标列为运行中，没有拒绝非法目标。

- **处理**：在按任一目标返回之前完成所有请求目标必要的类型、可见性和关系校验，仍遵守总预算及取消；不能因列表顺序跳过校验或制造已知状态。
- **完成条件**：合法目标与查无、无权、错误类型、查询失败目标按不同顺序混合均有验证；查无和查询失败分开，不泄漏不可见目标的存在性。

### WAIT-READY-01：无目标等待不检查入口已经就绪的账本内容

本次先在账本保留已读取、尚未交付的终态正文，再开始无目标等待；调用仍等完整预算后以“没有可处理消息”返回，同时附上正文。[当前入口](<../lib/wait.js#L528-L762>)主要扫描消息及显式目标，依赖新就绪事件而漏掉既有内容。

- **处理与完成条件**：无目标入口发现可交付正文或必要终态条目时立即交回，并说明实际原因；不能等一个不会重发的事件。覆盖多个活等待、完成消息让位及取消后的缓冲保留，不重复正文。

### WAIT-AGENT-01：等待期间状态变化通道未接通，备用检查未执行

[观察器](<../lib/interrupts.js#L391-L410>)要求关系确认后调用 `proveRelation()`；[统一等待](<../lib/wait.js#L597-L633>)未完成接线，且等待循环没有按 `pollIntervalMs` 执行备用状态检查。本次子代理从运行转空闲，即使发出 `agent/status`，仍等到预算耗尽；不发事件时同样漏报。

- **处理与完成条件**：关系证据确认后启用状态事件，按生效间隔进行受总预算约束的备用检查；捕获关系确认前后变化，及时报告一次，不把未知当变化，不把静止反复作为新事件。普通消息、提问和结算继续由宿主交付，不复制正文。

### WAIT-AGENT-02：重复观察静止状态会污染跨调用基准

[统一等待入口](<../lib/wait.js#L609-L632>)在无需新报告时仍无条件写入 `running`。本次同一主体／目标依次为 idle→idle→running：第一次报告静止，第二次应保持登记却改为运行，第三次恢复运行的真实变化被吞掉；未知观察也可能误写运行基准。

- **处理与完成条件**：基准只记录实际向该主体报告的公开状态；同态保持，未知不伪造。覆盖 idle／absent 重复观察后恢复、unknown 后变化、不同主体隔离及查无清除；重复静止不报新变化，也不单独取得挂起资格，立即返回行为按 WAIT-EMPTY-01 验证，与等待期间观察通道分别处理。

### RESULT-03：完成消息绕过批次条目数及说明总量限制

[等待批次](<../lib/delivery.js#L610-L637>)限制单次收集条目，但[完成消息投递](<../lib/delivery.js#L703-L807>)未使用同一条目额度。本次同主体一次让位复查投出 `12` 条完成消息，超过[设计 2.6](<design.md#L175>)的单批 `10` 条；说明限制也主要按单条或单载体计算，不能证明跨载体批次合计有界。

- **处理与完成条件**：首次返回、多个等待及完成消息按主体同批共享条目数和说明额度；超限延后并给紧凑继续方式，保留身份及必要结局。验证分多次收集、忙碌／空闲投递、长标识和多留存路径，不以正文已限额代替说明总量限制。

### WAIT-COMMIT-01：交付构造与模型实际收到之间的防丢失保证尚未成立
