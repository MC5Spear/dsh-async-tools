# 发布前待处理问题清单

本清单记录当前需要修正的缺陷、验证缺口和待处理事项。修正后删除对应条目，历史由 Git 保存；删除条目不代替独立复核。当前尚不具备发布条件，已有测试通过不能替代下列行为的验证。

范围为本公开仓库的 `adapt/dsh-0.2.1` 分支，目标版本 `0.2.8+dsh.0.2.1-rc`。批准目标以[需求](<requirements.md>)为准；[GB-01（Windows Git Bash 开关）](<requirements.md#92-gb-01windows-git-bash-开关暂缓>)继续暂停，不纳入本轮实施与验收。推送、标签和 Release 需另行授权。

本轮实现与文档缺陷（原第一、二节的 WAIT／RESULT／YIELD-DEFAULT／WAIT-DEFAULT／SAFE／UI-ASK／DOC／COMMENT／PUBLIC 各项）已修复并删除，仓库内受控测试与全部检查器通过（双宿主锚全量）；对应行为以独立盲审与隔离实例盲测复核，发现的残留缺陷按本清单重新登记。下列为当前仍开放的事项。

## 一、验证缺口、兼容与资源收尾

### VERIFY-01：修正后取得与需求相称的真实运行证据

本轮等待与交付机制的行为变化已有三层证据：仓库内受控测试（双宿主锚当时全量 662 项全绿，本轮新增测试后为 680 项）、2026-11-01 两轮隔离实例独立盲测、同日五组独立验证（V1-V5，隔离实例与进程内端到端，报告与证据在 `.local/tmp/v1-*`…`v5-*`，工件不入 git）。已取证通过：

- 默认夹紧（yield 1000→20000、wait 1000→20000、wait 0 不夹紧）、无目标挂起资格、非目标消息不打断（排队与插话对照）、批次预算与裁剪恢复（省略量精确对账）、三态状态行与正文不重复、两语文案构造一致性（盲测两轮）；静止目标立即返回（Δ≈9ms 两轮复现）、无目标资格（无工作立即＋有工作挂起且结算时正文同批）、并行直付合计恰一份预算（续段零等待全量领回、逐字节复现）、英文档插话文案（补测轮）。
- 中文档插话文案（profile 行 config 预置 `agentLang=zh` 生效后的行为验证，「结束等待没有终止被等待的后台工作。」精确在场、无旧形态）、多行输入 API 侧交付（原文逐字节全等、不 trim 不折叠）、非零包装退出码（`[退出码: 4294967295]` 原样保留、CommandNotFoundException 完整在场）、开启进度日志时的首次结果与后台交付（开/关档对照，结果与预算不受影响）（V1）。
- 读取失败与恢复（进程内端到端注入真件 `LocalJobRegistry`：失败态模型可见、不置已交付事实、恢复后正文恰一次、两路并发重试在途去重；中文档抽查同口径）、查询失败与查无（挂起查询实测 wall≈预算不被拖住、查无/失败/无权三路可区分、零等待挂起关系查询按固定上限以未证实交回、拍内应答不误报）、内部日志与快照过滤（六种宿主真实内部消息形态先到与挂起中投递均不误唤醒、不被消费，真实插话双锚命中且不消费插话消息）（V2）。
- 目标结算通知的领取时机（父回合中/入口先到/挂起中被唤醒/父空闲四形态毫秒级时间线，最终回答不在等待返回值、另行到达）、恢复会话（重启后作业清单如实消失、旧 job_id 可读拒绝不伪造、完成通知零重复）、多层子代理实时策略（`async_list_subagent_models` 子代理身份可用、children 与 descendants 区别如实、不越层）（V3）。
- 取消交叠（挂起中取消 11ms 交回无预算误报、结算瞬时取消多偏移试验无矛盾口径、作业不被杀、正文恰一次）、消息投递与请求数对照（后台直投 3 请求 0 次等待、挂起窗口 0 请求、不引入额外或纯领取请求）、预设单独挂载与共存（无依赖、无重名、描述逐字节一致）、卸载与重装生命周期 Windows 侧（home 零残留、设置与凭据逐字段恢复、standard 冒烟正常）（V4）。
- GBK 命令输出乱码归属（定性：宿主读取层对 GBK 字节按 UTF-8 有损解码×环境代码页，插件纯转发零编码代码；FFFD 计数与同语义预测逐字符精确对账；处置建议在案——勿覆盖 OutputEncoding、ANSI 工具先 `chcp 65001`、装 pwsh7）、宿主目录选择器挂起（已复现：无服务端超时等操作者、宿主不冻结、断连约 0.7s 自关、杀 worker 如实结算；定性：宿主文档化设计，不记插件账；绕开建议在案——无人值守用 `-browse`、API 勿调 pick）（V5）。

### COMPAT-01：隔离实例依赖解析来源未证明属于 rc.5 同一宿主树

此前通过官方 tgz 安装后，页面、设置接口和两预设创建可用；但从隔离安装包解析九项 DSH peer 时落到仓库祖先依赖的 rc.4，配套包还有其他安装来源。本轮盲测已将插件入口经 `createRequire` 解析的九项 peer 全部对准 rc.5 同树（`@deepseek-ai` 域因沙箱禁 junction 为字节复制，已在盲测报告注明），但同轮在复制式 profile 的隔离实例上另观察到两项装置形态疑因（未定性为本包缺陷，pnpm 形态复测后关闭或另立缺陷）：

- `settings/update` 对本包一律返回 `settings/rejected`："dsh: profile reload requires the root Include entry"（任意字段、`replace|update|mutate` 同，宿主层 `dsh-app-boot` 拒绝；复制式 profile 无根 Include 所致，V1/V4 三轮复现）。既有真实部署实例（根 Include 形态）上的 GUI 写入痕迹不受影响；该形态下的写入与保留待真实部署验证（见 VERIFY-01）。
- profile 层对 bundle `insert:` 宿主行的 `config:` 替换不进生效快照——**已定性**（V1，机制结论按 2026-11-01 盲审宿主逐行复核修正）：0.2.5 形态的平铺根键经 schemastery object resolve 与 cordis `internal/config` waterfall **原样透传到达本包**（不是被 schema 层丢弃），丢失点在本包 `normalizeConfigInput` 的 `settings` 缺省 `{}` 短路——loader 输入恒含 `settings` 键，平铺抬升分支成死分支，`resolveConfig` 只读 `settings.*`，预置值静默回落默认（行正常激活、无警告）；正形 `config: {settings: {…}}` 实证生效（`describe` 复核）。0.2.8 已加装载警告（见 MIGRATE-01）。

- **处理与完成条件**：建立不继承仓库祖先依赖的 pnpm 形态隔离环境，核对运行时实际解析而不只看包清单或静态 `createRequire`；对 settings/update 一项在该环境复测——复制式 profile 限制的定性以 pnpm/根 Include 形态不复现关闭，仍复现则按缺陷另立条目。九项 DSH peer 与测试宿主精确同版同树，配套与直接依赖遵守[需求 7.3](<requirements.md#73-当前兼容基准与统一维护>)，再验证官方安装、装载、预设及设置。四宿主统一包的来源和受影响行为分别验证。
