# 发布前待处理问题清单

本清单只记录当前未完成的缺陷、开发任务、验证缺口和外部事项。修正后删除对应条目，全部解决后清空正文，历史由 Git 保存；清理条目不代替复核。当前存在三项已复现的高优先级功能缺陷，尚不具备发布条件。

范围为本公开仓库的 `adapt/dsh-0.2.1` 分支，目标包版本 `0.2.8+dsh.0.2.1-rc`。批准目标以[需求](<requirements.md>)为准；[GB-01](<requirements.md#92-gb-01windows-git-bash-开关暂缓>)继续暂缓。新增的[预设功能绑定](<requirements.md#94-preset-bind-01预设功能绑定>)是待开发任务，不作为既有实现的漏项。推送、标签和 Release 需另行授权。

以下缺陷核查基于提交 `da5428b1119d57f655d0182426bc4cb72694f7a5`。实际交付模块的受控反例已独立复现；既有同进程全量测试 681 项通过未覆盖这些反例，不能据此关闭缺陷。临时实例验证、静态解析和受控探针分别只证明各自范围。

## 一、必须修正的功能缺陷

### REL-LIFECYCLE-01：卸载单个工具行清空其他主体的交付记录（高优先级）

- **位置与影响**：[工具行卸载处理](<../lib/index.js#L294-L300>)对每一行调用共享交付账本的 `disposeAll()`，包括单独挂载的路由查询行。其他预设和主体的保活监听、未交付缓冲及交付事实会被一起清除，影响后续通知和内容恢复。
- **复现**：挂载单独的 `async_list_subagent_models` 行，向实际共享账本登记另一主体的作业；只卸载查询行后，作业记录数由 1 变为 0。
- **依据**：需求 3.2、7.2、9.3.5 的隔离和生命周期要求。
- **完成条件**：单行卸载仅释放该行应负责的资源，不破坏其他活动组合和主体的交付。查询行卸载不清除交付行的作业；补充跨预设活动作业、未交付及裁剪内容的回归验证，确认最终整体卸载仍正确释放资源。

### REL-SEND-01：部分投递失败导致已送达正文回滚重发（高优先级）

- **位置与影响**：[逐条注入与失败回滚](<../lib/delivery.js#L978-L987>)在批次中途失败时回滚整个待发列表，包含宿主已经接受的条目，后续可能再次交付同一正文。
- **复现**：对运行中主体投递两项已结算结果，使第一项 `inject` 成功、第二项抛错；随后调用实际账本的 `collectBatch`，两项正文均重新出现，第一项重复交付。
- **依据**：需求 9.3.2 的首次交付、重复抑制及失败恢复要求。
- **完成条件**：保留已成功投递项的交付事实，仅恢复未被接受的内容。覆盖中途失败、失败项恢复、后续重试及并发投递，不重复已送达正文，也不丢失未送达内容。

### REL-TERMINAL-01：后台交付遗漏退出码、终止信号和诊断（高优先级）

- **位置与影响**：[完成消息渲染](<../lib/delivery.js#L1028-L1037>)和[等待批次状态行](<../lib/wait.js#L425-L433>)只使用状态及字符数，没有完整呈现上游保存的终态细节。[命令结算](<../lib/jobs.js#L330-L374>)已生成终止信号、非零退出码、沙箱及静默失败诊断，但后台载体可能遗漏这些信息。
- **复现**：对实际 `DeliveryLedger.readSettled` 传入带 `killed`、`SIGTERM`、退出码 143 和唯一诊断文本的终态，中文和英文完成消息均只有正文及 `killed`，没有信号、退出码或诊断。该证据为交付模块受控复现；真实模型端到端尚待补验。
- **依据**：需求 2.2.2、2.2.3、9.3.4 要求保留真实结局、非零退出及信号标记，必要诊断始终可见，首次与后台路径一致。
- **完成条件**：完成消息和等待返回均交付已知且适用的退出码、信号、失败原因及安全诊断，不重复正文、不因内容预算丢失必要信息。补中英文受控反例及真实后台非零退出、终止路径的验证。

## 二、必须修正的现行文档

### DOC-PUB-01：`no-work` 定义遗漏挂起后无工作出口

[中文用户参考](<user-reference.md#L132>)及[英文用户参考](<user-reference.en.md#L132>)将 `no-work` 解释为本次没有挂起；实际实现也会在挂起后确认全部工作结束时返回该状态。另须区分“确认没有可等待工作”和“无法确认等待条件”，不能把两者混同。

- **完成条件**：两语说明分别解释入口无工作和挂起后工作结束，结合 `note`、`waited_ms` 理解实际过程；`unconfirmed` 继续表示条件未证实。修改说明，不改变既有状态语义。

### DOC-PUB-02：实施和验证状态未按证据范围更新

[设计的当前状态](<design.md#L1353-L1403>)仍将部分已登记取证的行为笼统写为待验证；[目标消息处理](<design.md#L1168>)还将已存在于实现的发送方状态复查写成待补实施。两语首页、用户参考及设计中的 rc.5 兼容结论，也须与 COMPAT-01 的依赖来源缺口区分，不能由局部安装和接口通过推导全部运行时同源通过。

- **完成条件**：逐项核实可取得的证据，更新设计第 9 章及相关正文，将已实现、受控验证、实例验证和仍未验证分别说明；相同对象及证据等级下保持全篇一致。公开说明只保留足以支持的结论。不能核实的既有证据保持未确认，不扩写为通过，也不直接抹掉仍有效的局部证据。关联新需求的设计由 PRESET-BIND-01 开发任务同步更新。
- **待确认事项**：兼容验收负责人需明确现有 rc.5 安装与行为证据中可复用的部分，以及依赖来源不明而需要重验的部分。该确认不授权修改宿主源码。

### DOC-PUB-03：留存位置和待答提示包含未经证实的断言

- [中英文结果留存文案](<../lib/text.js>)中，`render.spillDisk`、`delivery.lossyAtPaths`、`delivery.spill` 将宿主报告的路径写成完整输出确定存在；本包没有据此核实文件此刻完整可读。
- [客户端待答文案](<../client.js#L936-L959>)中的 `ask.needAnswer` 对多选题仍说“选择一项”；`ask.undelivered` 将记录缺席归因为超过保留期或批次结束，回执未必证明具体原因；`help.askTimeoutMs` 只按本轮结束解释迟到答案投递，未包含空闲但已有未领取通知时仍走注入的条件。英文对应项应同步。
- **完成条件**：留存提示说明宿主报告的位置和可确认的找回方式，不承诺当前文件完整；作答提示适用单选与多选；记录缺席只报告已知事实并保留直接回复会话的出路；迟到答案说明与实际忙碌、空闲及未领取通知处理一致。保持既有行为及必要调用规则。

## 四、验证缺口与外部事项

### VERIFY-01：完成修正后的实际行为与界面验证

正常根 Include 形态的隔离 rc.5 实例已通过官方 tgz 安装，设置读回、真实用户覆盖写入及恢复、两异步预设和 standard 创建回读可用；“设置入口不可写”不再是当前缺口。仍需完成：

- 本清单功能修正及新需求的实际运行验证；新反例须能检出对应退化，已有通过记录不覆盖修改后的实现。
- 用户设置的升级保留、重启持久化、恢复默认及实际 GUI 保存反馈；新多选块的深浅主题、窄屏、键盘和可辨认状态。
- 待答多行输入的视觉与可访问性，以及需求 9.3.6 的真实模型等待必要性和协作续接。已记录但本轮未独立核实的旧行为证据，按 DOC-PUB-02 辨认有效范围，不整体重复宣称通过或未验。
- Linux 命令、单次提权和卸载生命周期；真实读屏、触屏软键盘及审批界面实点等尚未取得的证据。缺少环境时记录具体项目，不能以 Windows 或受控测试代替。
- 结算通知与注册表状态滞后的自然时序。本部署尚未取得该形态的实例级证据；故障注入只证明受控范围。

**宿主边界**：当前 rc.5 不允许后台子代理直接请求人类交互，因此目标子代理提问通知在该环境不能自然产生；保留需求适用条件和未验证事实，不要求本插件绕过宿主限制，不将相邻消息路径通过冒充本项通过。

### COMPAT-01：隔离安装的依赖来源与运行时同源尚未证明

新建正常根 Include 形态的隔离实例后，从已安装插件入口进行静态解析，仍有 DSH peer 落入祖先目录的 rc.4，配套 peer 另有其他宿主来源。本轮已验证官方安装、RPC 设置接口和预设创建可用，尚未验证 GUI；这些结果不能证明运行时实际取得了同版本同来源的依赖。

- **完成条件**：建立不继承工作区祖先依赖的隔离安装环境，核对插件运行时实际取得的九项 DSH peer、配套及直接依赖，满足[需求 7.3](<requirements.md#73-当前兼容基准与统一维护>)。在该环境复核官方装载、预设、设置和受影响行为；静态包清单或 `createRequire` 单项结果不代替运行期证据。四个受支持宿主分别保留自己的证据范围。

### RC5-01：四宿主远端 CI 结果与发布授权

[CI 配置](<../.github/workflows/ci.yml>)包含 rc.2、rc.3、rc.4、rc.5；当前修订尚无对应远端 Actions 实跑结论。

- **完成条件**：取得推送授权后核对四档实际结果及集合外拒载；不把本地套件或配置存在写成远端已通过。标签、Release 和公开发布继续单独取得授权。

### MIGRATE-01：既有部署的旧平铺配置需要迁移确认

仓内已有平铺配置装载警告及迁移说明；既有部署是否仍使用旧平铺形态，本轮没有读取私有部署配置，也没有代为修改。旧配置可能正常装载却回落默认值。

- **完成条件**：部署负责人升级前按[更新日志的迁移说明](<../CHANGELOG.md>)检查旧 `config`，必要时改为 `config.settings`，并确认实际生效值。该事项不授权开发任务修改在用实例；迁移说明和警告的仓内修正继续由本仓维护。

### CLEANUP-01：旧验证资源归属尚未确认

旧隔离实例、浏览器和测试 home 的归属记录本轮未核实。当前新建的验收实例已经停止，不能据此宣称旧资源全部清理。

- **完成条件**：维护者向资源创建者取得必要的归属说明，核对资源及使用方，只处理可确认属于验证且不再使用的资源；在用资源明确负责方和清理条件。归属不明时保留，不按端口批量停止，不在公开清单保存机器标识或凭据。
