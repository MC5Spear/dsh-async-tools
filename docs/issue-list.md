范围为本公开仓库的 `adapt/dsh-0.2.1` 分支，目标版本 `0.2.8+dsh.0.2.1-rc`。批准目标以[需求](<requirements.md>)为准；[GB-01（Windows Git Bash 开关）](<requirements.md#92-gb-01windows-git-bash-开关暂缓>)继续暂停，不纳入本轮实施与验收。推送、标签和 Release 需另行授权。

### WAIT-OBSERVE-01：无目标等待对静默转空闲的子代理无观察通道（待决策）

无目标挂起等待的资格由运行中子代理提供，但状态观察通道（watchers 与备用轮询）只按显式子代理目标建立：运行中子代理在无任何消息与结算通知的情况下静默转空闲时，等待将耗尽全部预算。[需求 9.3.6 第 12 项](<requirements.md#936-可判断的验收结果>)要求可等待工作全部结束及时交回；[设计 3.2.5](<design.md>) 的确认通道同样只列就绪事件与消息——这是需求与设计的共同缺口，不是实现偏离。

- **处理与完成条件**：登记决策后实施——或为无目标挂起建立对账本所依据清单的受预算约束周期复查（不扩大权限、不重复轮询既有目标），或修订需求／设计口径明示该边界。实施后按“运行中子代理静默结束 → 等待及时交回（不早于资格消失、不耗尽预算）”取证；维持现状则在本节登记用户可见影响。

### WAIT-SETTLE-GATE-01：结算通知弱证据路径缺 settled 门（既有缺陷）

[结算通知处理](<../lib/wait.js>)对通知事件不区分证据来源（via）：宿主结算通知胜出后未复查「不再观察到运行」即返回 `settled`，且注册表现读仍为 `running` 时照样返回并把跨调用基准写成空闲——与[实现自述](<../lib/interrupts.js>)「胜出后必须复查到不再观察到运行才返回 settled」不符。该代码与上一轮（`e933b30`）逐字相同，非本轮引入，未修。

- **处理与完成条件**：结算通知胜出后按自述补复查门（复查到运行仍返回则不报 settled、不写错基准），或修正自述与设计口径一致；以「结算通知到达但注册表仍观察到运行」的受控场景取证。修前列为已知缺陷，不据此宣称结算路径已验证。

### COMPAT-01：隔离实例依赖解析来源未证明属于 rc.5 同一宿主树

此前通过官方 tgz 安装后，页面、设置接口和两预设创建可用；但从隔离安装包解析九项 DSH peer 时落到仓库祖先依赖的 rc.4，配套包还有其他安装来源。本轮盲测已将插件入口经 `createRequire` 解析的九项 peer 全部对准 rc.5 同树（`@deepseek-ai` 域因沙箱禁 junction 为字节复制，已在盲测报告注明），但同轮在复制式 profile 的隔离实例上另观察到两项装置形态疑因（未定性为本包缺陷，pnpm 形态复测后关闭或另立缺陷）：

- `settings/update` 对本包一律返回 `settings/rejected`："dsh: profile reload requires the root Include entry"（任意字段、`replace|update|mutate` 同，宿主层 `dsh-app-boot` 拒绝）；既有真实部署实例上的 GUI 写入痕迹不受影响。第二轮补测再次复现，并连带阻断 `agentLang` 运行时切换（中文档文案的行为验证因此受阻）。
- profile 层对 bundle `insert:` 宿主行的 `config:` 替换在重启后不进生效快照（`describe` 仍为 schema 默认、user 层为空），与该行注释宣称的"改出厂值正式入口"不符。

- **处理与完成条件**：建立不继承仓库祖先依赖的 pnpm 形态隔离环境，核对运行时实际解析而不只看包清单或静态 `createRequire`；对上述两项装置疑因在同一环境复测——pnpm 形态下不复现即定性为复制式 profile 的装置限制并在此关闭，仍复现则按缺陷另立条目处理。九项 DSH peer 与测试宿主精确同版同树，配套与直接依赖遵守[需求 7.3](<requirements.md#73-当前兼容基准与统一维护>)，再验证官方安装、装载、预设及设置。四宿主统一包的来源和受影响行为分别验证。
