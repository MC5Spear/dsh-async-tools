# 发布前待处理问题清单

范围：公开仓库 `adapt/dsh-0.2.1`，受验提交 `95a8f15a0c9dd93c983ac8a7bab896d7a1ef439f`，插件 `0.2.8+dsh.0.2.1-rc`，支持 dsh `0.2.1-rc.2`、`rc.3`、`rc.4`、`rc.5`。缺陷证据针对该候选；第三节为本轮已批准、尚待设计或实现的任务，不将新要求倒算为旧候选原本已承诺的行为。批准目标见[需求](<requirements.md>)。

**当前候选不具备推送条件。** 第一节为推送前须修复的问题。出现概率、严重程度分别评为高／中／低；任一维度高或两者均中时阻断推送。第二节登记其余未解决问题，不阻断推送，留待下轮；第三节已批准任务须纳入本轮开发交验，不按缺陷评级决定是否实施。验证缺口、暂缓目标与外部交接分别列明。修复历史由 Git 保存，不以删除条目或旧完成声明代替核验。

## 一、推送前须修复

### RA-FOREIGN-DISCOVERY：陈旧交付记录造成无工作空等和外来结果漏交付

- **出现概率：中；严重程度：中。** [目标构造](<../lib/wait-job-target.js#L59-L74>)在确认作业存在前登记编号，[无目标工作检查](<../lib/wait.js#L707-L737>)把记录中的 `terminal === null` 直接视为仍在运行，[结果发现](<../lib/wait.js#L408-L424>)又跳过所有已有记录。宿主公开状态与本包记录不一致时，后续判断无法纠正。
- **已复现条件：** 不存在的作业目标被正确拒绝后仍留下未终态记录，后续实际没有作业或子代理的无目标等待挂满预算；外来作业先被定向零等待观察、随后静默完成时，无目标等待同样挂满预算且不交付正文。rc.2、rc.5 的真实作业注册表均复现，干净状态的无工作对照立即返回。显式指定原编号仍能恢复结果，不是正文永久丢失。
- **完成条件：** 挂起资格以当前宿主公开状态为准；无效或不可见编号不留下假运行记录；已登记外来作业的终态可在无目标入口及周期检查中发现并交付，读取失败保留恢复方式。覆盖上述两种触发及查询失败、真实运行工作、显式恢复和重复抑制对照。原来仅发现未登记终态作业的修复不足以关闭本项。

### DOC-PUBLIC-FINGERPRINT：公开探针包含本机端口，标准检查失败

- **出现概率：高；严重程度：中。** [无障碍探针](<../verify/_visual/probe-a11y-input.mjs#L31-L33>)、[待答视觉探针](<../verify/_visual/probe-ask-visual.mjs#L21-L23>)、[持久化探针](<../verify/_visual/probe-gui-persist.mjs#L32-L34>)、[设置视觉探针](<../verify/_visual/probe-settings-visual.mjs#L23-L25>)、[徽标探针](<../verify/_visual/probe-vis-ratify.mjs#L24-L26>)把特定开发机端口写入公开注释。本轮 `check:public-surface` 对精确公开候选报 10 处命中，退出 1；[CI 检查步骤](<../.github/workflows/ci.yml#L142-L157>)执行同一入口。
- **完成条件：** 保留只操作自建隔离实例和按归属清理的必要说明，去掉本机坐标；相应检查通过，不以整文件豁免掩盖机器事实。

### DOC-MODEL-CHECK-SYNC：新增提示段与检查器分类不同步

- **出现概率：高；严重程度：中。** [提示常量与注册](<../lib/index.js#L92-L166>)新增了模型可见的作业收集段和内部 effect 标签，[检查器例外](<../tools/check-model-text.mjs#L299-L305>)未同步。当前 `check:model-text` 报两处并退出 1，[CI](<../.github/workflows/ci.yml#L142-L157>)因此不能通过。effect 标签是诊断文本，属于误报；宿主原文保留英文也不能直接判为本包漏译。
- **完成条件：** 宿主未改原文可保留宿主语言，本包改写指令按 AGENT-LANG-01 随 `agentLang` 切换；内部标签按诊断职责作范围明确、理由充分的分类。同步检查与反例，使入口通过且仍能检出真正散落的模型文案，不把模型可见段假称为内部文本。

### DOC-CONTROL-FACT：官方控件能否复用的事实状态相反

- **出现概率：中；严重程度：中。** [客户端注释](<../client.js#L15-L21>)确定宣称官方字段帮助图标固定、标签无扩展入口，因此必须自绘；[设计](<design.md#L968-L1009>)却明确这些事实尚未核实，不能据此排除官方控件。当前采用自绘字段不能反向证明官方方案已被核实不适用。
- **完成条件：** 按目标宿主的公开接口或实际页面确认依据，直接同步注释和设计的确定程度与选型理由；不靠删除疑问或降低[官方控件要求](<requirements.md#54-设置页面>)制造一致。

### DOC-PROBE-COVERAGE：现行视觉探针及入口说明与实际覆盖不符

- **出现概率：中；严重程度：中。** [卡片探针头注](<../verify/_visual/probe-card-visual.mjs#L6-L14>)仍称值字段使用官方控件、与官方设置页逐项对照及全量 17 字段，实际[比较步骤](<../verify/_visual/probe-card-visual.mjs#L219-L234>)只读主题圆角令牌，当前字段为 20 项。其[期望集合](<../verify/_visual/probe-card-visual.mjs#L34-L43>)及[r24 探针](<../verify/_visual/probe-r24-bundle-config.mjs#L148-L173>)仍只取四组，却采集页面全部帮助按钮。
- [验证索引](<../verify/README.md#L131>)把徽标探针描述为还会测设置正文对比度、选项和操作钮悬停及双预设提示；实际[现行范围](<../verify/_visual/probe-vis-ratify.mjs#L674-L710>)只复测徽标悬停，并明确省略设置对比度和提示核对。旧证据可以在条件不变时复用，但不能写成当前脚本仍执行这些检查。
- **完成条件：** 明确各脚本的现行用途，统一代码期望、选择器和入口说明；按真实字段全集或明确子集检查，区分官方控件比较、主题令牌取值和历史证据复用。实际验证当前入口，不只改数字或删头注掩盖错误判据。

### DOC-CURRENT-STATE：现行完成声明、验证状态与正文未同步

- **出现概率：中；严重程度：中。** [设计当前状态](<design.md#9-当前实施与验证状态>)及[验证入口](<../verify/README.md#L126-L152>)仍累积修复轮次、复跑经过、旧结论和未分发过程材料。[全套检查通过声明](<design.md#92-受控验证rc5rc2-双锚>)与当前确定失败的两项标准检查不符；部分页面、持久化和运行验证又同时被写为已完成与待验证。原 DOC-CURRENT-01／DOC-STATE-01 不能按清单上的完成索引整体关闭。
- **完成条件：** 以当前候选、宿主、安装形态和实际证据范围直接维护现行结论，保留必要来源与未验边界，删除被取代的状态和无用制作经过。同步设计、验证说明及相关使用资料；问题清单只保留当前未解事项。只整理本清单不代表其他正文已修复，真实发布历史按[更新日志](<../CHANGELOG.md>)职责保留。

## 三、本轮已批准的开发任务

以下要求的产品取舍已确定；待开发的是机制、明确参数和实现，不再把相同取舍交回产品决定。具体技术方案由开发设计说明，现行缺陷评级不因新增任务而自动改变。

### RESULT-RECOVERY-01：未确认送达的结果保留有限恢复副本

- **目标：** 按[作业内容首次交付](<requirements.md#932-作业内容首次交付>)，正常自动交付且不重复发送；结果构造、内部读取或等待注销均不等于模型已收到。构造后被宿主改写取消或送达无法确认时，在明确期限内保留可经 `async_wait` 恢复的副本，不重跑原任务。恢复可能重复时，在正文前说明并标明作业。
- **当前差距：** [已交付记录](<../lib/delivery.js#L370-L405>)及当前构造点清理可能阻断再次取得正文；该窗口尚无自然实例复现，不能据此接受丢失，也不直接按高严重故障评级。正常状态检查不应展开已确认交付的历史正文。
- **完成条件：** 明确送达证据、状态检查与恢复请求的区分、副本保留期限、存储上限、到期及生命周期清理；设计中给出可测数值。覆盖构造后取消、注入失败、未确认领取、并发去重、恢复可能重复标记、到期与清理。期限内取消等待不提前清副本，清理后不伪称已送达；原权限和同批预算保持。

### DOC-ZERO-01：零等待只作一次有短时总上限的检查

- **目标：** 按[等待条件](<requirements.md#931-等待条件目标检查与唤醒>)，不等待任务进展或未来消息、不重试、不轮询；必要权限、可见性与关系查询各只发起一次。多目标和全部返回处理共用短时总上限，慢查询按未确认交回，取消及时响应，不省略安全检查。
- **当前差距：** [关系查询](<../lib/wait.js#L651-L667>)仍有分查询两秒窗口，现行两语参考和实现的时限含义未统一。原低概率／中严重评级保留作缺陷背景；本轮澄清已批准，不再待产品选值。
- **完成条件：** 按支持宿主接口和实测确定总上限、固定调度容差并写入设计，不直接将现有两秒或正等待下限当批准值。验证多目标不倍增、慢／挂起／失败查询、取消、已到有效消息及迟到查询结果清理，保持权限与状态真实性；同步说明和相关测试。

### ECHO-WORKFLOW-01：回显开关同时覆盖普通命令和工作流脚本

- **目标：** 按[Agent 展示配置](<requirements.md#934-agent-展示配置>)默认关闭；开启后在选定位置向 Agent 提供普通命令与 `async_workflow` 脚本原文，同一领取窗口不在多个载体重复附上。原文受同批预算和裁剪约束，结果正文、必要结局和界面原始记录保持不变。
- **当前差距与完成条件：** 当前编排无论开关取值都不回显脚本；普通命令开启后将原文放入注册名称，尚未明确该名称经 `job_list` 进入模型时如何遵守统一预算与去重。两类路径均须补设计及实现，明确呈现位置，验证开／关、后续生效、长文本裁剪量、任务列表与其他载体同窗合计及混合批次，更新两语设置名称及说明。界面原始记录保持；编排任务名称可继续为 `meta.name`，不要求每条进度或任务列表都贴整段脚本。

### AGENT-LANG-01：自有提示改写随 Agent 语言生效

- **目标：** 按[两个独立语言开关](<requirements.md#53-两个独立语言开关>)，宿主原封不动的提示可保留宿主语言，本包新增或改写的指令随 `agentLang`，包括 `tool:jobs` 的收集句。只引导取得未交付、延后或送达未确认的内容，不要求再次领取已收到正文。
- **完成条件：** 分清原文、改写和内部标签，补齐两语来源与已有会话后续组稿刷新；验证中英文实际提示、原文保真、其他预设不受影响及已到正文不被要求重新领取。同步 DOC-MODEL-CHECK-SYNC 的分类和退化反例，不以整体豁免替代翻译或改变上游原文。

### ASK-ANNOUNCE-01：新待答问题温和提醒，不抢焦点

- **目标：** 按[全局待答面板](<requirements.md#42-全局待答面板>)，新题进入时向辅助技术提醒新增数量；同批可合并，不移动当前焦点、不打断朗读、不自动读整道题。侧栏收起和浮窗均适用，倒计时、重复刷新和重渲染不重复播报，文案随 `uiLang`。
- **完成条件：** 设计提醒方式与新题去重规则，覆盖新增多题、重复状态、重连、两种显示方式和语言；真实读屏验证提醒及焦点保持，不仅检查某个属性在场。当前只有可访问名称和结构证据，不能据此声明新提醒已实现。

### ASK-IME-SUBMIT-01：组合输入期间禁止提交，不延后补发

- **目标：** 按[有效提交](<requirements.md#424-有效提交与答案一致性>)，该题自定义输入仍在组词时临时禁用提交并说明原因；鼠标、触屏和键盘入口均不接受动作，保留草稿与选择。组合结束后重新校验，必须再次明确提交；失焦导致组合结束也不能补发先前动作。“不答／忽略”及服务端答案校验保持原规则。
- **完成条件：** 设计并验证组合状态及事件顺序，包含组合中点击、失焦确认、快捷键、有效／无效自定义及多选；真实输入法确认键不误提交仍须独立验证。两种面板行为一致，浏览器合成事件不代替真实输入法端到端结论。
